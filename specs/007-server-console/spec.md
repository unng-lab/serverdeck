# Feature Specification: Консоль сервера

**Feature Branch**: текущая рабочая ветка; отдельная ветка не создаётся
**Created**: 2026-11-06
**Status**: Implemented — unit checks passed; independent review clean; converged (2026-11-07)
**Input**: Нужна отдельная спека консоли сервера рядом с журналами, заданиями и мониторингом. Стандартный терминал с выбором профилей, как в VS Code; default выбирается в настройках приложения.

**Scope update 2026-11-06**: MCP также должен работать через эту консоль, видеть её историю и выполнять корректирующие действия в общей с пользователем сессии.

## Clarifications

### Session 2026-11-06

- Q: Встроенная вкладка сервера или отдельное окно терминала? → A: Встроенная вкладка; профиль оболочки выбирается в настройках приложения.
- Q: Должна ли консоль быть доступна MCP? → A: Да: MCP пишет через консоль, видит историю и может корректировать дальнейшие действия. Запрет MCP-доступа из первоначальной редакции 007 отменён.

## User Scenarios & Testing

### User Story 1 — Интерактивная консоль сервера (Priority: P1)

Пользователь выбирает сервер и вкладку «Консоль», явно открывает сессию, вводит команды и видит ответы в контексте этого сервера.

**Why this priority**: Переход от наблюдения журналов и метрик к ручной диагностике.
**Independent Test**: Fake connection/terminal проверяют запуск, ввод, вывод и принадлежность серверу.

**Acceptance Scenarios**:

1. **AC-701 Given** подключённый доверенный сервер A, **When** открыть вкладку, **Then** показаны сервер, SSH-пользователь, профиль терминала и «Открыть консоль»; оболочка запускается только по этому действию, ровно одна на принятое действие.
2. **AC-702 Given** активная сессия A, **When** вводить команды, использовать Enter, стрелки, Tab, Ctrl+C, **Then** ввод получает только A, вывод последователен, Ctrl+C передаётся удалённому терминалу; клиент не исполняет команды локально.
3. **AC-703 Given** сервер отключён или требует доверия, **When** открыть вкладку, **Then** запуск/ввод заблокированы с причиной, доступны штатные действия 003; просмотр не подключает сервер. После явного подключения открытие консоли остаётся отдельным действием.
4. **AC-704 Given** запрос пароля, полноэкранная программа и фрагментированный UTF-8/ANSI поток, **When** поступают данные, **Then** работают удалённое управление echo, курсор, стирание и альтернативный экран; фрагментация не меняет текст, сервер не может вызвать локальные действия.

### User Story 2 — Выбор профиля в настройках приложения (Priority: P1)

В общих настройках есть «Терминал»: профиль по умолчанию и другие профили удалённых оболочек. Новые консоли используют сохранённый выбор.

**Why this priority**: Явный запрос пользователя на настройку терминала.
**Independent Test**: Fake settings store/launcher проверяют defaults, validation, сохранение и ошибки.

**Acceptance Scenarios**:

1. **AC-705 Given** настройки отсутствуют, **When** открыть «Терминал», **Then** default — встроенная «Оболочка входа сервера», без предположения о наличии bash.
2. **AC-706 Given** создан профиль «Bash» с удалённым путём `/bin/bash`, **When** сохранить default и перезапустить приложение, **Then** выбор сохранён; новая консоль использует удалённую оболочку, не локальный процесс.
3. **AC-707 Given** работающая консоль, **When** изменить default/профиль или удалить его, **Then** сессия не перезапускается, её снимок профиля терминала и буфер сохраняются. Новую можно открыть с другим профилем разово, без изменения default.
4. **AC-708 Given** оболочки нет на сервере или запуск запрещён, **When** открыть консоль, **Then** видна причина и доступен выбор другого профиля; нет установки, скрытого fallback и автоповтора.
5. **AC-709 Given** невалидное поле/ошибка записи, **When** сохранить, **Then** старые настройки остаются, draft доступен для исправления. Удаление default атомарно выбирает встроенный профиль.

### User Story 3 — Сессии и потеря связи (Priority: P2)

Пользователь переключается между консолями, закрывает их и различает завершение оболочки и обрыв соединения.

**Why this priority**: Ввод может изменять сервер; неверный контекст и повторы недопустимы.
**Independent Test**: Fake clock/channel/owner проверяют гонки, ограничения и закрытие.

**Acceptance Scenarios**:

1. **AC-710 Given** сессии A и B, **When** переключить сервер/вкладку, открыть настройки или скрыть окно в трей, **Then** каналы продолжают работать в пределах лимитов, клавиатурный UI-ввод доступен только выбранной видимой консоли. Авторизованный MCP работает по явному sessionId независимо от видимости. Возврат показывает собственный буфер.
2. **AC-711 Given** активная консоль, **When** закрыть её с подтверждением, **Then** закрывается только её канал, буфер удаляется; SSH, журналы и мониторинг продолжают работать. Завершённая консоль закрывается без подтверждения.
3. **AC-712 Given** обрыв/завершение оболочки, **When** событие получено, **Then** консоль read-only с причиной и exit code при наличии; новый запуск только явный, ввод не воспроизводится.
4. **AC-713 Given** смена endpoint/auth, отзыв доверия, отключение или удаление сервера во время открытия/ввода, **When** действие вступило в силу, **Then** старые ввод/ответы блокируются, поздний callback не оживляет сессию. Rename не закрывает канал.
5. **AC-714 Given** открытые консоли, **When** полный выход и restart приложения, **Then** каналы закрыты, сессии/вывод не восстановлены, команды не повторены; настройки терминала сохранены.

### User Story 4 — MCP работает в той же консоли (Priority: P1)

Авторизованный MCP-клиент находит консоли сервера, читает доступную историю и текущий экран, открывает новую либо использует уже открытую сессию, отправляет команды и управляющие клавиши. Пользователь видит тот же терминал и результаты. Для исправления MCP может редактировать ещё не отправленную строку средствами оболочки, прервать текущую работу и отправить новую команду; прошлое исполнение и историю переписывать нельзя.

**Why this priority**: Явное уточнение пользователя: MCP должен действовать через наблюдаемую консоль с общим контекстом, а не отдельный невидимый exec.
**Independent Test**: Fake MCP actor/terminal/clock проверяют историю, один общий канал, передачу управления, повторы и отзыв доступа.

**Acceptance Scenarios**:

1. **AC-715 Given** действующее разрешение MCP и открытая UI-консоль, **When** запросить консоли сервера и прочитать выбранную по sessionId, **Then** возвращаются её состояние, профиль оболочки, текущий экран и доступный scrollback, включая вывод до присоединения MCP; SSH-канал не дублируется.
2. **AC-716 Given** MCP получил право ввода в сессию, **When** отправить текст и Enter, **Then** команда попадает в тот же терминальный канал, пользователь видит ввод при echo сервера и весь полученный вывод. MCP читает результат отдельно; подтверждение отправки не означает завершение команды.
3. **AC-717 Given** незавершённая строка либо выполняемая команда, **When** MCP отправляет Backspace/Ctrl+U либо Ctrl+C и исправленный ввод, **Then** действия получает удалённая оболочка с её обычной семантикой; прошлый результат не меняется, успех прерывания/исправления не выдумывается. Приложение не предполагает, что оболочка сейчас на prompt.
4. **AC-718 Given** управление у MCP A, **When** MCP B пытается писать либо пользователь выбирает «Взять управление», **Then** B получает busy, пользователь немедленно забирает управление, поздний ввод A отклоняется. Чтение истории остаётся доступным авторизованным клиентам.
5. **AC-719 Given** ответ на отправку потерян, **When** клиент повторяет ту же операцию, **Then** нет повторного ввода. Неизвестный/устаревший исход явно отличается от успеха; повторное чтение и новый ввод не запускаются автоматически.
6. **AC-720 Given** scrollback усечён/очищен либо сессия явно закрыта, **When** MCP читает по старой позиции, **Then** получает признак разрыва при вытеснении/очистке или отсутствия сессии после её закрытия, а не выдачу полного контекста. Простое завершение оболочки сохраняет чтение доступной истории и финального вывода по действительным позициям до закрытия сессии/выхода приложения. После restart старая история недоступна.
7. **AC-721 Given** отзыв/замена/истечение разрешения либо отключение MCP, **When** поступает чтение/ввод/повтор или приходит поздний результат, **Then** нет новых данных/отправок этому клиенту, его право ввода освобождено; общий SSH и терминал пользователя не закрываются.
8. **AC-722 Given** подключённый сервер и авторизованный MCP, **When** явно открыть консоль с default либо выбранным профилем и затем закрыть с подтверждением, **Then** сессия появляется/исчезает и в UI, действуют те же caps и trust fences; никакие настройки профилей оболочек или серверов при этом не меняются.

### Edge Cases

- Нет выбранного сервера; отказ псевдотерминала; timeout; повторное нажатие запуска; поздний callback закрытой сессии.
- Сохранение default одновременно с запуском; удаление используемого профиля; повреждённые настройки и отказ хранилища.
- Неизвестен результат последнего ввода после обрыва; закрытие канала не гарантирует остановку удалённых фоновых процессов.
- Многострочная вставка, пароль в выводе, escape-последовательности clipboard/URL, неполный UTF-8, flood вывода и переполнение ввода.
- Предел сессий, вывод в скрытой консоли, отказ одного канала при работающем общем SSH.
- Два MCP-клиента и пользователь пишут одновременно; пользователь оставил частичный ввод; утрата права ввода между подтверждением и отправкой; обрыв MCP при живом терминале; cursor старше scrollback.

## Requirements

### Functional Requirements

- **FR-701**: MUST добавить вкладку «Консоль» выбранного сервера; сессия привязана к profileId, connectionRevision, поколению SSH и sessionId. Показаны сервер, SSH-пользователь, профиль терминала и состояние. ПО и задания этим пакетом не реализуются.
- **FR-702**: MUST открывать терминальный канал только по явному UI-действию или авторизованному MCP-запросу через существующий аутентифицированный доверенный SSH-сеанс 003. Нет второго логина, изменения системного known_hosts, передачи credentials внешним процессам или подключения от просмотра/чтения консоли. Политики подключения/доверия — 003; отключённый сервер MCP подключает отдельной штатной операцией 003.
- **FR-703**: MUST поддержать интерактивный удалённый псевдотерминал: UTF-8, потоковый ввод/вывод, ANSI/VT курсор/стирание/альтернативный экран, Enter, Backspace, стрелки, Home/End, Tab, Ctrl+C/Ctrl+D и передачу изменения строк/столбцов серверу. Фрагментация сетевых данных не меняет смысл. Это полноценная консоль, не поле разового запуска команды. Точный профиль совместимости фиксируется в контракте до реализации.
- **FR-704**: Общие настройки приложения MUST содержать «Терминал», список профилей и default для всех серверов текущего локального хранилища. Per-server override нет. При каждом открытии можно выбрать профиль разово без изменения default. Встроенная неудаляемая «Оболочка входа сервера» — начальный default.
- **FR-705**: Пользовательский профиль MUST содержать стабильный ID, имя 1–80 символов после trim и абсолютный Linux-путь к удалённой оболочке до 1024 UTF-8 bytes без NUL/CR/LF; максимум 16 пользовательских профилей. Аргументы, environment, рабочий каталог, стартовые команды и секреты не настраиваются. Путь исполняется как один путь без интерпретации его символов как команды. Оболочка запускается интерактивно; встроенный профиль использует оболочку входа учётной записи. Наличие/права определяются результатом явного запуска на сервере, без локального поиска или фонового SSH.
- **FR-706**: Save MUST быть явным и атомарным; default ссылается только на существующий профиль. Ошибка оставляет старые настройки и draft. Удаление default атомарно выбирает встроенный. Изменения касаются только будущих сессий; запуск фиксирует один снимок профиля при принятии действия, гонка не смешивает версии. Отсутствующие настройки в существующих данных означают встроенный default; повреждённые данные — ошибка, не сброс. Модель хранения проектируется по конституции без несанкционированного удаления базы.
- **FR-707**: MUST ограничить консоли 4 на сервер и 16 глобально, включая открывающиеся и завершённые до явного закрытия. Reservation атомарна; повтор pending-действия не создаёт дубль, отдельная «Новая консоль» создаёт независимую сессию. Лимит блокирует только новый запуск с причиной.
- **FR-708**: Открытие канала MUST закончиться успехом/ошибкой/отменой за 15 секунд сетевого ожидания, без автоповтора. Различимы состояния «Ещё не открыта», «Открывается», «Активна», «Завершена», «Связь потеряна», «Ошибка» и причины: отказ терминала/оболочки, лимит, timeout, обрыв. Отказ одного канала сам по себе не закрывает общий SSH.
- **FR-709**: MUST сохранять порядок ввода/вывода; каждый принятый фрагмент ввода отправляется не более одного раза, без обещания exactly-once исполнения. После обрыва результат последнего ввода может быть неизвестен; очередь очищается, команды не повторяются. Скрытая/невыбранная консоль не получает клавиатурный UI-ввод; MCP адресует сессию явно. Многострочная UI-вставка требует подтверждения с числом строк; отмена не отправляет ничего. MCP передаёт явное подтверждение многострочного ввода в своём запросе, без обязательного открытия UI. Подтверждение привязано к сессии, её поколению, праву ввода и точному содержимому действия.
- **FR-710**: Disconnect, изменение endpoint/auth, удаление сервера и отзыв доверия MUST немедленно блокировать ввод и отменять старые каналы до принятия новых эффектов; поздние callbacks игнорируются. При отзыве доверия/смене endpoint/auth/удалении профиля сервера буферы очищаются. При обычном обрыве/отключении или выходе оболочки буфер read-only до закрытия/выхода приложения; reconnect не оживляет старый канал.
- **FR-711**: Закрытие активной/открывающейся консоли MUST требовать подтверждения «Удалённые процессы могут продолжить работу» в UI либо явного confirmed в MCP-запросе, закрывать только её канал и очищать буфер. MCP закрывает активную консоль только при наличии текущего права ввода; завершённую — без него. Повтор безопасен. Выход приложения использует lifecycle 002, закрывает все каналы без отдельных запросов на каждый; нет remote kill/sudo и обещания завершить фоновые процессы.
- **FR-712**: Смена раздела/сервера, общие настройки и трей MUST сохранять консоли. Мониторинг 004 и журналы 005 независимы. Терминал не удерживает эксклюзивную очередь их чтения на всё время жизни оболочки; разделение ресурсов определяется планом.
- **FR-713**: MUST ограничить scrollback каждой сессии 10 000 строками и 4 MiB декодированного текста (первый достигнутый предел), очередь необработанного вывода 1 MiB, очередь ввода 64 KiB. Экран и parser state имеют конечные пределы, закрепляемые контрактом до реализации. Старый scrollback вытесняется с отметкой; если вывод нельзя обработать в лимите, канал завершается с причиной неполноты, без молчаливого удаления байтов из середины протокола. Превышение ввода отклоняет действие целиком, без скрытой частичной отправки.
- **FR-714**: Ввод/вывод MUST оставаться в памяти владельца приложения, без локального transcript на диске, клиентской базы команд, telemetry и диагностических payload. Авторизованный MCP получает только явно запрошенное содержимое своей целевой консоли по FR-719–721. Удалённая оболочка может вести свою историю, приложение её не меняет. Произвольные секреты в выводе автоматически не маскируются и могут быть видны MCP как пользователю. При echo off клиент не создаёт отдельную историю отправленных клавиш/секретов и не возвращает их как историю. Clipboard используется только по явному UI-копированию/вставке; серверные последовательности не читают/меняют clipboard, не открывают URL/файлы, не запускают локальные процессы и не принимают доверие.
- **FR-715**: Консоль MUST быть доступна UI и MCP с действующим разрешением 003, включая существующие действующие grants; отдельный терминальный token/grant не вводится. В UI описания полномочий MCP MUST явно указывать чтение содержимого консолей и ввод команд. Права удалённых действий определяет SSH-учётная запись; нет автоматического повышения прав, вставки credentials из хранилища в prompts или установки оболочек/агентов. Прочитанное содержимое — данные; терминальный owner не интерпретирует его как MCP-запросы или автоматические команды.
- **FR-716**: MUST использовать C01, C02, C03/C04/C13 для настроек, C10/C11/C12 для состояний, C14 для подтверждений, C16/C17 для навигации из [001](../001-design-system/component-library.md). Текущий C26 — машинный текст, не интерактивный терминал. Терминальный вариант C26 оформляется в scope 001 до UI-реализации консоли; локальный аналог запрещён. Owner консоли управляет каналами/лимитами/вводом/lifecycle, общий компонент не создаёт SSH/exec/retry/consent.
- **FR-717**: MUST использовать готовый стандартный терминальный движок для встраивания в Windows-приложение. Выбор библиотеки, лицензии, поставки, точной совместимости и SSH-адаптера обязателен на стадии плана; runtime-компоненты не скачиваются при открытии. Пользователь выбирает удалённую оболочку, не библиотеку рендеринга. Внешние Windows Terminal/PowerShell/cmd/PuTTY и локальные сессии вне первой версии.
- **FR-718**: Приёмка MUST использовать только unit/native adapter unit и functional widget fakes: данные/семантику, состояния, callbacks, validation, лимиты, потоковые фрагменты, гонки, trust fences и recovery. Нет integration/e2e, реального Isar в Flutter unit, запуска приложения/внешних терминалов или feature layout/golden/overflow/capture gates. Дизайн общего C26 проверяется отдельно в scope 001 на синтетических входах; unit не доказывают полную интеграцию на чистой ОС.

### MCP: общий терминал, история и управление

- **FR-719**: MUST предоставить через встроенный MCP ограниченные операции списка сессий выбранного сервера, открытия, чтения истории/состояния, получения/освобождения права ввода, отправки текста/клавиш и закрытия. Каждая операция указывает сервер и sessionId (кроме списка/открытия); скрытый generic exec вне сессии запрещён. UI и MCP используют одного owner, одни каналы и буферы; сессия MCP видна в UI даже в трее, действия MCP не переключают выбранный пользователем сервер или вкладку. Доступны все сессии разрешённых серверов, включая созданные UI/другим клиентом; отдельной клиентской копии терминала нет. Профили оболочек можно перечислить/выбрать для запуска, но их CRUD/default остаются настройками UI.
- **FR-720**: История MUST означать текущий экран и доступный ограниченный scrollback сессии, включая вывод до присоединения клиента, а не shell history сервера или дисковую запись всех прошлых запусков. MCP получает очищенное от исполняемых управляющих последовательностей текстовое представление, порядок, состояние, владельца ввода и признак неполноты. Полноэкранные изменения отражаются актуальным снимком экрана; старый снимок не выдаётся за текущее состояние. Команды видны в истории только в той мере, в какой их отобразил терминал; ввод без echo не раскрывается отдельно. Каждый снимок/страница несёт позицию/версию истории; постраничное/последующее чтение явно сообщает вытеснение/очистку и позволяет запросить новый актуальный снимок. Успешная отправка ввода не доказывает, что команда завершилась или имеет отдельный exit code: exit code известен только при завершении оболочки. Результат произвольной команды MCP определяет по наблюдаемому выводу, без выдуманной command-boundary модели.
- **FR-721**: MUST ограничить выдачу одной страницы истории 1000 строками и 64 KiB UTF-8 текстового содержимого, общую сериализованную MCP-выдачу — 1 MiB согласно 003; длинная строка может возвращаться фрагментами с позицией продолжения, без разрыва Unicode-символов. Чтение возвращает доступные данные сразу, без бесконечного ожидания команды; длинные операции наблюдаются повторным явным чтением. Screen/scrollback остаются в пределах FR-713; дублирующий неограниченный transcript для MCP запрещён. После закрытия, очистки по trust fences или restart старые позиции не дают доступ к удалённым данным. Хранение истории внешним MCP-клиентом вне контроля приложения; локальная очистка не отзывает уже выданные ему данные.
- **FR-722**: MUST сериализовать UI/MCP ввод через единственное право ввода на сессию: начально владелец — создавший сессию UI или MCP-клиент. MCP явно запрашивает право и получает его, если оно свободно либо уже принадлежит этому клиенту, без отдельного UI-подтверждения. UI может освободить право отдельным действием «Передать управление MCP». Другой MCP не вытесняет текущего владельца, получает busy; чтение доступно независимо. Право действует до освобождения/отзыва/закрытия, но не дольше 60 секунд с выдачи или последнего принятого действия ввода владельца; после истечения оно свободно, прежний token не действует. Продление происходит только новым принятым вводом. Первый UI-ввод при свободном праве атомарно выдаёт его UI; гонка с MCP-захватом допускает только одного владельца. UI всегда может явно взять управление без ожидания, инвалидируя прежний token/поколение права. Частичная строка оболочки при смене владельца остаётся как есть, не отправляется/не стирается автоматически; новый владелец читает экран и решает, как продолжить. UI показывает имя MCP-владельца и возможность забрать управление; клавиатурный UI-ввод при владении MCP блокируется с причиной, без незаметного смешивания байтов.
- **FR-723**: Ввод MCP MUST адресовать конкретную сессию, её поколение и актуальное право ввода; текст и управляющие клавиши проходят тем же каналом, что UI, без отдельного exec. Корректировка — ввод редактирующих клавиш в текущую удалённую программу, прерывание Ctrl+C или последующая исправленная команда. Нет переписывания прошлой истории, отмены уже выполненных эффектов или гарантии успешности Ctrl+C. Приложение не определяет prompt и не обещает автоматическое исправление команды. Изменение терминальных строк/столбцов принадлежит UI, MCP не меняет их конкурентно.
- **FR-724**: Открытие, передача управления, ввод и закрытие через MCP MUST иметь идентичность повтора и проверку актуальных версий, исключающие повторный эффект после потери ответа, включая reconnect MCP к живому приложению. Повтор того же действия возвращает прежний исход только после повторной авторизации; иной payload с той же идентичностью — конфликт. Содержимое ввода не сохраняется в дисковой истории повторов 003 и не возвращается в cached response; для сравнения допустим только ограниченный in-memory fingerprint. Устаревший/вытесненный повтор явно отклоняется без отправки; контракт до реализации определяет bounded replay records и защиту от повторного принятия забытого ID. После restart прежние session/operation identities не действуют. Отзыв, утрата права ввода или смена SSH-поколения блокируют ещё не отправленную часть; уже отправленные байты не отзываются. Частичный обрыв при отправке даёт «результат неизвестен», без автоматического replay.
- **FR-725**: Авторизация 003 MUST проверяться на каждом запросе, перед выдачей истории и перед отправкой ввода, включая повторы. Отзыв/замена/expiry grant и выключение MCP отменяют pending операции клиента и освобождают его право ввода; терминальные каналы и UI-история остаются, если нет причины закрытия по FR-710. Потеря stdio/pipe освобождает право ввода и блокирует неотправленный ввод этого соединения, но не закрывает терминал и не останавливает уже исполняемую команду. Новый канал MCP заново получает право; одного clientId или знания sessionId недостаточно для доступа. MCP не получает управление выходом приложения, удалением серверов или выдачей grants.
- **FR-726**: Расширение MCP MUST быть оформлено в техническом плане как явное дополнение baseline 003: типизированные tools/schema/results/errors, реестр и UI-описание полномочий обновляются согласованно. Ограничения 003 на 13 tools, отсутствие terminal/exec и запрет выдачи произвольного remote payload относятся к исходным возможностям 003; этот пакет расширяет их только операциями консоли FR-719–725. Защита credentials хранилища, транспорт/протокол/identity и запреты delete-host/token-admin/app-exit остаются. До реализации обязательны версия внешнего контракта, совместимость discovery, cursor/replay и unit-проверки всей новой цепочки; текущие JSON-схемы 003 этим продуктовым документом не объявляются уже изменёнными.

### Key Entities

- **Профиль терминала**: ID, название, встроенный default-shell либо абсолютный путь. Не содержит SSH-credentials и отличается от профиля сервера.
- **Настройки терминала**: пользовательские профили и ID default в общем локальном хранилище.
- **Терминальная сессия**: sessionId, сервер/revision/поколение, снимок профиля терминала, состояние, причина/exit code и ограниченный буфер в памяти.
- **Действие ввода**: UI/MCP-источник, байты, сессия/поколение и порядок; байты после отправки/завершения не хранятся отдельно от отображённого терминалом вывода. Ограниченные replay metadata без payload могут оставаться в памяти.
- **Право ввода**: единственный UI/MCP-владелец, поколение/token и момент истечения; чтение не требует владения вводом.
- **Позиция истории**: сессия/поколение, версия снимка/позиция страницы; позволяет различать продолжение и разрыв ограниченной истории.

## Success Criteria

### Measurable Outcomes

- **SC-701**: Во всех fake-сценариях AC-701–704/710–713 ввод/вывод принадлежат своей сессии; 0 запусков от просмотра и 0 отправок после инвалидирования поколения.
- **SC-702**: Все AC-705–709 сохраняют целостные настройки; 0 перезапусков работающих сессий от изменения профилей/default.
- **SC-703**: На границах всех лимитов FR-707/713 работа либо принята целиком в caps, либо отклонена с причиной; неполный вывод всегда обозначен.
- **SC-704**: Во всех AC-711–714 прекращается ввод, нет replay и закрытия чужих каналов; открытие не остаётся pending дольше 15 секунд сетевого ожидания.
- **SC-705**: Для тестовых управляющих последовательностей/секретных payload FR-714/715 — 0 неявных действий с clipboard/локальными процессами и 0 payload в persistence/diagnostics или неавторизованных MCP-ответах; ввод без echo не появляется в истории.
- **SC-706**: Во всех AC-715–722 UI/MCP наблюдают один терминал; 0 невидимых exec-каналов, повторных вводов от retry и отправок от утратившего право клиента. Захват UI/отзыв/обрыв MCP не закрывают общий терминальный канал.
- **SC-707**: Все fake-сценарии чтения до/после вытеснения, очистки и restart сохраняют границы FR-713/721, корректную последовательность и признак неполноты; 0 выдач удалённой истории или скрытого ввода.

## Assumptions

- Пользователь подтвердил встроенную вкладку консоли с выбором профиля удалённой оболочки в настройках приложения; решение зафиксировано в Clarifications.
- Первая версия: Windows-клиент и Linux SSH-серверы [003](../003-ssh-mcp/spec.md), runtime/store [002](../002-desktop-runtime/spec.md). Нет подходящей оболочки/терминала — понятная ошибка, не установка зависимостей автоматически.
- Исключение terminal/commands из scope 003 относится к исходному пакету 003; текущий 007 добавляет общую UI/MCP-консоль по FR-726. Отдельный generic exec вне наблюдаемой сессии не вводится. [Мониторинг](../004-server-monitoring/spec.md) и [журналы](../005-server-journals/spec.md) сохраняют read-only контракты.
- Дисковый recording/replay, экспорт, поиск scrollback, tmux, serial/container console, локальные оболочки, внешние terminal providers и расширения как у VS Code вне scope. Команды вводит пользователь или авторизованный MCP в рамках права ввода. История означает доступный буфер текущей сессии; хранение между запусками не добавляется.
- Пакет проходит полный цикл Spec Kit по запросу пользователя: подготовлены [план](plan.md), [исследование](research.md), [модель данных](data-model.md), [контракты](contracts/mcp-console.md), [задачи](tasks.md) и [проверки](quickstart.md). Готовность к реализации устанавливается отдельным независимым ревью после analyze/checks. Общий компонент изменяется в scope 001; реализация и пройденные проверки не подразумеваются самим наличием документов.
