# Feature Specification: 003 — MCP, SSH-профили, подключения и доверие

**Feature**: `003-ssh-mcp`
**Created**: 2026-11-02
**Status**: Базовая003 реализована; уточнение2026-11-04 в работе по Spec Kit.
**Input**: Сохранять профили серверов, подключаться по SSH с паролем или ключом,
проверять доверие при подключении и явно отмечать сервер с изменившимся доверием.
**Amended**: 2026-11-02 — встроенный MCP: те же SSH-возможности, кроме удаления хостов.

## Test policy — уточнение пользователя 2026-11-03

Только юнит-тесты по constitution1.3.0: owners/controllers/router/codec/SSH policy
проверяются изолированно с подставными transport/store/clock/identity/crypto-boundary
зависимостями. Pure-Dart parsing/crypto допускаются на synthetic key material.
Unit protocol fixtures подают байты через in-memory streams без TCP/SSH-сервера,
реальной Isar, GUI/stdio subprocess, Explorer, VM или process-kill scenarios.
AC/SC описывают поведение продукта; они не предписывают интеграционные прогоны.
Сборка, статические анализ/import/manifest и ссылки проверяются отдельно.

## User Scenarios & Testing

### User Story 1 — Сохранить профиль сервера (Priority: P1)

Пользователь сохраняет параметры сервера один раз и после перезапуска находит
профиль с выбранным способом входа. Сохранение не подключает к серверу.

**Why this priority**: Список сохранённых серверов — основа повторного подключения.
**Independent Test**: Юнит-проверки profile operations и model serialization на fake store: пароль/ключ, сохранение, повторное чтение snapshot и отсутствие сетевых вызовов.

**Acceptance Scenarios**:

1. **AC-301 Given** новый профиль, **When** сохранены имя, адрес, порт, пользователь
   и пароль, **Then** профиль появляется в списке и остаётся после перезапуска;
   пароль не отображается в списке и повторно вводить его для подключения не нужно.
2. **AC-302 Given** приватный ключ, **When** пользователь выбирает его и сохраняет
   профиль, **Then** приложение сохраняет защищённую копию ключа; перемещение или
   удаление исходного файла не ломает сохранённый профиль.
3. **AC-303 Given** некорректные поля или неподдерживаемый ключ, **When** нажато
   «Сохранить», **Then** указана причина, профиль не сохранён частично и SSH не начат.
4. **AC-304 Given** сохранённый профиль, **When** изменены параметры или подтверждено
   удаление, **Then** изменения переживают перезапуск; удаление не меняет сервер.

### User Story 2 — Подключиться и подтвердить сервер (Priority: P1)

Пользователь выбирает профиль и явно подключается. До передачи credentials
приложение проверяет предъявленный сервером host key. Пользователь проверяет
отпечаток неизвестного сервера и принимает или отклоняет его.

**Why this priority**: Успешная аутентификация должна относиться к проверенному серверу.
**Independent Test**: Юнит-проверки SSH policy на in-memory transport и подставном peer: host verification до auth, выбранный метод, cancel/timeout; без управляемого сервера.

**Acceptance Scenarios**:

1. **AC-305 Given** сервер ещё не принят, **When** начато подключение, **Then** видны
   профиль, адрес:порт, тип host key и SHA-256-отпечаток; до явного принятия пароль
   и доказательство владения пользовательским ключом серверу не отправляются.
2. **AC-306 Given** запрос доверия, **When** пользователь отменяет его, **Then** попытка
   завершается без аутентификации и без сохранения доверия.
3. **AC-307 Given** пользователь принял показанный ключ, **When** доверие сохранено
   и аутентификация успешна, **Then** профиль имеет состояние «Подключён»;
   следующий сеанс с тем же host key не требует повторного принятия.
4. **AC-308 Given** неправильный пароль или passphrase ключа, **When** вход не удался,
   **Then** показана соответствующая ошибка, профиль сохранён, статус не «Подключён»;
   исправление и повтор возможны только по действию пользователя.
5. **AC-309 Given** подключение установлено, **When** пользователь отключается или
   перезапускает приложение, **Then** сеанс закрыт, профиль и принятое доверие
   сохранены; приложение не подключается автоматически после запуска.

### User Story 3 — Увидеть смену доверия (Priority: P1)

Если сервер предъявил другой ключ, пользователь видит устойчивое предупреждение
и решает, можно ли доверять новой идентичности после отдельной проверки.

**Why this priority**: Смена ключа может означать другой сервер; её нельзя принять молча.
**Independent Test**: Юнит-проверки trust owner на последовательности A→B→C, fake durable snapshot и часах: warning, restart state, fences и явная замена.

**Acceptance Scenarios**:

1. **AC-310 Given** ранее принят A, **When** сервер предъявляет B, **Then** попытка
   блокируется до аутентификации; у профиля в списке и в подробностях появляется
   текст «Доверие изменилось», доступны старый и новый отпечатки и адрес:порт.
2. **AC-311 Given** обнаружена смена ключа, **When** предупреждение закрыто или
   приложение перезапущено, **Then** предупреждение сохраняется; A остаётся
   принятым, B автоматически не принимается, повторный вход с B заблокирован.
3. **AC-312 Given** пользователь отдельно сверил B, **When** он явно подтверждает
   «Заменить доверенный ключ» для этого адреса и пары A→B, **Then** замена сохраняется;
   новое подключение проверяет B заново и допускает аутентификацию только при совпадении.
4. **AC-313 Given** открыто подтверждение A→B, **When** сервер уже предъявляет C,
   профиль изменён/удалён или доверие уже заменено другим действием, **Then** старое
   подтверждение не разрешает вход и не перезаписывает актуальное решение.

### User Story 4 — Управлять SSH через встроенный MCP (Priority: P1)

Пользователь подключает MCP-клиент к запущенному ServerDeck и управляет теми же
профилями, соединениями и доверием. Удалять хосты через MCP нельзя.

**Why this priority**: Автоматизация использует ту же работу с серверами и те же
ограничения, что интерфейс, без второго приложения или независимой базы.
**Independent Test**: Юнит-проверки MCP router и общих AppOperations на fake actors/transport/store: grants,13tools, паритет эффектов с UI и запрет delete.

**Acceptance Scenarios**:

1. **AC-314 Given** MCP выключен или токен неверен/отозван, **When** клиент запрашивает
   данные или действие, **Then** доступа нет и никакие профили/соединения не меняются.
2. **AC-315 Given** разрешённый MCP-клиент, **When** создаёт/редактирует профиль,
   подключается, отменяет попытку или отключает сеанс, **Then** результат и данные
   совпадают с UI; секреты не возвращаются в ответе и нет второй копии состояния.
3. **AC-316 Given** неизвестный/изменившийся ключ, **When** MCP инициирует подключение,
   **Then** возвращается необходимость решения с endpoint и отпечатками; отдельное
   явное актуальное подтверждение через MCP подчиняется FR-307–313, без auto-accept.
4. **AC-317 Given** клиент знает ID хоста, **When** пытается удалить его прямо,
   неизвестной командой, через bulk/import или другим обходом, **Then** операция
   отклонена и хост/его credentials/доверие не удалены. UI-удаление остаётся доступно.
5. **AC-318 Given** окно скрыто в трее, **When** MCP меняет профиль или читает состояние,
   **Then** действия продолжают работать; восстановленное окно показывает их результат.
6. **AC-319 Given** UI и MCP одновременно меняют профиль либо повторяется запрос после
   потери ответа, **When** операция обрабатывается, **Then** нет потерянного изменения,
   дублированного профиля или повторного принятия неактуального ключа.

7. **AC-320 Given** конфигурация клиента из UI, **When** клиент запускает мост под
   текущим пользователем Windows, **Then** соединение авторизовано без ручной вставки
   токена, другого EXE, HTTP-порта и запуска второго владельца данных.
8. **AC-321 Given** другой Windows-пользователь/сессия, поддельный pipe или истёкшее
   разрешение, **When** запрошено соединение, **Then** данных и SSH-эффектов нет;
   при неверном владельце pipe секрет клиента не передаётся.
9. **AC-322 Given** разрешение отозвано/заменено во время запроса или после restart,
   **When** старый канал/секрет повторяет запрос, **Then** нет доступа, в том числе
   к кэшированному результату; подтверждённые до отзыва записи не откатываются.

### Edge Cases

- Недоступная сеть, неверный адрес, отказ TCP, timeout, обрыв SSH и отказ аутентификации
  различаются от изменения доверия; сеть не сбрасывает ранее обнаруженное предупреждение.
- Пароль содержит пробелы/спецсимволы; IPv6-адрес; имя пользователя чувствительно к регистру.
- Зашифрованный, повреждённый, слишком большой или неподдерживаемый ключ; пользователь
  выбрал публичный ключ вместо приватного; защищённое хранилище недоступно.
- Двойное нажатие «Подключиться», отмена во время handshake, поздний ответ после отмены,
  удаления профиля или смены адреса; повторное подтверждение устаревшего host key.
- Несколько профилей с разными пользователями для одного endpoint; DNS-имя и IP одного
  сервера считаются разными endpoint; сервер снова предъявляет прежний A после обнаружения B.
- Ошибка сохранения профиля/секрета/доверия и завершение приложения во время записи.
- Потеря MCP-ответа после записи, одновременные UI/MCP-действия, отзыв доступа во
  время подключения, закрытое в трей окно и выход из приложения во время запроса.

## Requirements

### Functional Requirements

#### Профили и credentials

- **FR-301**: MUST поддерживаться создание, просмотр, изменение и подтверждаемое удаление
  локальных профилей. Профиль содержит стабильный ID, имя, host, порт, SSH-пользователя
  и ровно один выбранный способ входа: пароль либо приватный ключ. По умолчанию порт 22.
- **FR-302**: Имя после обрезки внешних пробелов MUST содержать 1–100 символов,
  пользователь — 1–255 символов без пробельных/управляющих символов; host — DNS-имя,
  IPv4 или IPv6 без URL, имени пользователя, пути и встроенного порта.
  Порт — целое 1–65535. Host не пустой, до 253 символов; ошибка относится к конкретному
  полю. Пароль не пустой и MUST сохраняться без trim/изменения содержимого.
  Совпадающие имена и адреса допустимы; профиль различается стабильным ID.
- **FR-303**: Явное сохранение профиля с паролем MUST сохранять пароль локально в
  защищённом виде для последующих подключений. Для ключа MUST импортироваться защищённая
  копия приватного ключа, а не только путь к исходному файлу. Поддерживаются приватные
  ключи OpenSSH Ed25519/RSA≥2048 и RSA PEM PKCS#1≥2048, зашифрованные и незашифрованные, по [контракту входных ключей](contracts/key-input.md).
  Иные форматы/типы явно отклоняются без изменения существующего профиля.
  Размер импортируемого файла — не более 1 МиБ. При импорте зашифрованного ключа
  passphrase запрашивается для проверки формата/типа и пригодности ключа; после
  проверки отбрасывается, её отмена/ошибка не сохраняет непроверенный ключ.
- **FR-304**: Passphrase зашифрованного ключа MUST запрашиваться при каждой новой попытке,
  использоваться только для этой попытки и не сохраняться между подключениями.
  Отмена ввода отменяет попытку; неверная passphrase не заменяет сохранённый ключ.
- **FR-305**: Секреты MUST быть защищены средствами локальной ОС для текущего пользователя;
  пароль, приватный ключ и passphrase не попадают в открытые файлы метаданных, логи,
  сообщения ошибок, список серверов или clipboard. Поле секрета скрыто по умолчанию.
  При недоступности защиты нет fallback к открытому хранению или частичному сохранению.
- **FR-306**: Сохранение/изменение MUST быть целостным: после ошибки или перезапуска
  доступна либо прежняя полная версия, либо новая полная версия, без потерянной связи
  профиля с credentials. Замена способа входа удаляет прежний секрет после успешного
  сохранения; удаление профиля удаляет его секреты. Пользовательский исходный файл ключа
  не изменяется. При ошибке удаления профиль остаётся доступным с явной ошибкой.

#### Доверие серверу

- **FR-307**: Доверие MUST проверяться при каждом новом SSH-подключении по реально
  предъявленному host key до аутентификации пользователя. Host key сервера и ключ
  пользователя — разные сущности. Никакого автоматического принятия или режима
  «игнорировать проверку». Отпечаток отображается как SHA-256 вместе с типом ключа.
- **FR-308**: Запись доверия MUST принадлежать endpoint (нормализованный host, порт)
  внутри локального пользователя приложения и быть общей для его профилей этого endpoint.
  DNS-имя сравнивается без учёта регистра и завершающей точки, IP — в канонической записи;
  IPv6-скобки ввода снимаются. DNS-алиасы и DNS→IP не объединяются автоматически.
  Изменение пользователя/credentials не сбрасывает доверие; изменение host/порта
  использует запись нового endpoint, не переносит принятие со старого.
- **FR-309**: Для неизвестного endpoint MUST запрашиваться явное принятие предъявленного
  ключа. Закрытие, Escape, отмена и timeout не означают принятия. Решение действует
  только для показанных endpoint и ключа; оно MUST быть сохранено до аутентификации.
  Ошибка записи доверия блокирует вход. Если credentials затем отклонены, уже явно
  принятое доверие сохраняется отдельно от результата аутентификации.
- **FR-310**: При несовпадении с принятым ключом MUST блокироваться вход и сохраняться
  предупреждение «Доверие изменилось» для всех профилей endpoint, с прежним принятым
  и последним отличающимся наблюдённым отпечатками и временем обнаружения.
  Предупреждение не зависит только от цвета, присутствует в списке и подробностях,
  переживает закрытие диалога, сетевые ошибки и перезапуск.
- **FR-311**: Новый ключ MUST приниматься только отдельным явным подтверждением замены
  с указанием endpoint, прежнего и нового отпечатков и необходимости независимой сверки.
  Старое доверие остаётся до успешной записи замены. Замена завершает текущую попытку;
  продолжение возможно только новым явным подключением и новой проверкой ключа.
  Отказ от замены не сбрасывает предупреждение. Если вновь предъявлен прежний принятый
  ключ, обычная проверка доверия допускает вход, но предупреждение о наблюдавшемся
  изменении остаётся до явного подтверждения «Оставить прежний ключ» с повторной
  проверкой совпадения принятого ключа. Тихого возврата доверия нет.
- **FR-312**: Все решения доверия MUST проверяться на актуальность endpoint, версии
  профиля и записи доверия; устаревшее подтверждение не действует. Принятие одного
  неизвестного ключа не разрешает другой ключ в повторном handshake. Замена/подтверждение
  доверия закрывает другие сеансы этого endpoint, чтобы переподключение проверило
  актуальное решение. Простое обнаружение иного ключа в новой попытке также закрывает
  другие сеансы этого endpoint; ошибка такого закрытия не разрешает новые операции.
- **FR-313**: Удаление последнего профиля endpoint MUST удалять связанную запись доверия
  и предупреждение в рамках целостного удаления. Пока другие профили endpoint есть,
  доверие остаётся общим. Повторное создание после удаления последнего профиля
  требует первого принятия заново. Приложение не меняет системный known_hosts.

#### Подключения и восстановление

- **FR-314**: MUST быть явные «Подключиться», «Отменить подключение», «Отключиться»
  и повтор после ошибки. Сохранение, открытие профиля и запуск приложения не начинают
  подключение. Используется только выбранный способ входа, без скрытого fallback.
- **FR-315**: Для профиля MUST быть различимы состояния «Не подключён», «Подключение»,
  «Нужно доверие», «Подключён» и ошибка с причиной. Состояние доверия отображается
  отдельно и не подменяется фактом сохранённого профиля. «Подключён» означает текущий
  аутентифицированный SSH-сеанс, а не сохранённый успешный результат прошлого запуска.
- **FR-316**: На профиль допускается не более одной активной попытки или одного сеанса;
  повторное нажатие не дублирует их. Разные профили могут подключаться независимо.
  Изменение host/порта, пользователя, credentials, удаление профиля или отключение
  MUST закрывать его сеанс и отменять попытку; переименование не переподключает.
  Поздние ответы не восстанавливают отменённое состояние или удалённый профиль.
- **FR-317**: Попытка связи/handshake/аутентификации MUST завершаться timeout не позднее
  30 секунд активного ожидания сети; время явного пользовательского ввода/сверки
  не включается. Неотвечающий запрос ввода/доверия отменяется через 5 минут.
  Первичная неудачная попытка автоматически не повторяется. После обрыва ранее
  установленного SSH-сеанса действуют ограниченные повторы FR-348.
- **FR-318**: Обрыв соединения MUST переводить сеанс в «Не подключён» с причиной;
  потеря связи без явного закрытия обнаруживается не позднее 90 секунд.
  После перезапуска все профили изначально отключены; сохранённые данные и предупреждения
  доступны без сети. Отказ локального хранилища не трактуется как пустой список:
  показана ошибка и доступно явное повторение чтения, без перезаписи сохранённых данных.
- **FR-319**: Ошибки MUST различать validation, чтение/защиту/запись данных, сеть/timeout,
  неизвестный/изменившийся host key, отказ аутентификации и неподдерживаемый SSH-сервер
  или ключ. Ошибка не содержит credentials и указывает допустимый следующий шаг.
  SSH-сервер не изменяется: клиент не устанавливает агентов, ключи или пакеты.

#### Общие элементы и функциональная приёмка

- **FR-320**: MUST использоваться готовые элементы [001](../001-design-system/spec.md):
  C01 — брендбук/темы; C02 — действия; C03/C04/C13 — поля, способ входа и формы;
  C07/C09 — список/карточка профиля; C10/C11/C12 — статус, предупреждение и ошибки;
  C14 — подтверждения доверия/удаления; C18 — данные и публичные отпечатки.
  Секреты не передаются общему copy control. Владельцы профиля и подключения управляют
  данными, состояниями, validation и callbacks согласно
  [контрактам 001](../001-design-system/component-library.md).
- **FR-321**: Приёмка MUST проверять данные, сохранение, переходы состояний, callbacks,
  блокировку аутентификации до доверия, устаревшие ответы и восстановление.
  Тесты дизайна страниц, golden/screenshots, geometry/overflow и матрицы тем/размеров
  не добавляются и не запускаются. Повторная дизайн-приёмка C01–C30 не входит в 003.

#### Встроенный MCP и паритет с интерфейсом

- **FR-322**: MCP MUST быть встроен в тот же экземпляр ServerDeck, использовать те же
  операции и данные, что UI, и не требовать отдельного EXE, сервиса, Node/Python или
  запуска второго владельца базы. Жизненный цикл приложения и единственная Isar
  определены в [002 — приложение и трей](../002-desktop-runtime/spec.md).
- **FR-323**: Разрешённому MCP-клиенту MUST быть доступны: список/подробности профилей,
  создание/редактирование (включая смену credentials), подключение, состояние/ошибка,
  отмена/отключение, чтение доверия/предупреждений, первое принятие ключа, явная замена
  и решение оставить прежний ключ. UI и MCP используют одну validation, версии,
  правила сохранения/отказов и состояния FR-301–319. Входные секреты допускаются
  в запросах записи, но ни одна операция чтения/ответа их не раскрывает.
- **FR-324**: Удаление профиля/хоста через MCP MUST отсутствовать в опубликованных
  возможностях и быть запрещено обработчиком, а не только спрятано в списке tools.
  Нет generic-command, bulk replace, reset/import или другой операции, позволяющей
  удалить хосты в обход запрета. Редактирование сохраняет стабильный ID; целевое
  удаление старого секрета при смене credentials по FR-306 не является удалением хоста.
- **FR-325**: MCP MUST быть выключен по умолчанию. В UI пользователь включает его,
  создаёт именованное разрешение для конкретного MCP-клиента и получает конфигурацию
  запуска того же EXE в режиме stdio-моста. Разрешение связывает текущую Windows-учётную
  запись и отдельный случайный секрет клиента; один Windows SID без разрешения
  недостаточен. Разрешение действует 90 дней, переживает restart, отзывается/заменяется
  из UI. Все SSH-операции FR-323 разрешены, удаление хостов — запрещено.
  Авторизация и отзыв определены в [локальном доступе MCP](mcp-access.md).
- **FR-326**: MCP-клиент использует стандартный stdio MCP `2025-11-25`, запуская
  `ServerDeck.exe --mcp-stdio --client <id>`. Мост подключается к основному экземпляру
  через локальный Windows Named Pipe с явным DACL, проверкой Windows SID/сессии и
  отдельного секрета клиента. Нет TCP/HTTP-listener, LAN-доступа, OAuth-сервера,
  Node/Python или отдельного устанавливаемого bridge. Мост не открывает Isar,
  не исполняет SSH и не начинает основное приложение. Без работающего основного
  экземпляра возвращает недоступность и завершает только себя. Named Pipe —
  внутренний канал приложения, а не требование к поддержке pipe внешним MCP-клиентом.
  Одно разрешение MUST поддерживать независимые одновременные MCP-сессии разных
  чатов без отдельной квоты на клиента, в пределах 8 каналов основного экземпляра.
  Закрытие одной сессии не закрывает остальные; отзыв/замена/истечение разрешения
  затрагивают все его сессии. Превышение общего предела отклоняет только новый канал.
- **FR-327**: MCP MUST явно запрашивать решение доверия отдельным действием с
  endpoint, точными отпечатками и актуальными версиями, как UI. Получение статуса,
  вызов connect и повтор не считаются согласием. Разрешённый клиент может принять
  решение через MCP без обязательного открытия UI, но не обходит FR-307–313.
  Ключ импортируется переданным содержимым, а не произвольным чтением сервером
  локального пути. Passphrase передаётся только для соответствующего импорта или
  текущей попытки; ожидание ввода и его отмена доступны клиенту, не требуют видимого окна.
- **FR-328**: UI/MCP MUST сериализовать конфликтующие изменения одной сущности и
  проверять её версию; устаревшая запись возвращает конфликт, а не затирает новую.
  Создание, изменение и решения доверия через MCP принимают идентификатор повтора
  клиента: повтор того же запроса тем же клиентом в течение 24 часов возвращает
  прежний исход без повторного эффекта, включая после restart; тот же ID с другим
  содержимым даёт конфликт. При недоступности истории повторов запись блокируется.
  Connect/cancel/disconnect подчиняются ограничению одного сеанса FR-316.
- **FR-329**: Ошибки MCP MUST быть различимыми машинно: нет доступа, не найден профиль,
  неверные поля, конфликт версии/повтора, нужно решение доверия, изменён ключ,
  отказ аутентификации, сеть/timeout, недоступно хранение, приложение завершает работу.
  Результат не выдаёт незавершённую запись за успех. Секреты исключены из ошибок и
  ответов; отказ транспорта не считается автоматической отменой или поводом повтора.
- **FR-330**: MCP MUST продолжать работу при скрытии окна в трей и прекращаться при
  выходе из приложения. Управление жизненным циклом приложения, удаление хостов
  и выдача/отзыв клиентских токенов остаются UI-функциями; это не SSH-операции FR-323.
  MCP не получает команды выхода. Для настройки используются C02/C03/C04/C10/C11/C13,
  для показа публичной конфигурации запуска — C18 из 001, без повторной приёмки их дизайна.

- **FR-331**: Создание, срок действия, замена/отзыв разрешения, включение/выключение
  MCP MUST быть доступны из UI. Выключение/отзыв немедленно закрывают затронутые
  каналы, блокируют новые действия и незавершённые попытки клиента. Авторизация
  повторно проверяется до фиксации изменения/начала SSH-аутентификации и перед
  выдачей данных, в том числе для повторов; принятая прежде MCP-сессия не обходит
  отзыв или срок. Уже подтверждённые записи не откатываются; установленные общие
  SSH-сеансы остаются до явного отключения или правила смены доверия FR-312.
- **FR-332**: Секрет разрешения MUST генерироваться криптографически случайно
  (не менее 256 бит), храниться под Windows DPAPI CurrentUser и ACL текущего
  пользователя. Его нет в CLI, конфигурации MCP, stdout/stderr, логах, URL или
  открытых файлах. Мост получает защищённый секрет по несекретному client ID
  только после проверки владельца pipe. Без доступной защиты доступ запрещён.
  После замены/отзыва прежний секрет не восстанавливает доступ, включая после restart.
- **FR-333**: Перед передачей секрета/данных MUST проверяться основной экземпляр:
  Windows SID и logon session владельца server process, его PID и время создания
  совпадают с защищённой записью работающего экземпляра. Сервер проверяет реальную
  Windows-идентичность клиента, а не заявленный в JSON SID; чужой пользователь,
  другая интерактивная сессия, удалённый pipe и неподтверждённая личность запрещены.
  Нельзя использовать default DACL, доверять только имени pipe или повторять вход
  через незащищённый TCP при ошибке проверки. Конкретные обязательные проверки и
  границы защиты — [mcp-access](mcp-access.md).
- **FR-334**: Настройка клиента MUST выдавать готовые command/args с абсолютным путём
  к текущему `ServerDeck.exe` и несекретным ID. Пользователь запускает MCP-клиент
  под той же учётной записью и в той же интерактивной сессии Windows, без admin-прав.
  Из UI видны имя клиента, срок, активность и причина отказа; token не надо вручную
  вставлять в клиент. Перенос EXE требует обновить путь в конфигурации, а не заново
  создавать профили/разрешения. MCP не выдаёт себе новое разрешение и не продлевает его.

### Key Entities

- **Профиль**: стабильный ID, имя, endpoint, SSH-пользователь, способ входа, ссылка на
  его защищённые credentials и версия для отклонения устаревших действий.
- **Credentials**: сохранённый пароль либо импортированный приватный ключ;
  временная passphrase принадлежит только попытке. Не часть публичного представления.
- **Доверие endpoint**: принятый публичный host key, тип, отпечаток, время принятия,
  версия; отдельно — факт смены, последний отклоняющийся ключ и время обнаружения.
- **Попытка/сеанс**: профиль и захваченные версии, endpoint, этап, результат/причина;
  живёт в памяти текущего запуска. Сохранённое доверие не означает живое подключение.

- **Доступ MCP-клиента**: client ID, Windows SID владельца, защищённый секрет,
  имя, время выдачи/окончания, версия и статус отзыва;
  авторизует операции FR-323, не выдаётся самому MCP-клиенту через tools.
- **Повтор MCP-изменения**: клиент, идентификатор, привязка к содержимому и исход,
  срок 24 часа; секретные части запросов не сохраняются в открытом виде.

## Success Criteria

### Measurable Outcomes

- **SC-301**: В сценариях пароля и ключа после сохранения и перезапуска восстановлены
  все данные профиля; подключение не требует повторного ввода сохранённого пароля
  или выбора исходного ключевого файла (AC-301–304, FR-301–306).
- **SC-302**: В каждом сценарии неизвестного, отклонённого или изменившегося ключа
  до актуального явного принятия — ноль попыток аутентификации (AC-305–306, AC-310–313).
- **SC-303**: При неизменном принятом ключе оба способа входа приводят к живому сеансу;
  отмена/неправильные credentials не показываются как успех (AC-307–309, FR-314–316).
- **SC-304**: Предупреждение смены ключа не теряется после закрытия, restart и сетевой
  ошибки; актуальная явная замена разрешает только новый проверенный ключ
  (AC-310–313, FR-308–313).
- **SC-305**: Для повторов, изменения/удаления во время подключения и поздних ответов
  нет двойных сеансов, восстановления удалённых профилей и принятия старого согласия
  (FR-312, FR-316); timeout и потеря связи укладываются в FR-317–318.
- **SC-306**: При ошибках сохранения/защиты/удаления и restart нет частично сохранённых
  профилей или открыто записанных секретов; ошибки не раскрывают credentials
  (FR-305–306, FR-313, FR-318–319).

- **SC-307**: Каждая операция FR-323 имеет функциональный сценарий UI/MCP с одинаковым
  результатом; в ответах нет credentials, попытки любого MCP-удаления не меняют хосты
  (AC-314–317, FR-322–327, FR-329).
- **SC-308**: Закрытие окна не прерывает MCP; отзыв доступа блокирует дальнейшие действия,
  конфликты и повторы не создают дубликаты и не затирают данные (AC-318–319, FR-325–330).

- **SC-309**: Настройка из UI позволяет stdio MCP-клиенту той же Windows-сессии войти
  через тот же EXE без ручной передачи секрета; чужая личность, подмена pipe, expiry,
  отзыв и замена дают ноль раскрытых данных/новых эффектов (AC-320–322, FR-331–334).

## Assumptions

- По уточнению пользователя порядок пакетов: 001 — компоненты, 002 — приложение
  и restore окна, 003 — MCP и SSH. Прежние SSH IDs FR/SC-001… и AC-01…
  перенумерованы в 3xx; прежний снимок пакета сохранён вне проекта.
- Начальный scope — локальное приложение для одного текущего пользователя ОС,
  прямое SSH-подключение к уже настроенному серверу с SSH2 и учётной записью.
  Windows — текущая целевая платформа; переносимость на другие ОС не входит в 003.
- Профиль и пароль/импортированный ключ сохраняются локально при явном сохранении.
  Passphrase не сохраняется. Trust on first use выполняется только с подтверждением
  пользователя; независимую сверку отпечатка пользователь делает по своему каналу.
- Под «подсветить сервис» понимается пометка сохранённого сервера, а не управление
  службами ОС. Изменение обнаруживается только при новом SSH handshake; фонового
  сканирования отключённых серверов нет. Ключ не отслеживается «в реальном времени».
- Вне scope: терминал/команды, метрики, файлы, установка ПО, sudo, bastion/proxy,
  SSH-agent, сертификаты SSH, MFA/keyboard-interactive, импорт ssh_config/known_hosts,
  облачная синхронизация и совместный доступ. Они не нужны для приёмки подключения.
- [Конституция](../../.specify/memory/constitution.md) и 001 действуют; архивная
  реализация не задаёт требований. Выбор библиотек, схемы хранения и размещения
  кода относится к следующему Plan; этот spec фиксирует поведение, не архитектуру.
- Flutter, встроенная Isar, один поставляемый EXE и работа в трее обязательны
  по конституции; базовое поведение приложения определяет 002. MCP и SSH реализуются в
  scope 003 после базового runtime 002.
- Для сверки терминов host-key/аутентификации использованы первичные руководства
  [OpenSSH ssh](https://man.openbsd.org/ssh.1) и
  [OpenSSH ssh_config](https://man.openbsd.org/ssh_config.5).

- Источники и сравнение Named Pipe/loopback/stdio: [исследование локального доступа](research.md).
  Разрешения MCP — доступ к этому компьютеру, а не отдельная учётная запись облачного сервиса.

## Уточнение пользователя — 2026-11-04

Новый пакет не создаётся: профили, форматы ключей, доверие и модальный поток остаются003; компактность метрик —004 и общий C21 —001. ПринципVI конституции1.4.0 запрещает обратную совместимость приложения до1.0. Поддержка RSA PEM и OpenSSH — текущий входной контракт.

- FR-335: Принимать ровно один RSA PEM PKCS#1≥2048 или OpenSSH RSA≥2048/Ed25519, plain/encrypted; шифры, строгие PEM/DER/RSA проверки, limits/error policy — [key-input](contracts/key-input.md). Исходные bytes под DPAPI, phrase не сохраняется.
- FR-336: Каждый privateKey credential MUST иметь проверенные canonical publicKeyBytes/type/bits; подпись в owned worker сверяет frozen public identity до результата. Отсутствие metadata — нарушение текущего контракта; старого fallback/backfill нет. Password не имеет public metadata.
- FR-337: Подробности/CRUD/connect/trust/phrase находятся в одном live C12 modal, не под списком. Выбор сервера читает данные, сам по себе не подключает.
- FR-338: После commit нового/connection-affecting save сразу открыть подробности и начать ручную проверку текущей ревизии; имя отдельно не reconnect. Полученный first host challenge и phrase предлагаются автоматически только в своём onboarding; trust принимается лишь явным согласием.
- FR-339: Изменение pin отмечается на сервере как требующее действий. Обычный мониторинг/открытие подробностей не открывает самопроизвольный trust modal; замена/retain требуют явного решения с отпечатками.
- FR-340: Не более одного trust/phrase prompt; nonce/revision/attempt/actor fences003 обязательны. Закрытый onboarding отменяет свою позднюю попытку независимо от UI pending, не новую попытку/готовый сеанс. Post-save continuation связан с controller/profile/navigation session и не влияет на другой сервер.
- FR-341: Нет старых aliases/optional compatibility constructors, миграций формата1 и веток старых credentials. Текущие API/схемы/тесты обновляются напрямую; данные без отдельного запроса не удаляются.
- AC-323: Все заявленные plain/encrypted PEM/OpenSSH варианты сохраняются/подписывают synthetic challenge; повреждённые, слабые и неподдерживаемые отклоняются без частичной записи.
- AC-324: Обязательная public metadata соответствует приватному ключу; mismatch не возвращает подпись; missing metadata не включает старый путь.
- AC-325: Нажатие строки открывает один live modal с актуальными действиями; постоянной нижней панели нет. Удаление закрывает принадлежащие профилю окна.

- AC-327: Decline/network failure сохраняют профиль и pin, дают явное восстановление без бесконечных повторов; отмена phrase/закрытие onboarding отменяет только его pending attempt.

- AC-329: Late admission/refresh, новый attempt/session, deleted profile, stale nonce и A→B navigation не дают чужих prompts/отмен/доверия.
- AC-330: Current-only API/store guards не поддерживают прежние формы приложения; старые данные явно отклоняются без автоочистки/переноса.

## Автоматическое восстановление SSH — 2026-11-10

- **FR-348**: После NETWORK_ERROR/timeout установленного сеанса ConnectionOwner
  MUST закрыть точные старые ресурсы и выполнить не более 8 повторных попыток.
  Задержка перед попыткой n: равномерный jitter в [cap/2, cap),
  cap = min(30 секунд, 1 секунда × 2^(n−1)); отсчёт монотонный, после cleanup.
  Повторные network/timeout ошибки продолжают тот же счётчик. Успешное соединение
  менее минуты не сбрасывает лимит; после ≥60 секунд работы следующий обрыв
  начинает новую серию. Первичная ошибка подключения и другие причины не повторяются.
- **FR-349**: Отмена, ручное отключение, изменение endpoint/пользователя/credentials,
  удаление, изменение trust/observation, quarantine и shutdown MUST остановить
  отложенные повторы; поздний callback не создаёт dial. Переименование сохраняет
  серию. После рестарта серия не восстанавливается. Ручное подключение после
  закрытия старых ресурсов начинает новую серию. Лимит ресурсов 64 сохраняется;
  отказ admission/cleanup останавливает серию без обхода ограничения.
- **FR-350**: Повтор выполняется owner authority текущего запуска, как продолжение
  уже установленного сеанса (включая MCP-сеанс после отзыва исходного клиента).
  Каждый dial проходит общий gate, актуальные revisions и обычную проверку ключа
  и credentials; секреты/введённая passphrase повторно не кэшируются. Запрос trust
  или passphrase передаёт управление пользователю и останавливает серию; после
  timeout этого запроса автоповтора нет. Консольные команды, ввод и прежний lease
  не воспроизводятся. Старый console session остаётся завершённым; открытие нового
  выполняется явно. Мониторинг использует новый общий SSH-сеанс штатным образом.
- **FR-351**: UI на существующих C07/C10/C14/C21 и C02-компонентах показывает номер автопопытки из 8
  и действие остановки. ConnectionView содержит optional reconnectAttempt (1..8)
  только во время ожидания/выполнения повтора. После исчерпания остаётся причина
  обрыва и доступно ручное подключение. Новый wire field additive; схема БД и
  runtime prerequisites не меняются, миграция не нужна.

Приёмка fake-only: обрыв transport/watchdog, backoff/jitter и предел, повторный
обрыв до/после минуты, ручная отмена/подключение, revision/trust/quarantine/shutdown
fencing, первый отказ/auth error и запрос ввода; никаких реальных сетевых тестов.
