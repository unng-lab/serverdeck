# Контракт входных приватных ключей

Input≤1048576original UTF8bytes, one exact supported PEM block with whitespace only outside, LF/CRLF allowed; phrase≤65536UTF8bytes. Existing OpenSSH cipher/type behavior remains003. Add label RSA PRIVATE KEY only, PKCS1 two-prime RSA n≥2048bits. No PKCS8/ECDSA/DSA fallback.

Legacy unencrypted PEM has no headers. Encrypted requires exactly one Proc-Type:4,ENCRYPTED and DEK-Info, no duplicates/extra headers. Cipher table: AES-128/192/256-CBC keys16/24/32bytes, IV/block16; DES-EDE3-CBC key24, IV/block8. IV exact hexlength; ciphertext nonempty and block aligned. KDF concatenates MD5(previousDigest+UTF8phrase+IVfirst8bytes) until keylength. CBC fullIV then strictPKCS7 unpadding. Crypto/private number validation in existing cancellable4slot/30s worker; no externalprocess.

DER: one definite minimal-length SEQUENCE ending exactly at buffer end; exactly9 primitiveINTEGERs, minimal signed representations, version0 and all8parameterspositive; no indefinite/nonminimal lengths, extra elements or trailingdata. RSA p/q>1 distinct, oddn/e,3≤e<n, p*q=n, d>1, ed mod lcm(p−1,q−1)=1, dp=d mod(p−1),dq=d mod(q−1),q*coefficient modp=1. Normalize to existing in-memory OpenSSHRsaKeyPair; run existing fixed-message sign/verify proof before import success. Clear owned decoded/decrypted/KDF/password buffers on all paths; immutableBigIntGC wipe is not claimed.

Missing phrase for recognized encryptedcontainer -> passphraseRequired/fieldpassphrase; empty/wrong phrase, invalid decryptedpadding/DER/privateproof -> passphraseInvalid/fieldpassphrase. Encrypted corruption cannot be distinguished from wrongphrase and has samecode. Malformedouterenvelope, unsupportedcipher/format/weakplaintextRSA -> unsupportedKey/fieldauthentication. Existing cancellation/deadline/resource mappings apply; native details never become UI/log messages.

Import persists ORIGINAL private-file bytes under existing DPAPI purpose and canonical publicKeyBytes from validated worker output; no passphrase persistence or sourcefile mutation. Public metadata≤262144bytes, canonical fullSSHblob with supported type/strength and existingtype/bits match. Required public metadata cannot be replaced by file inference or a second private parse outside the worker. Canonical public metadata is REQUIRED for every private-key credential. Missing/invalid metadata fails closed; no record-version fallback or inference is permitted. Sign worker compares parsedpublicbytes to frozenexpectedpublicbytes BEFORE signing; mismatch no signature/no authwrite. Original fences/hostverification precede private parse/sign. RSA SHA256/512 policies003 unchanged.

Текущий Credential.publicKeyBytes nullable только для password. Каждый privateKey credential MUST содержать канонические публичные bytes, type и bits. Все constructor/API вызываются по текущему контракту; parsePrivateKey — единственная функция разбора. Нет parseOpenSshKey alias, optional-hint API shims, старых схем, fallback или backfill. Исходный файл остаётся под DPAPI; пользовательские PEM/OpenSSH — текущие входные форматы. UI: «Приватный ключ SSH», error hint OpenSSH Ed25519/RSA либо RSA PEM≥2048 и файл≤1MiB. ПринципVI конституции применяется до приложения1.0.

Текущие сигнатуры: KeyInspection требует publicKeyBytes; readPublicKeyHint(file, publicKeyBytes: required) проверяет suppliedmetadata, не выводит её при отсутствии. PrivateKeyCredential и OwnedPrivateIdentity требуют explicit PublicKeyHint. ConnectionOwner отклоняет privateKey безmetadata до передачи credentials/signing. Чтение публичных полей профиля и обычная явная замена credentials не выполняют inference/backfill; автоматического восстановления некорректной записи нет.
