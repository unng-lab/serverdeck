# Feature Specification: Журналы сервера

**Feature Branch**: текущая рабочая ветка (отдельная ветка не создаётся)
**Created**: 2026-11-04
**Status**: Implemented — unit/fake/static validated
**Input**: Пользователь хочет видеть журналы выбранного сервера по systemd-сервисам и из файлов в разных местах, хранить последний час. Пройти полный цикл Spec Kit.

## Clarifications

### Session 2026-11-04

- Q: Как хранить последний час журналов? → A: Локально между запусками, сбор пока приложение работает.
- Q: Как добавлять файловые журналы из разных мест? → A: Вручную задавать абсолютные пути для каждого сервера; systemd обнаруживать автоматически.

## User Scenarios & Testing

### User Story 1 — Журналы сервисов (Priority: P1)

Пользователь открывает «Журналы» выбранного сервера, видит доступные systemd-сервисы, выбирает источник и включает его сбор. Время, сервис, важность (если известна) и текст помогают найти причину ошибки.

**Why this priority**: Основной запрос — диагностика сервера по его службам.
**Independent Test**: Подставной источник возвращает службы и записи; functional widget/unit проверяют выбор, содержимое и действия.

**Acceptance Scenarios**:

1. **Given** подключённый доверенный сервер A, **When** открыть журналы и обновить источники, **Then** показаны реальные доступные сервисы A без запуска/остановки служб.
2. **Given** включённый источник, **When** приходят новые записи, **Then** они появляются с временем и происхождением; повторное чтение не дублирует запись.
3. **Given** выбран A, **When** выбрать B при незавершённом чтении A, **Then** записи A не появляются у B.
4. **Given** отсутствие systemd или прав, **When** чтение не удалось, **Then** показано различимое состояние недоступности; файловые источники продолжают работать.

### User Story 2 — Файлы в разных расположениях (Priority: P2)

Пользователь добавляет именованный файловый источник по абсолютному пути на сервере, независимо от стандартного каталога логов. Он может отключить сбор или удалить источник.

**Why this priority**: Сервисы могут писать в собственные файлы вместо journal.
**Independent Test**: Подставные файловые ответы проверяют validation пути, строки, ротацию, отказы и продолжение.

**Acceptance Scenarios**:

1. **Given** файл `/opt/app/logs/service.log`, **When** добавить источник, **Then** сохраняются имя и путь только для выбранного сервера; история до подключения явно не обещается.
2. **Given** файл перемещён/обрезан/заменён, **When** следующий сбор, **Then** источник продолжает с явным предупреждением возможного пропуска, без выдачи старого содержимого за новые события.
3. **Given** неверный путь/каталог/нет доступа, **When** добавить или читать, **Then** видна ошибка конкретного источника без sudo и изменения прав на сервере.

### User Story 3 — Последние записи и восстановление (Priority: P2)

Записи сохраняются на этом компьютере: последний час и последние 200 записей каждого источника независимо от возраста, в пределах ресурсных caps. Потеря связи не превращает старые данные в актуальный поток.

**Why this priority**: Диагностика должна переживать временное отключение и перезапуск.
**Independent Test**: Fake clock/store/connection моделируют expiry, рестарт, пределы и поздние callbacks.

**Acceptance Scenarios**:

1. **Given** сохранённые записи, **When** перезапуск через 20 минут, **Then** последний час и хвост до 200 записей доступны без автоматического SSH; более старые записи вне хвоста не возвращаются.
2. **Given** нет связи/приложение завершено, **When** события возникают на сервере, **Then** непрерывность не обещается; после reconnect возможный пропуск обозначен.
3. **Given** поток превышает ресурсные пределы, **When** достигается лимит, **Then** сбор остаётся ограниченным, старые записи удаляются первыми, неполнота явно показана.

### Edge Cases

- Нет выбранного профиля, удаление источника/профиля, смена endpoint или host key во время чтения.
- Пустой journal, остановленный сервис, vacuum journal, одинаковые тексты и времена разных событий.
- Часы сервера отличаются от локальных; файловая строка без даты, неполный UTF-8, очень длинная строка, управляющие символы.
- Ротация/усечение/исчезновение файла, символические ссылки, двоичные данные, повторный путь.
- Ошибка локального хранения, выход во время чтения/записи, приостановка и возобновление сбора.

## Requirements

### Functional Requirements

- **FR-501**: Вкладка «Журналы» MUST принадлежать выбранному profileId; показывать источники, записи, состояние сбора и действия без демоданных. Общие C02/C03/C04/C06/C07/C08/C10/C11/C12/C13/C14/C20/C28 применяются по [каталогу 001](../001-design-system/component-library.md).
- **FR-502**: MUST обнаруживать systemd system services по явному обновлению и читать выбранные пользователем источники journal. Не включать автоматически все службы. Список ограничен 500 службами, неполный результат обозначен.
- **FR-503**: MUST позволять добавить файловый источник по абсолютному пути Linux, переименовать, включить/выключить, удалить. Максимум 16 настроенных источников на профиль и отдельно 1024 глобально (включая выключенные); добавление сверх любого предела атомарно отклоняется с понятным сообщением, ввод сохраняется. Предел профилей003 не меняется. Имя 1–80 символов, путь 1–1024 UTF-8 bytes; повтор kind+target отклоняется. Обход файловой системы и поиск всех логов вне scope.
- **FR-504**: Все remote операции MUST быть только чтением через существующий доверенный SSH-сеанс и его текущие fences; не запрашивать sudo, не устанавливать агент, не подключаться от открытия вкладки и не раскрывать командный API в MCP. Нет нового разрешения читать логи для MCP.
- **FR-505**: Сбор включённого источника MUST работать, пока приложение работает и сеанс готов, включая трей и смену вкладки. При запуске сбор ждёт разрешённого существующей политикой подключения; новая функция сама не подключает. Отключение источника останавливает его чтение, оставляет записи согласно FR-506 и FR-510.
- **FR-506**: MUST хранить локально между запусками объединение последнего часа по времени получения и последних 200 записей каждого источника независимо от возраста. Сортировка: receivedAt убывает, затем id убывает. Пределы FR-510 имеют приоритет, поэтому 200 — максимум хвоста, не гарантия при превышении caps. Одинаково для journal/file, disabled/offline и restart. Удалять просроченные записи только вне хвоста; startup/tick и reactive deadline очищают их до выдачи. Исходное время сервера не управляет retention; TTL незавершённого файлового prefix остаётся 60 минут.
- **FR-507**: Journal MUST запрашивать последние доступные 200 записей сервера без временного фильтра при первом чтении, новой SSH-сессии (включая restart/reconnect/re-enable) и восстановлении после ошибки cursor. Далее читать после cursor с лимитом 200; metadata recovery остаётся 1 запись. Dedupe и caps сохраняются. Файл MUST начинать с текущего конца и собирать новые завершённые строки, без backfill. Видна отметка «время получения». Недоступная предыстория и пропуски MUST быть явно обозначены.
- **FR-508**: MUST предотвращать дубликаты при повторах по identity события, сохранять checkpoint вместе с batch и корректно возобновлять чтение после ротации/потери курсора. Разные события с одинаковым текстом не объединяются.
- **FR-509**: MUST различать loading, empty, disconnected, paused, unavailable, permission denied, storage error и partial/limit; ошибка одного источника не блокирует остальные. Повтор чтения доступен явно, автоматические попытки не чаще 5 секунд без накопления параллельных чтений одного источника.
- **FR-510**: MUST ограничивать хранение 10 000 записями и 8 MiB текста на профиль, 50 000 и 32 MiB глобально; удалять самые старые первыми и показывать неполноту. Одна запись ≤16 KiB UTF-8 с явной пометкой усечения. План определяет bounded remote reads и честную сигнализацию потерь.
- **FR-511**: MUST показывать текст как неисполняемые данные, обезвреживать управляющие последовательности; локальные логи диагностики не содержат remote payload, путей или credentials. Записи доступны локальному пользователю приложения в том же защищённом каталоге Isar, не отправляются третьим лицам. Произвольные секреты в содержимом пользовательского лога автоматически не распознаются и не маскируются.
- **FR-512**: Удаление источника MUST удалить его записи/checkpoint; удаление профиля — все его настройки и записи. Изменение endpoint/auth connection revision MUST отменять старые чтения и очищать старые записи/checkpoints до сбора нового endpoint. Конфигурация источников (sourceId,kind,target,name,enabled) MUST сохраняться, её connectionRevision обновляется атомарно с профилем; payload сбрасывается к пустой истории и checkpoint с partial=true. После разрешённого подключения enabled источники продолжают обычный initial сбор по FR-507 (journal tail200 без временного фильтра, file EOF), без авто-connect. Rename профиля данные не сбрасывает. Отзыв доверия останавливает чтение, исторические данные остаются по FR-506/FR-510 (последний час плюс хвост200 с приоритетом caps) с явным offline-состоянием.
- **FR-513**: MUST использовать общий runtime/store, штатно отменять чтения и дожидаться записей при выходе. Нет старых схем/миграций/backfill. Новые форматы текущего приложения обновляются напрямую, без удаления несвязанных пользовательских данных.
- **FR-514**: Приёмка MUST проверяться только unit и functional widget fakes: содержимое, состояния, validation, права, повторы, recovery; без integration/e2e, реального Isar в unit, дизайна feature-экранов, captures или VM.

### Key Entities

- **Источник журнала**: профиль, connection revision, kind journal/file, target (unit/path), отображаемое имя, enabled.
- **Запись журнала**: источник, уникальная event identity, время получения, исходное время при наличии, важность при наличии, текст, усечение.
- **Checkpoint**: позиция источника, поколение файла/journal, состояние полноты; обновляется атомарно с записью batch.
- **Состояние сбора**: активность, ошибка, последнее успешное чтение, причина неполноты без remote payload в diagnostics.

## Success Criteria

### Measurable Outcomes

- **SC-501**: В синтетических сценариях 100% записей и действий относятся только к выбранному серверу и источнику; 0 действий запуска/остановки служб и 0 неавторизованных remote reads.
- **SC-502**: На одном исправном источнике при свободном канале новые завершённые записи становятся доступны не позднее 15 секунд при ответе источника ≤5 секунд и доступных лимитах. Несколько источников обслуживаются по очереди; ожидание канала показано явно, более длинное ожидание не выдаётся за актуальный поток.
- **SC-503**: После запуска и во время работы записи возрастом ≥60 минут видны только в последних 200 на источник; тихий сервис с событиями старше часа возвращает доступный tail200 без временного фильтра; настроенные пределы хранения не превышаются после batch commit.
- **SC-504**: Повтор одного batch создаёт 0 дубликатов; 100% сценариев лимита, ротации, недоступной предыстории и reconnect показывают неполноту, когда её нельзя исключить.
- **SC-505**: Потеря связи и отказ прав одного источника не стирают доступную историю других источников и не останавливают их сбор.

## Assumptions

- Базовая платформа и доверие — [002](../002-desktop-runtime/spec.md) и [003](../003-ssh-mcp/spec.md), мониторинг [004](../004-server-monitoring/spec.md) работает независимо. Этот пакет заменяет заглушку только вкладки «Журналы» из003, ПО/Задания остаются вне scope.
- Linux systemd system services; user units, контейнерные API, Windows Event Log, архивы/compressed/binary файлы, remote writes, экспорт, полнотекстовый поиск по сообщениям, серверный/индексированный поиск и alert rules вне scope. Файлы — UTF-8 plain text. Фильтр названий сервисов/источников определён FR-515.
- Ручные абсолютные пути подтверждены пользователем; systemd-сервисы обнаруживаются автоматически по явному обновлению списка.
- Последний час и хвост 200 — ограниченная локальная история, не обещание полной истории сервера. Ресурсные caps имеют приоритет с явной отметкой потерь.
- Файловые пути настраиваются вручную согласно ответу пользователя. В journal успешный поиск сохранённого cursor тоже не доказывает непрерывности: выдача обозначает ограниченную историю с возможными пропусками. При ошибке cursor чтение восстанавливается по контракту без бесконечного повтора неработающей позиции.

## Поиск сервиса/источника — уточнение пользователя 2026-11-04

Предыдущая трактовка поиска по тексту логов отменена пользователем: нужен поиск systemd-сервиса в «Журналах».

- **FR-515**: C05 поле «Поиск сервиса или источника» доступно над списками без выбора источника. Буквальная подстрока без учёта регистра (включая кириллицу) фильтрует обнаруженные systemd unit names и настроенные источники по name/target; таким образом можно найти сервис по unit-имени или локальному названию, файловый источник — по названию/пути. Крайние пробелы игнорируются, пустой запрос/очистка возвращают все строки. Нулевые совпадения отличаются от ещё пустого списка. Query сохраняется при обновлении списка и выборе источника в том же сервере; смена profile/connectionRevision/owner очищает его. Поиск только сужает списки выбора: не меняет выбранный sourceId, выдачу/пагинацию сообщений, сбор, настройки или историю. Никакого поиска в содержимом логов, SSH/MCP передачи или сохранения query.
- **AC-515**: Functional fake tests проверяют unit/name/кириллицу/регистр/пробелы, буквальные символы, clear/no-results/empty, обновление discovery, сохранение query при выборе источника, context reset и отсутствие фильтрации/сброса pagination сообщений. Общие C05 не изменяются; без layout/integration gates.

### Уточнение 2026-11-10

Пользователь запросил последние примерно 200 строк вместо пустого журнала тихого сервиса. FR-506/507 и SC-503 выше заменяют прежнее строгое часовое окно. Уже удалённые локальные строки не восстанавливаются с диска; новый journal-сеанс повторно читает доступный серверный хвост. Файловый backfill не добавляется.
