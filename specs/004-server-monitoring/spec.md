# Feature Specification: 004 — Базовый мониторинг серверов

**Feature**: `004-server-monitoring`
**Created**: 2026-11-04
**Status**: Требования, план и задачи согласованы; реализация и результаты проверки — [implementation review](reviews/implementation.md).
**Input**: На экране «Серверы» показывать текущую нагрузку в реальном времени и
подсвечивать превышенные пороги красным.

## Clarifications

### Session 2026-11-04

- Пользователь подтвердил CPU, занятую RAM и заполнение корневого диска,
  обновление каждые 5 секунд и пороги 90%.
- Пользователь выбрал автоматическое подключение ко всем сохранённым серверам.
- Q: Историю последнего часа хранить только в запуске или после перезапуска? → A: Сохранять после перезапуска (US4, FR-424).

## User Scenarios & Testing

### User Story 1 — Видеть текущие нагрузки всех серверов (Priority: P1)

Пользователь открывает «Серверы» и видит CPU, RAM и диск у каждого сохранённого
сервера без выбора отдельного сервера и без ручного обновления.

**Why this priority**: Это основной результат функции — сравнивать состояние серверов.

**Independent Test**: Подставные подключения, источник измерений и часы позволяют
проверить автоматический запуск, значения и обновления нескольких серверов.

**Acceptance Scenarios**:

1. **AC-401 Given** сохранены три профиля, **When** экран впервые открыт в текущем
   запуске приложения, **Then** автоматически запрашивается подключение каждого
   профиля; уже подключённые сеансы используются повторно.
2. **AC-402 Given** соединение установлено и данные доступны, **When** получены
   измерения, **Then** у соответствующего сервера отображаются CPU, RAM, диск `/`
   в процентах и статус актуальности; без времени обновления/возраста по [уточнению представления](contracts/monitoring.md).
3. **AC-403 Given** мониторинг работает, **When** приходит следующее измерение,
   **Then** значения обновляются без действий пользователя; поиск, выбор сервера
   и изменение профилей продолжают работать.
4. **AC-404 Given** список пуст, **When** открыт экран, **Then** сохраняется
   предложение добавить SSH-профиль и никакие подключения не запускаются.

### User Story 2 — Замечать превышенные пороги (Priority: P1)

Пользователь сразу видит, какая именно нагрузка превысила допустимый уровень.

**Why this priority**: Значения должны помогать обнаружить проблему.

**Independent Test**: Передать значения ниже, на границе и выше порога;
проверить severity, текст и изменение состояния без проверки цветов или геометрии.

**Acceptance Scenarios**:

1. **AC-405 Given** порог CPU 90%, **When** актуальная CPU равна 90% или больше,
   **Then** показатель получает критический статус, красную индикацию штатной
   error-роли и текст «Порог достигнут: CPU ≥ 90%»; сервер отмечен как требующий внимания.
2. **AC-406 Given** CPU критична, RAM и диск нормальны, **When** отображена строка,
   **Then** понятно, что превышен именно CPU; нормальные показатели не получают
   критический статус. Аналогичное правило действует отдельно для RAM и диска.
3. **AC-407 Given** показатель был критичным, **When** следующее актуальное
   значение ниже 90%, **Then** его критический статус снимается немедленно.

### User Story 3 — Различать перегрузку и отсутствие данных (Priority: P2)

Пользователь понимает, когда сервер недоступен, не поддерживается или ожидает
подтверждения, и не принимает последнее сохранённое значение за текущее.

**Why this priority**: Отсутствие измерений не означает нулевую нагрузку.

**Independent Test**: На подставных часах и источниках проверить таймаут,
частичный результат, отключение, подтверждение доверия и восстановление.

**Acceptance Scenarios**:

1. **AC-408 Given** сервер ещё не присылал данные, **When** идёт подключение или
   первый сбор, **Then** показано ожидание и «Нет данных», а не нули.
2. **AC-409 Given** есть последние значения, **When** их возраст достиг 15 секунд
   или соединение потеряно, **Then** они помечены «Устарело» без показа времени обновления;
   их прежнее превышение не выдаётся за текущую перегрузку.
3. **AC-410 Given** один источник недоступен, **When** прочие метрики получены,
   **Then** они обновляются, недоступная метрика имеет причину и статус «Нет данных»,
   а сервер — признак частичных данных.
4. **AC-411 Given** неизвестный/изменившийся ключ или зашифрованный ключ входа,
   **When** автоподключение требует решения, **Then** показаны штатные действия
   из 003; сбор невозможен до успешной авторизации и проверки доверия.
5. **AC-412 Given** пользователь отключил сервер, **When** проходят циклы сбора
   или экран открыт повторно, **Then** автоматического подключения нет;
   явное «Подключиться» возобновляет мониторинг после успешного подключения.
6. **AC-413 Given** источник измерений временно отказал при живом SSH-сеансе,
   **When** следующий сбор успешен, **Then** актуальные данные и severity
   восстанавливаются без ручного сброса ошибки.
7. **AC-414 Given** экран уже открывался, затем стал неактивным, а MCP создал
   новый профиль, **When** пользователь возвращается на экран, **Then** новый
   профиль автоматически добавляется в очередь; ранее отключённые вручную или
   завершившие попытку ошибкой профили повторно не подключаются.

### Edge Cases

- Значения 0%, ровно 90%, 100%; решение о пороге принимается до округления.
- Недоступна только RAM либо диск; повреждённые/отрицательные/нечисловые данные,
  нулевая ёмкость и сброс CPU-счётчиков не превращаются в 0% или 100%.
- Один медленный сервер не блокирует показ уже полученных данных другого.
- Удаление/редактирование профиля или закрытие сеанса во время сбора;
  результат старого сеанса не появляется в новом профиле/соединении.
- Перевод системных часов не меняет возраст измерений и период опроса.
- Поиск не прекращает сбор скрытых фильтром серверов и не меняет порядок списка.
- Нет прав читать метрики, не Linux или запрещены команды по SSH:
  понятная недоступность мониторинга без требования sudo/установки агента.

## Requirements

### Functional Requirements

- **FR-401**: Экран «Серверы» MUST показывать три показателя каждого профиля:
  CPU всей машины, занятую физическую RAM без swap и заполнение файловой системы `/`.
  Показатели относятся к среде ОС, видимой SSH-учётной записи (в том числе контейнеру),
  а не гарантированно к физическому хосту.
- **FR-402**: CPU MUST означать долю занятого процессорного времени по всем ядрам,
  нормированную в 0–100%; idle и iowait считаются незанятыми. Первое значение требует
  двух валидных отсчётов; сброс/неизменность общего счётчика означает отсутствие
  данных до следующей валидной пары. RAM = `(MemTotal − MemAvailable) / MemTotal × 100`;
  отсутствие MemAvailable не заменяется приблизительной оценкой.
  Диск = `used / (used + available для обычного пользователя) × 100` для `/`;
  reserved blocks исключены из знаменателя. Невалидный знаменатель означает «Нет данных».
- **FR-403**: Каждый показатель MUST иметь фиксированный порог 90%.
  Актуальное неокруглённое значение ≥90% критично; ниже — нормально.
  Настройка порогов, уровни warning и задержка/гистерезис в 004 не входят.
  Отображение — один десятичный знак; значение ниже порога, которое округлилось
  бы до 90,0%, показывается как «<90,0%», чтобы текст не противоречил статусу.
- **FR-404**: Превышенный показатель MUST получать error-семантику штатных компонентов
  (красная роль брендбука) и текст с названием и порогом. Сервер имеет сводный
  признак «Порог достигнут», если хотя бы одна актуальная метрика критична.
  При отсутствии актуальных превышений этот признак снимается; потеря данных
  отображается отдельно и не считается нормальной нагрузкой.
- **FR-405**: Первый сбор MUST начинаться после установления пригодного сеанса.
  Пока окно открыто на экране серверов, очередной цикл назначается каждые 5 секунд
  по монотонным часам. Для одного профиля одновременно выполняется не больше
  одного сбора; пропущенные циклы не накапливаются. При доступных источниках и
  отсутствии очереди первый полный набор появляется не позднее 10 секунд после
  подключения, следующие — не позднее 10 секунд после предыдущего.
- **FR-406**: Сбор MUST быть независимым по профилям, с максимум четырьмя
  одновременно выполняемыми сборами во всём приложении. Очередь содержит не более
  одного запроса на профиль и обслуживается по кругу без голодания; при перегрузке
  лимита обещание 10 секунд не действует, а актуальность определяется фактическим
  возрастом. Сбор ограничен 5 секундами после старта, без накопления вывода:
  не более 64 KiB суммарно на сбор. Таймаут/превышение размера отменяет сбор.
- **FR-407**: Актуальность MUST определяться отдельно для каждой метрики по
  локальному монотонному времени получения. Возраст ≥15 секунд — «Устарело»;
  при потере SSH или остановке мониторинга данные немедленно становятся неактуальными.
  Последнее значение сохраняется в памяти с отметкой возраста; невалидный новый
  ответ немедленно снимает актуальность этой метрики и показывает причину.
  Успешное новое значение заменяет её и повторно вычисляет порог.
- **FR-408**: Первое открытие экрана в запуске приложения MUST инициировать
  подключения всех сохранённых профилей; добавленный при активном экране профиль
  также включается автоматически. Уже живой сеанс используется без дублирования.
  При каждом возвращении экран сверяет очередь со всеми сохранёнными профилями
  и добавляет ещё не охваченные, включая созданные через MCP при неактивном экране;
  отметки завершённой попытки и ручной остановки из FR-409 сохраняются.
  Попытки подключения ограничены четырьмя одновременно и одной на профиль;
  ожидание trust/passphrase занимает слот. Остальные ждут своей очереди.
  Поиск не влияет на этот набор. До открытия экрана новые подключения не создаются.
- **FR-409**: Мониторинг MUST использовать владельца SSH, credentials, trust и
  отмену из 003, без второго SSH-владельца и обхода проверки ключей. Автоматическая
  попытка не подтверждает ключ, не вводит passphrase и не меняет credentials.
  Ошибка подключения или потеря сеанса не вызывает повторных автоподключений в
  текущем запуске; повтор — штатной кнопкой «Подключиться». Ручное отключение/отмена
  также подавляет автостарт до явного подключения или нового запуска приложения.
- **FR-410**: При уходе с экрана или скрытии окна в трей MUST прекращаться новые
  сборы и автоподключения; выполняющиеся сборы отменяются, живые SSH-сеансы
  сохраняются согласно 002/003. Возврат возобновляет сбор живых сеансов, но не
  повторяет уже завершившиеся/отменённые попытки. Ещё не начатые попытки из очереди
  продолжаются. После перезапуска текущие измерения отсутствуют, часовая история восстанавливается по FR-424; после аварийного завершения
  автоматический старт подавлен до явного «Начать мониторинг» на экране, согласно
  запрету автоматического восстановления SSH из конституции.
- **FR-411**: Мониторинг MUST поддерживать Linux с доступными счётчиками CPU/RAM
  и статистикой файловой системы `/` для текущей учётной записи. Сбор только читает
  данные через авторизованный SSH; без root/sudo, установки агента, изменения
  конфигурации сервера или обязательного отдельного сервиса. Для иной ОС или
  отсутствующих возможностей показана причина и доступное действие; SSH-соединение
  само по себе не объявляется неисправным. Ошибки сбора при живом SSH повторяются
  в следующем цикле; постоянная неподдерживаемая ОС — только после нового подключения.
- **FR-412**: Результаты MUST связываться с profileId, ревизией подключения и
  сеансом; удаление, изменение endpoint/credentials, отзыв доверия, disconnect и
  выход отменяют сбор и отбрасывают поздние результаты. Переподключение начинает
  новый baseline CPU. Переименование не переносит метрики на другой профиль.
- **FR-413**: UI MUST различать ожидание подключения/решения, сбор, актуальные,
  частичные, устаревшие, недоступные данные и ручную остановку; иметь безопасную
  причину и следующий шаг. Ошибки мониторинга не скрывают SSH/trust-предупреждения.
  Время/возраст остаются внутренними данными свежести; в сводке и настройках не показываются. Во вкладке истории время доступно согласно FR-422. Возраст не зависит от часов ОС.
- **FR-414**: Текущая свежесть MUST оставаться в памяти текущего экземпляра;
  часовая история и графики входят в 004 согласно FR-422–426; уведомления вне экрана,
  внешняя отправка телеметрии и новые MCP-методы не входят. Секреты, сырой SSH-вывод и текст удалённых ошибок
  MUST NOT попадать в UI/логи; допускаются фиксированные безопасные причины.
  Данные сервера не исполняются как локальный код и не вставляются в команды.
- **FR-415**: UI MUST использовать компоненты [001](../001-design-system/component-library.md):
  C01 (темы/роли), C02 (действия), C07/C09 (сервер), C10/C11/C12 (состояния и ошибки),
  C21 (метрики; compact вариант001); сохранить C04 (поиск) и существующие действия
  003. Функциональная приёмка проверяет значения, severity, текст, callbacks и
  lifecycle на fake-зависимостях, а не цвет, положение, размеры или дизайн экрана.

### Key Entities

- **Набор мониторинга профиля**: profileId, ревизия/сеанс, lifecycle мониторинга,
  причина остановки/недоступности, три независимых показателя и сводный статус.
- **Измерение**: вид, процент без округления, время получения/возраст,
  актуальность, безопасная причина отсутствия, вычисленная severity.
- **Состояние автоподключения**: очередь профилей и отметки предпринятой попытки /
  ручной остановки в текущем запуске; не является новым сохранённым SSH-профилем.

## Success Criteria

### Measurable Outcomes

- **SC-401**: Для 1–4 подключённых поддерживаемых серверов без отказов источников
  пользователь получает первый полный набор за ≤10 секунд и обновления с
  интервалом ≤10 секунд, без ручного обновления (AC-401–404, FR-405–406).
- **SC-402**: Для всех трёх метрик 89,9% нормально, 90% и 100% критично;
  причина превышения читается текстом, восстановление снимает её при следующем
  актуальном значении (AC-405–407).
- **SC-403**: Ни одно значение возрастом ≥15 секунд и ни одно значение
  отключённого сервера не представляется текущим; отсутствие данных никогда
  не представляется нулевой нагрузкой (AC-408–410).
- **SC-404**: Все сохранённые профили включены в автоматическую очередь;
  неподтверждённое доверие не обходится, ручное отключение соблюдается,
  поздние ответы не меняют новый сеанс (AC-411–414, FR-408–412).

## Assumptions

- Первая версия мониторит Linux; Windows-серверы, сеть, I/O, swap, остальные
  файловые системы, процессы и службы не входят в этот пакет. Это исходное
  ограничение версии, а не вывод из приложенного скриншота.
- Скриншот показывает существующий экран и точку добавления данных, а не вводит
  новые требования к расположению/дизайну страницы.
- Пользовательское решение об автоподключении расширяет поведение 003 только
  в контексте запуска мониторинга 004; запрет обхода доверия и восстановления
  SSH после аварийного завершения сохраняется.
- Зависимости: [002 — runtime](../002-desktop-runtime/spec.md),
  [003 — SSH](../003-ssh-mcp/spec.md),
  [конституция](../../.specify/memory/constitution.md).
- Продуктовые требования дополнены [планом](plan.md),
  [контрактом](contracts/monitoring.md), [моделью](data-model.md),
  [задачами](tasks.md) и [проверками](quickstart.md).
  Готовность пакета к реализации подтверждается независимым ревью, а не статусом файла.
- Проверки только unit: fake SSH/source/clock, синтетические байты и функциональные
  widget tests. Не нужны реальные серверы, Isar, e2e, VM, запуски приложения и
  screen-layout/design acceptance. Unit-результаты не доказывают интеграцию на ОС.

## Часовая история — 2026-11-04

### User Story 4 — Видеть изменение нагрузки за час (Priority: P1)

Пользователь выбирает сервер и открывает отдельную вкладку «Мониторинг» рядом
с ПО, журналами, заданиями и настройками. Он видит графики CPU, RAM и диска `/`
за последний час, в том числе после перезапуска приложения.

- Уточнение пользователя: история сохраняется после перезапуска.
- **FR-422**: Вкладки сервера MUST включать «Мониторинг» между «Задания» и
  «Настройки», с иконкой и доступным именем. Вкладка показывает три серии C22
  за скользящий последний час, единицы %, диапазон 0–100 и текстовую альтернативу
  с временем и значениями. Пустая история явно обозначена; один замер допустим.
  Компактные текущие метрики остаются общей сводкой; графики находятся во вкладке.
- **FR-423**: История MUST сохранять результаты существующего 5-секундного сбора
  всех подключённых профилей при активной рабочей области, независимо от вкладки
  и выбранного сервера. Дополнительный SSH-сбор при открытии графиков запрещён.
  Хранятся не более 720 последних точек на профиль в интервале `(сейчас−1 час, сейчас]`.
  При меньшем числе точек показывается фактически накопленная история.
- **FR-424**: История MUST сохраняться локально после каждого завершённого сбора
  и восстанавливаться при следующем запуске; после подтверждения записи точка
  доступна следующему запуску. История не отправляется по MCP или во внешние сервисы.
  Точки старше часа удаляются при чтении, записи и активной периодической очистке;
  при закрытом приложении очистка выполняется при следующем открытии хранилища истории.
  Восстановленные точки не восстанавливают SSH, baseline CPU, свежесть или превышения.
- **FR-425**: Отказ метрики MUST давать пропуск только её серии, а не ноль или
  копию последнего значения. Смена SSH-сеанса, pause/resume и перезапуск создают
  разрыв; интервалы более 15 секунд также не соединяются. При disconnect история
  сохраняется до истечения часа. Переименование сохраняет историю; изменение
  endpoint/credentials/connectionRevision и удаление профиля очищают его историю.
  Поздние ответы не записываются после инвалидирования сеанса/профиля.
- **FR-426**: Ошибка чтения или записи истории MUST иметь безопасное сообщение
  и действие «Повторить сохранение истории», не мешая живым метрикам/SSH.
  Повреждённая история явно отклоняется без преобразования и без автоматического
  удаления. Ограничения истории и данные одного профиля не затрагивают другой.
  Часы ОС могут менять показанный часовой диапазон: будущие точки исключаются
  и удаляются при очистке; перевод назад разрывает линию, не меняет polling/freshness.

**Acceptance Scenarios**:

- **AC-419**: При выборе вкладки показана история только выбранного profileId;
  смена сервера не переносит чужие точки и не запускает дополнительный сбор.
- **AC-420**: На fake-часах после 65 минут в истории нет точек возрастом ≥60 минут,
  число точек ≤720; восстановление из fake-хранилища сохраняет неистёкшие точки,
  но до новых измерений текущие метрики неизвестны и crash gate остаётся действующим.
- **AC-421**: Частичный отказ, полная ошибка, смена сеанса, pause/resume и перезапуск
  дают пропуски/разрывы; reconnect сохраняет старую часть часа, rename сохраняет,
  смена connectionRevision и delete очищают; поздний результат отбрасывается.
- **AC-422**: Ошибки read/write/corrupt дают безопасную причину и retry, live метрики
  продолжаются; успешный повтор сохраняет актуальную ограниченную историю.
- **SC-407**: AC-419–422 покрываются unit и функциональными widget tests с fake
  clock/source/storage; C22 проверяется отдельно на синтетических входах в scope001.

### Key Entities истории

- Точка истории: время получения UTC, идентификатор сегмента сеанса/активации,
  три независимых nullable процента без округления.
- История профиля: profileId, connectionRevision, ограниченная последовательность
  точек и состояние загрузки/сохранения; не содержит endpoint, secrets или raw output.
