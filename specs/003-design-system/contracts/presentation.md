# Presentation Contract003 — версия1

Внутренний UI-контракт [пакета003](../spec.md). Не меняет Local API, protocol/schema versions, storage или полномочия001/021. Существующий owner остаётся единственным владельцем runtime effects; связи с кодом/35origins заданы в [плане](../plan.md).

## P01 — Tokens, assets, component states

- Исходные три брендовых font assets сохраняются побайтно. Для отсутствующих glyphs используется bundled Noto Sans SC fallback поR12; одинаковая chain в явных typography roles, обеих темах и fixture loader. Текст≥4.5:1, focus/controls/graph≥3:1 к фактической соседней surface; проверяются использованные пары, включая selected/hover/disabled.

Disabled не opacity-only; error не удаляет focus/selection. Reduced motion отключает cyclic/progress animation, сохраняя статичный symbol+pending text; transitions используют существующий `Motion`.
- Stock row/popup focus fill использует readable `selected` surface, отдельный focus outline — роль `focus` с2px stroke/2px gap. Shared label wrapper не создаёт новый Tab stop и охватывает только заголовок, не expanded body. Closed dropdown сохраняет InputDecorator focus. Проверяются actual composited pixels и keyboard/disabled semantics; значения Theme properties сами по себе не доказательство контраста.
- Машинные значения журналов/версий/команд используют Noto Sans Mono13/20/400 (`BrandTypography.log`) по DESIGN/брендбуку. В MCP это и primary command/args, а не только дополнительный JSON. UI labels сохраняют свою caption/body роль; default human values DeckKeyValue не переводятся в Mono. Selectable/wrapping/copy и точные значения сохраняются.

## P03 — Phone navigation

Пять видимых полных labels в растущем `Wrap`; нет fixed panel height, maxLines, ellipsis, FittedBox или textScale suppression. Item: icon20, vertical gap4, caption12/16 с текущим TextScaler, horizontal padding4/side, vertical8, min44×44. Panel padding horizontal4/vertical8, spacing/runSpacing4.

Item width=`max(44,ceil(max(normalLabelWidth,selectedLabelWidth))+8)`, не шире доступной панели. Width измеряет `TextPainter` с актуальными locale/direction/font/TextScaler; учитываются обе styles, чтобы selection не перестраивал ряды. Если label шире панели, ему отводится вся ширина и разрешается перенос. Items переносятся целиком в исходном порядке; высота равна фактическим рядам. Контрольная200% композиция на360/390 допускает несколько рядов и сохраняет весь текст.

Panel занимает место в `Scaffold.bottomNavigationBar`/`SafeArea`, не overlay. Body имеет остаток высоты и vertical scroll; основные actions доступны. При keyboard inset>0 phone bottom navigation скрывается временно, section/draft не меняются; после закрытия клавиатуры возвращается. Focused field/actions формы прокручиваются в доступную область.

## P04 — Forms, dialogs, keyboard

Forms/dialogs используют доступную высоту над insets и scroll; actions переносятся, targets≥44×44. Title/target/consequences объясняются обычным текстом. Field validation связана с полем, error не сбрасывает draft. Protocol IDs/JSON доступны в дополнительных selectable details; обязательный effect/target/scope/deadline не спрятан исключительно там.

Общий JSON editor сохраняет тот же TextEditingController и точный введённый текст до соответствующего owner result либо явного закрытия пользователем. Synchronous parse/type/context errors не dispatch; delayed semantic/service VALIDATION показывается у JSON-поля или связанным warning и не закрывает форму. Не вводятся новые server validators или ограничения: authoritative validation остаётся у existing owner.

Полные подписи полей и выбранных режимов видимы при200%, включая private-key/passphrase branch, пустой/focused/locked ввод. Перенос текста сохраняет связанное доступное имя, masking, прежние controllers/picker и readOnly/submit исключения; существующий секрет не считывается для показа подписи.

Tab/Shift+Tab следуют reading order, Enter/Space активируют focused control; Escape закрывает cancellable dialog без destructive effect. Existing multiline key input/submit exception сохраняется. Focus возвращается на launcher при обычном закрытии; при исчезнувшем launcher — на безопасный существующий control того же контекста. Theme/resize не закрывают modal и не повторяют callback. Readiness exceptionP10 имеет приоритет.

## P05 — Local, remote и quality — отдельные оси

Shell показывает local readiness и действующий profile metadata. Без real projection SSH state не утверждается: выбор профиля сам по себе не означает «подключён» или «не подключён». Real connection state показывается owner выбранного server; observation отдельно имеет source/observedAt/receivedAt/quality из payload. Если поле не предоставлено DTO, оно не выдумывается.

Locald failure выводит readiness; SSH offline при locald-ready оставляет локальные profiles/catalogs доступными. `available` описывает соединение, `success` — подтверждённую операцию. Unknown/missing/denied/unsupported/incomplete не zero и не successful empty. Stale имеет явную подпись/символ, сохраняет source/time; inherited stale flag имеет приоритет над old known label. Gaps/dropped/truncated отображаются словами с доступными фактическими counts, без фиктивной полноты.

## P06 — Status и следующее действие

| Фактическое состояние | UI/role/symbol | Разрешённый следующий шаг |
| --- | --- | --- |
| Loading/pending | Точный этап/running/arc; статичный при reduced motion | Ждать/предусмотренная отмена ожидания; не дубликат запроса |
| Successful empty | Явная пустота: что успешно получено и где нет записей | Existing create/filter/refresh по owner; не имитация данных |
| Validation/conflict | Причина у поля или warning/triangle, сохранённый draft | Исправить либо existing reread; не новый approval/retry payload |
| Denied/unsupported | Причина/ограничение+warning/triangle | Existing permissions/environment guidance; без активного фиктивного handler |
| Stale/incomplete/gaps | Метка качества/time/source+warning/triangle | Existing refresh/page/recovery; не success badge |
| SSH unavailable | «Подключение не установлено»/unavailable/cross | Existing connect/trust diagnosis; не «сервер остановлен» |
| Unknown write/job | «Исход не подтверждён»/unknown/question | Только owner status/reconcile/exact allowed retry |
| Confirmed success/error | Подтверждённый результат/success-check либо error-octagon | Existing readback/details/recovery |

Символ+точный text обязательны; color не единственный канал. Host-key change, storage protection failure и job unknown имеют разные причины/безопасные actions; generic retry не обход их условий. `TRUST_CHANGED` не изображается обычным revision conflict без объяснения доверия. Protection failure не предлагает plaintext/reset; host key не принимается автоматически.

## P07 — Lists, data и overflow

Profiles/software/current jobs наphone — одна читаемая колонка cards/sections; whole-page и server-list horizontal scroll запрещены. Длинные Unicode names/tags/messages/fingerprints/commands переносятся; screen text не масштабируется вниз. Raw tables/log content могут иметь самостоятельный scroll при сохранённом target/source/time context. Полный обрезанный text доступен keyboard/touch через existing details или перенос. Большие списки сохраняют текущие bounds/pagination; design не добавляет сбор/retention.

T100 уточняет существующий log-record context: при открытии modal caller захватывает matching authorized ProfileView (имя и адрес/порт), source и observedAt соответствующего logs result и отдельный record timestamp. Эти display props передаются в ServerLogRecordDialog вместе с записью, без дополнительного read или нового DTO. Если source отсутствует, виден текст «Источник не указан»; не подставлять demo/source другого result. Время записи и время наблюдения имеют две различимые подписи с UTC; timestamp не подменяет observedAt. Контекст находится внутри modal, вне самостоятельной прокрутки message, доступен в semantics и при200% после обычной прокрутки внешнего layout; background не считается доступным контекстом. Resize/theme сохраняют snapshot и не вызывают effects; P10 retirement полностью скрывает dialog/target/source/record.

T102 определяет matching до открытия: readonly RAM projection `ServerLogRecordContext.capture(currentProfile, logs)` находится в server_sections.dart; это display value, не Local API DTO/cache/owner. Name/address текущего ProfileView включаются только если logs.serverId и logs.identity.profileId равны profile.id, а connectionRevision/credentialRevision/trustRevision точно совпадают. Metadata-only name/tag/revision update при тех же connection identities не запрещает отображение. Missing/invalid identity и любое несовпадение дают unresolved projection, без исключения в render и без подстановки текущего name/address. Показываются serverId самого logs result (либо «Цель записи не указана»), причина «Параметры цели записи не подтверждены текущими сведениями» и следующий шаг закрыть окно/получить журнал для текущих параметров. Source/observedAt/record остаются значениями исходного result; не объявлять неизвестный старый endpoint известным, не определять направление изменения по несовпадению. Никакого automatic read/retry/очистки owner/recreation или нового retained cache. Projection создаётся из того же build result, который передал records; dialog принимает её вместе с выбранной записью. Уже открытая projection не retarget при parent update; новый matching result применяется только к новому открытию. P10 и все прежние keyboard/copy/scroll gates сохраняются.

## P09 — Mutations, trust, plan/job lifecycle

Trust review10 получает existing ProfileView из ProfileList через ServerPanel. До подтверждения рядом с fingerprint видны адрес и порт (IPv6 в скобках), при наличии имя; UUID обозначается как диагностический ID профиля. Display target связан с challenge.profileId и expected/connection/credential/trust revisions. Несовпадение скрывает недостоверную пару target/key и блокирует confirm с понятным следующим шагом. Если current target/revisions/challenge изменились при открытом review, прежнее согласие не применяется: проверка выполняется и в самом production review component, и у owner после await. Cancel не принимает; автоматический probe/connect/retry и новые wire fields не вводятся.

Executor review40 получает тот же existing ProfileView и exact inspection. Name/address:port (IPv6 в скобках) показываются рядом с fingerprint только при совпадении serverId/profileId и connection/credential/trust revisions с enrollment ConnectionIdentity. UUID профиля/исполнителя остаются selectable diagnostics. Изменение/удаление target metadata, revisions или inspection необратимо отзывает прежнее согласие; возврат старых значений его не восстанавливает. Component проверяет актуальность при клике, owner наблюдает retirement во время await и повторно проверяет owner/profile/inspection перед существующим confirmExecutor. Окончательная native authority/expiry остаётся у service; новых wire fields нет.

Automation dialogs получают существующие authorized display metadata через presentation props от ProfileList/SoftwarePanel, без нового read/cache. Plan/preflight/approval/parameters/delegation сопоставляют name/address:port с фактическим serverId; grants показывают каждую serverIds target, а plan — matching automation profile name и exact version/digest. Нельзя подставлять выбранный в родителе профиль для другогоID. Unresolved/mismatched metadata явно обозначаются; технические IDs доступны дополнительно. При открытом согласии snapshot targets не retarget незаметно, смена/утрата действительного контекста не восстанавливает старое согласие. Existing owner guards/authority сохраняются.

Внешний вид не меняет существующие command payload/request identity/idempotency/revision checks. Pending блокирует повтор same action, не независимую shell navigation. Для unknown mutation доступны только реальные `checkResult/reconcile/retryPending` ветви owner и их условия; отсутствие receipt не доказывает lost outcome. Recent receipts остаются bounded20 и не заменяют job state.

Trust/executor confirm показывает действующую цель/fingerprint; cancel/close не принимает. Plan/approval/apply различаются; exact params/effects/checks/deadline видны до согласия; stale/expired не разрешает прежний apply. «Перестать ждать ответ» не названо безопасной остановкой job; safe cancel и effects/postchecks передаются из существующего job. Уход/resize/theme не отменяют физическое задание. Не меняются MFA/credentials/grant/delegation scopes или сроки; никаких новых API методов.

Automation presentation хранит максимум один результат retained write, полученный при завершении соответствующего borrowed owner callback. Последующая read error и active read phase показываются отдельно: FORBIDDEN/VALIDATION write→read TIMEOUT не означает unknown write; successful read не подтверждает прежнюю unknown write. Background notifications не присваивают результат записи. Dismiss/owner replacement/dispose/retirement pending очищают только этот UI context; request identity и authority остаются у owner. No-op/stale callbacks не присваивают чужую ошибку.

Ansible profile editor проверяет name/description существующим protocol automationText до dispatch: name1–100 Unicode codepoints, description0–2000, существующие NFC/control/multiline правила. Нет новой нормализации, schema или truncation ввода. Ошибки связаны с полями и полностью читаются при200% после reveal; если показан counter, его единица соответствует validator. Draft/controllers сохраняются до явного закрытия или успешного owner result; pending/repeated save не создаёт новый запрос. Поздний result после закрытия/retirement не обновляет disposed dialog.

При retained request внутри editor доступны существующие status/retry/dismiss: retry использует точный прежний owner request/payload, explicit dismiss сохраняет draft и не обещает отмену действия. Для definitive CAS recovery порядок явный: dismiss старого отклонённого запроса с сохранением draft → existing selectProfile read того же profile/workspace → показ exact current head revision/digest → отдельное принятие новой expected head → последующий save. Read proposal принимается только при согласованных profile/workspace/revision и неизменном current owner; archived/missing/failed read не даёт accept. Собственного TTL/новой lease нет: известное изменение context/head отзывает proposal, а неизвестное конкурентное изменение по-прежнему отклоняется existing atomic CAS владельца. Исходная версия и текст черновика не подменяются fresh body; различаются draft basis и accepted expected head. Unknown write/read success не разрешает автоматический новый save/rebase; нет auto read/retry. Context/model/profile/head проверяются перед accept/save и после await; old captured revision не читается из replacement model. Успешное чтение не закрывает editor как будто запись подтверждена; закрытие после записи требует успешного соответствующего owner result и отсутствия retained pending.

Generic JSON dialogs различают existing read phases version/compare и durable phases createPlan/saveGrant/replaceGrant/delegate. Operation kind задаётся вызывающим UI, не выводится из глобального pendingLabel. Во время собственного callback ввод/Continue заблокированы; при собственном retained durable request поля остаются читаемыми с opaque body/log roles, доступны только existing exact retry/dismiss. Dismiss сохраняет JSON и не отправляет новый изменённый payload; новый Continue — отдельное явное действие при действующих context/admission guards. Unrelated retained write не становится результатом или блокировкой read editor: успешный собственный read может закрыть свою форму, не подтверждая чужую запись.

Generic flow получает явное подтверждение admission своего callback от существующего presenter/синхронного owner busy seam и snapshot результата этого captured owner. No-op или отказ до admission не закрывает dialog и не присваивает ему прежнюю глобальную error/pending запись. UI не создаёт и не исследует mutation IDs; before-dispatch checks и фактическое выполнение команды остаются у owner. Synchronous type error внутри borrowed wrapper до owner dispatch учитывается отдельно от принятого service request.

Generic editor закрывается только после успешного собственного callback и current captured owner/client/private epoch/dialog; для durable operation дополнительно отсутствует её retained pending. Successful readback, изменивший DTO собственной успешно выполненной записи, не мешает безопасному закрытию этой формы; это не новое согласие. Known context change блокирует дальнейший dispatch, ready loss/owner replacement/close/disposal блокируют late updates. Unknown/read success не выдаётся за successful write. Controller-generated identity/payload/retry и все existing snapshot/context predicates сохраняются. Нового CAS/rebase UI для generic dialogs нет; профильный exact-head flow выше относится к Ansible profile editor.

## P10 — Readiness и приватность

UI visibility epoch в AppState наблюдает existing bootstrap readiness epoch, client connecting/disconnected/closed и snapshot error unauthorized. Каждый retirement меняет UI epoch даже при прежнем bootstrap.ready; весь private shell и modal удаляются, не меняя service state. Восстановление после retirement требует ready и current-generation snapshot, уже принятого существующим ProfileController; closed блокирует поздние snapshots до нового соединения/текущего авторизованного snapshot. Обычные polling snapshots/theme/resize epoch не меняют. Подписки снимаются при dispose; нового timer/request/retry/auth authority нет.

Private feature subtrees servers/settings/software keyed по этому UI epoch отдельно от public FoundationShell State. Поэтому loss и valid recovery в одном frame всё равно dispose прежние private descendants и их buffers; новый local snapshot не сохраняет прежний remote owner. Public section и ordinary theme/resize identity остаются стабильными; late callbacks прежнего owner по-прежнему блокируются его existing dispose/identity guards.

Ready loss/client closed/incompatible/authorization failure немедленно убирает private target/profile/remote data/secret input/consent, включая modal content. Можно закрыть private modal либо заменить весь private content/title на корректную readiness view; публичная оболочка не оставляет name/address в title/semantics/tooltip. Поздний Future/stream/picker completion не возвращает данные через retired epoch.

Нет keepalive private children за readiness panel. Новый ready даёт только current authorized snapshot через существующий lifecycle; secret и consent автоматически не восстанавливаются, connect/apply не выполняются. Store/trust/history не удаляются визуальным переходом. Ordinary resize retentionP02/P04 не отменяет эту защиту.

## P11 — Bounded capability adoption

35origins покрываются A01–A12 через текущие owners и shared themes. Сохраняются nested logs/jobs, recipe catalog и existing authoring/grants editors. Global Logs/Jobs говорят: общий список пока недоступен; существующие журнал/задания доступны в контексте сервера при действующем доступе/доверии и условиях owner. Действие «К серверам» только переключает local section, не читает сервер, не подключает и не подтверждает. Blanket «Выполнение заданий пока недоступно» не допускается: оно скрывает действующий nested jobs сценарий. Privacy gate сохраняется; доступ без полномочий не обещается.

Не добавляются отсутствующие fleet filters/aggregate state, pause/advanced logs, global job inventory, general software inventory или save-and-connect. Их примеры в атласе остаются visual references владельцев004/008/009 и других пакетов. В пяти разделах доступна честная причина ограничения/существующий следующий шаг; нет активной пустой кнопки.

Shared components не импортируют `docs/design/screens.json`, HTML renderer или demo assets/data. Synthetic fixtures доступны только test support/visual captures; обычный запуск получает реальные existing snapshots или честную пустоту/ошибку. Связь концепта с shared widget не означает готовность его runtime.
