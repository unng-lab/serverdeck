## Finding

**P2 — в диалогах согласия нет понятной идентичности целевого сервера.** Все16approval variants, например `19-plan-approval-1100x760-dark-100.png`, показывают только server UUID. Аналогично35parameters/37grantform/39delegations; approval также заменяет имя automation profile его UUID. При нескольких серверах или workspace grant выбранный в родителе профиль не обязательно является фактической целью. Закрытый диалогом контекст не позволяет сверить привычные name/address перед согласием.

Production цепочка подтверждена: [_PlanSummary](../../../lib/automation/automation_sections.dart) выводит serverId/profileId; [_decision](../../../lib/automation/automation_panel.dart) передаёт только plan; parameters/delegation — widget.serverId; grant preview — serverIds. Вызывающие [ProfileList](../../../lib/profiles/profile_list.dart) и [SoftwarePanel](../../../lib/software/software_panel.dart) уже располагают authorized ProfileView, но передают толькоID. Требуются существующие display metadata для точного target ID и каждой grant target, matching automation profile name; IDs остаются техническими сведениями. Не подставлять произвольный selected profile, не добавлять API/service возможности. Закрытие: T071, затем fresh captures/visual QA.

Других подтверждённых clipping/overlap в этом scope нет. Переносы при200% сохраняют содержимое; vertical scroll сам по себе не defect. В восьми MCPdetails началоJSON читается и видимая область существенно>80px, весьJSON одновременно не требуется.
