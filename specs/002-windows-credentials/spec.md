# Feature Specification: Защита доступов в Windows Credential Manager

**Created**: 2026-10-10
**Status**: Implemented
**Input**: Пароли, приватные SSH-ключи и passphrase хранить в Windows Credential Manager.

## User Scenarios & Testing

### User Story 1 — Сохранить и использовать доступ (Priority: P1)

Приложение сохраняет пароль либо приватный SSH-ключ с необязательной passphrase
в защищённом хранилище текущей учётной записи Windows. Доступ извлекается по
неприватной ссылке, когда он нужен для подключения.

**Independent Test**: сохранить синтетический пароль, прочитать новым экземпляром
адаптера, заменить его ключом с passphrase и проверить точное совпадение.

**Acceptance Scenarios**:

1. **AC-01**: сохранённый пароль возвращается без изменений новым экземпляром адаптера.
2. **AC-02**: SSH-ключ, Unicode и passphrase сохраняются без изменений.
3. **AC-03**: запись по той же ссылке заменяет предыдущий доступ.

### User Story 2 — Удалить доступ и безопасно обработать отказ (Priority: P1)

После удаления доступ отсутствует до следующей успешной записи по той же ссылке. Некорректные или неподдерживаемые запросы
дают ошибку, не сохраняют секрет открыто и не раскрывают его в диагностике.

**Independent Test**: проверить удаление, неизвестную ссылку, oversized запись,
некорректный сохранённый payload и безопасное текстовое представление секрета.

**Acceptance Scenarios**:

1. **AC-04**: неизвестная и удалённая ссылка возвращают отсутствие; повторное удаление допустимо.
2. **AC-05**: слишком большая запись отклоняется, предыдущий доступ сохраняется.
3. **AC-06**: некорректная ссылка или payload дают ошибку без секретного содержимого; password с String passphrase отклоняется, отсутствующая/null passphrase принимается; key сохраняет passphrase точно.
4. **AC-07**: текстовое представление credential не содержит пароль, ключ или passphrase.
5. **AC-08**: отказ CredRead, отличный от отсутствия записи, даёт явную ошибку, не null; диагностика содержит только операцию и системный код.
6. **AC-09**: отказ CredWrite при замене даёт ошибку; прежние kind/material/passphrase остаются доступными через независимое чтение, новый секрет не сохраняется открыто.
7. **AC-10**: отказ CredDelete даёт ошибку, не успешное завершение; credential остаётся доступным. Отсутствующая запись по-прежнему допустима.

AC-08..10 воспроизводятся контролируемым ERROR_ACCESS_DENIED на native call
boundary при наличии реального синтетического credential. Проверяется точное
фиксированное сообщение без material/passphrase, одна попытка API и отсутствие
автоматического retry или fallback в другой storage. После отказа независимый
native reader должен вернуть неизменённое содержимое.

### User Story 3 — Общая reference нескольких процессов (Priority: P2)

Несколько экземпляров или процессов могут применять изменения одной reference.
При конкуренции одно полное значение может заменить другое; delete не запрещает
последующий write. Требующий защиты от lost update caller организует порядок
изменений самостоятельно.

**Independent Test**: два Windows процесса готовят write/write либо write/delete
по общей синтетической reference; проверяются оба контролируемых порядка и
перекрывающиеся запросы.

**Acceptance Scenario AC-11**: завершённый write A, затем write B → целое B;
обратный порядок → целое A; write, затем delete → отсутствие; delete, затем ранее
подготовленный write → целое write. При overlapping write/write допустимо целое
A либо B; при overlapping write/delete — отсутствие либо целое write. Новых
изменений между завершением процессов и проверочным read нет.

Для AC-01..10 предусловие — отсутствие конкурирующих изменений reference.
Отказ операции не защищает от успешной записи другого процесса. Полные правила:
[contract](contracts/credentials.md).

### Edge Cases

Пустая/некорректная ссылка, отсутствующая запись, Unicode, неизвестный тип
credential, повреждённый JSON/UTF-8, превышение лимита и отказ системного API.

## Requirements

### Functional Requirements

- **FR-001**: пароли, приватные SSH-ключи и passphrase должны сохраняться только в Windows Credential Manager текущего пользователя.
- **FR-002**: чтение и замена по одной ссылке должны сохранять точное содержимое поддерживаемого доступа; password допускает только отсутствующую/null passphrase, key допускает String/null/отсутствующее поле.
- **FR-003**: удаление должно убирать текущую запись без запрета последующей записи по той же reference; отсутствие записи при чтении/удалении допустимо.
- **FR-004**: неправильная ссылка, неподдерживаемый размер/формат/платформа и системный отказ должны давать явную ошибку без открытого сохранения секрета.
- **FR-005**: диагностические сообщения и текстовое представление credential не должны содержать секреты.

- **FR-006**: адаптер должен допускать конкурентные callers одной reference по модели AC-11: без FIFO/CAS, с заменой полного payload и границами гарантий отказа/удаления.

### Key Entities

- **CredentialReference**: неприватная ссылка на доступ.
- **SshCredential**: пароль либо приватный ключ с необязательной passphrase.

## Success Criteria

- **SC-001**: все native roundtrip/overwrite/delete сценарии сохраняют точные значения либо подтверждают отсутствие записи.
- **SC-002**: все negative сценарии отклоняются без собственного изменения credential и раскрытия синтетического секрета; предыдущий доступ сохраняется при отсутствии конкурирующих изменений.

- **SC-003**: все сценарии AC-11 двух процессов завершаются с допустимым полным значением либо отсутствием, без смешивания полей двух payload.

## Assumptions

Windows x64, текущая Windows account; синтетические тестовые данные. Поддерживаемый
размер credential задаётся контрактом хранилища. Ссылки не содержат секретов.
