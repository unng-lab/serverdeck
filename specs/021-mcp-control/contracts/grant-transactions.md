## Internal boundary and request

T077 implements actual owner grant mutations in `packages/serverdeck_locald/lib/mcp/grants.dart`, with a private StateStore library part `storage/owner_grant_writes.dart` for native access. The common StateStore mutation tail owns serialization, stage/transaction/publication and shutdown. No second Isar owner, raw native handle export, caller-supplied digest, grant row or transaction callback is accepted. This internal service is called only by the verified owner Local API adapter in T006/T010; it has no enabled wire route until that gate exists. Its API name does not prove authentication, and its tests do not close that gate. MCP clients cannot call grant mutations. The adapter supplies the immutable verified owner role; never accept a JSON owner flag or caller originGrantId.

Strict request objects include requestId UUIDv4. Create is exactly `{requestId,grantId,label,scopes,serverIds,lifetimeSeconds?}`. Replace is exactly `{requestId,grantId,expectedRevision,label,scopes,serverIds,lifetimeSeconds?}` and is a full replacement. Revoke is exactly `{requestId,grantId,expectedRevision}`. No null optional values. grantId is the owner's chosen UUIDv4, label follows existing NFC1..100 rules, scopes/targets use strict GrantScopePolicy. lifetimeSeconds integer300..2592000/default28800; normalize omission to the default before digesting. expectedRevision uses int1..2147483647. Sort explicit target IDs for canonical request identity; scope order is the existing enum order. Reject duplicate IDs/scopes, unknown fields and invalid UTF8/types with VALIDATION. Snapshot request inputs synchronously before asynchronous work. Canonical request is `{operation,originGrantId:null,params:<normalized fields excluding requestId>}`. Compute its receipt-key HMAC with existing KeyCustody and encode32bytes as lowercase64hex for canonicalDigest; never accept an input hash.

The permanent receipt key is requestId in the automation receipt collection. A known receipt with foreign non-null origin is FORBIDDEN before disclosing result/conflict; an owner receipt with another operation/digest is IDEMPOTENCY_CONFLICT. A request ID already consumed by a foundation receipt is also IDEMPOTENCY_CONFLICT, never a second mutation; the future schema2 foundation coordinator must symmetrically consult automation receipts before activation. Existing foundation receipt shape/counters remain unchanged. Exact replay returns the persisted acknowledgement after reconciling the current grant binding, regardless of expired/revoked/replaced state. It never rechecks the old CAS, stages a key or rewrites history. Automation mutations do not advance foundation storeRevision: that counter and receipt chain remain exclusive to foundation profile/settings mutations.

## Admission and native commit

All accepted mutations, including replay, pass through StateStore's common serial tail. At most32 distinct pending owner grant request IDs, including the running one; exact concurrent duplicates share a future and consume no extra slot, changed input for the same pending ID conflicts. Queue saturation is RESOURCE_LIMIT. Admission after shutdown begins is NOT_READY; accepted work drains before native close/key/lease release. Future automation writers must use this same tail and pending request identity registry. No grant-specific independent writer queue may bypass it.

Inside the queue recheck live store/lease/key and current full snapshot. Replay precedes receipt/grant/file quota and CAS admission. New receipt at10000 and new grant at32 reject RESOURCE_LIMIT before staging. Existing grants, including revoked, count toward32; no deletion/eviction. Create with an existing grantId and replace/revoke with wrong expectedRevision or a terminal revoked grant fail REVISION_CONFLICT. Missing replace/revoke target is FORBIDDEN. Revision exhaustion is RESOURCE_LIMIT. Create/replace resolves every explicit target against current foundation profiles, including empty author-only operation; deleted historical identities cannot become new targets. Revoke preserves its retained policy and can revoke a grant whose old target was deleted. Expired nonrevoked grant replacement is permitted, no implicit renewal.

The service clock is read inside serialization, truncated to UTC milliseconds and floored by retained foundation/automation receipt timestamps and grant issuance/revoke timestamps. This prevents backwards revision time after clock rollback. The clock is an internal dependency, never a wire parameter. Create sets createdAt=issuedAt, revision1; replace preserves createdAt, increments revision, sets issuedAt and expiry from this explicit operation; revoke increments revision/sets revokedAt and preserves every other grant field. A fresh secretRef UUIDv4 and internally random DPAPI key are chosen only for admitted create/replace, never reused; staging is immutable and verified by the shared file layer. Revoke never stages a new blob.

OperationalSnapshot retains immutable exact native `{nativeId,entityId,payload}` lists for all ten collections, captured by the existing bounded native reader. They are internal storage data, not MCP output. Preserve every unchanged payload/native ID verbatim; do not serialize all existing DTOs back to JSON. Build candidate rows by replacing/adding exactly the grant row and adding exactly its stable receipt, with positive unique native IDs allocated as max retained nativeId+1 for a new row (int64 overflow→RESOURCE_LIMIT before staging). A replacement/revoke retains the grant's native ID. Run the full shared candidate graph validator before staging/native write, with exact expected receipt history and current foundation. Native transaction verifies the expected existing row/absence and receipt absence against the owned snapshot, then atomically puts grant and receipt. No collection clear/rewrite, physical marker change, foundation mutation, event allocation or server effect occurs.

Before entering the native transaction mark automation authority unavailable; all public operational snapshot/authentication reads must fail closed while commit/publication is in progress. This avoids a committed revoke/replacement being authorized through an older cached snapshot. Internal queued writer checks remain available. On a verified rollback restore previous readiness. On commit, replace cached retained state only with fully validated committed rows; never expose old authority. T006/T010 must consult current readiness/binding on every session authorization and delayed response and invalidate a stale epoch; a successful historical receipt is never fresh permission.

After commit run full T074 committed graph/current-blob/all-lookups preflight and reconcile DB-derived pointers before acknowledgement, then replace the public immutable snapshot and restore readiness. Exact replay also reconciles from the latest DB snapshot, never the secretRef/revision from its older acknowledgement. Any postcommit IO/verification failure returns safe STORAGE_BLOCKED, blocks subsequent automation mutations/bridge opens, retains ownership/data and exposes only an owner readiness status outside the guarded snapshot. Recovery requires a fresh fully validated open; no in-process second rotation/rollback/receipt reconstruction. Graceful close may confirm native closure and then let the caller release key/lease; an unconfirmed close preserves reservation until process exit.

Only pinned Isar native capacity failures may return RESOURCE_LIMIT after transaction entry, and only after actual full native reread proves the previous foundation/native rows and graph unchanged. The staged orphan remains inert. Unknown transaction errors or failed rollback proof set STORAGE_BLOCKED and preserve ownership until verified recovery. Precommit custody/IO failures also block safely without publishing a candidate. Domain validation/CAS/quotas do not poison a healthy store. All public errors are fixed codes without paths, secrets, provider/native exception text or submitted values.

Prove create/replace/revoke, full all-ten raw row/native ID preservation, restart and original stable acknowledgement replay after later replacement/revoke; verify bridge lookup uses current secretRef/revoked flag and old key cannot be restored. Rejected admission creates no blob, receipt or grant and leaves previous pointer unchanged.

T070 additionally requires actual native crash/IO/capacity proof at before/after stage, transaction grant/receipt writes, commit, pointer rename/readback and acknowledgement, including hard-killed children and restart/replay. A compile-time-only test probe may stop/throw at named boundaries but cannot change validated data, bypass a check, replace native transaction/DPAPI/space calls, or activate in normal builds. Actual Isar/DPAPI/reopen—not a fake transaction callback—provides acceptance. A retained real native reader may drive the64MiB map to capacity; injected capacity codes alone do not qualify rollback. Native core completion does not close owner image/role authentication, product1.1 activation, actual MCP clients or executor/VM gates.

### Inner lookup publication boundaries

T081 exercises create, replace and revoke at each actual lookup boundary: pending bytes have been protected-written/flushed/closed before rename (`afterPending`); native atomic rename has returned before readback (`afterRename`); bounded protected read has returned before content comparison (`afterReadback`). McpCredentialFiles owns this sequence with the existing protected write/promote/read primitives; it preserves the same random32hex pending filename, quotas, ACL/path gates, native flush/rename and exact comparison. No generic file writer hook or runtime configuration is introduced. Extend the existing compile-time-only SERVERDECK_TEST_MCP_FILE_PROBES instrument with a one-time enum-only async boundary handler; ordinary builds reject installation/hit and never call the hook. Handlers receive no paths, data, keys or bindings and cannot replace native calls or authorize a write.

For all three operations and all three boundaries, throw a private test error or hard-kill the owned child only after inspecting actual committed grant/receipt and publication state. During every hook operational authority must be unavailable. A pre-rename pending file must remain inert and preserve the prior lookup (or its absence on create); after rename the lookup must equal the committed binding/revocation. On thrown error assert safe STORAGE_BLOCKED, no later mutation/cached authority, retained committed metadata and sole-writer ownership. Fresh complete opening must reconcile from DB; original mutation replay must retain its acknowledgement, revision, current secretRef and file count, including a terminal revoke and old-create replay after replacement/revoke. Kill cases use a fresh ordinary-build recovery process and actual protected native data; no same-process fabricated recovery. Fixtures retain pending/orphan files and every native receipt. These tests do not close remaining auth/product/client/VM or physically filled-disk gates.
