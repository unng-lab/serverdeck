# Pinned Dart binding transaction cleanup

The schema2 foundation writer requires the same real native capacity/abort/readback guarantee as owner-grant writes. Both callback-time and commit-time `IsarError('The database is full.')` must return to the caller without native process termination, with no successful acknowledgement. After native abort settles, the repository rereads the complete previous foundation/automation graph before returning RESOURCE_LIMIT. Other uncertain native/readback failures block storage; they do not acknowledge success or retry a mutation.

## Required lifetime corrections

Root Flutter also selects this same local binding in its explicit pubspec override/lock, including the runtime pulled transitively by the pinned native-library package; locald's override resolves the generator's hosted-source constraint. This changes no DLL selection. Preserve the complete upstream web source, but exclude its unused legacy web backend from native Windows source analysis because the pinned SDK removed dart:indexed_db. Preserve upstream's generated native-bindings analysis exclusion. These analysis exclusions do not waive analysis of the changed native/common lifetime code and do not claim web compatibility.

In `lib/src/common/isar_common.dart`, both asynchronous and synchronous transaction wrappers abort a failed callback only while `txn.active` remains true. Native commit consumes the transaction even when its completion reports an error. A failed commit therefore must not cause a second finish/abort against the consumed pointer. Preserve the original error and the normal callback-failure abort path; do not convert a failed commit into success.

In `lib/src/native/txn.dart`, asynchronous commit and abort cancel and await the owned native reply-port subscription in a finally block around native finish plus its reply. Cleanup must run on both success and reported failure; a commit error must not keep an otherwise finished owned process alive through a leaked ReceivePort. Do not cancel before the actual finish reply or forcibly release a live native transaction. Synchronous transactions have no asynchronous reply port. All other upstream behavior remains unchanged except pinned-SDK source formatting and explicit local package metadata/provenance.

## Acceptance

An actual owned Windows child using the selected binding and actual native library opens the production-size 64MiB map, retains a real reader, and performs actual native writes until a commit-time capacity error. It must return the exact Isar capacity error, retain the original committed logical records, release the reader, complete a subsequent write/read, close native storage and physically exit zero within the existing child bound. No fake native exception, reduced map size or substituted transport/role qualifies. A separate native schema2 foundation case must prove RESOURCE_LIMIT only after full rollback readback, unchanged retained automation native IDs/payloads and no new durable receipt, then retry the same prepared candidate after the reader is released and reopen the committed result. The earlier unpatched crash and the intermediate ReceivePort-leak reproduction remain audit evidence.
