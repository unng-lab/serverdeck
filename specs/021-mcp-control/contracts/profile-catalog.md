## Components and authority

Implement `AutomationProfileService` in locald/automation/profiles.dart, an explicit schema2 profile writer in storage/automation_profile_writes.dart, `OperationalProfileOwnerApi` in api/owner_profiles.dart and a `ProfileCatalogMcpServices` adapter in mcp/profile_services.dart. Both adapters call the same service. The storage writer shares StateStore's existing serialization, automation pending IDs, 32 admitted grant/foundation/catalog interests, native collections and full retained graph loader. No new database, schema version, remote dependency or permissive fallback is introduced.

Construction requires one identical ready operational store, its custody/receipt key, the real native-gated OperationalSessions and its bound OperationalMcpAuthority. Trusted actor factories accept only an already proved owner request for its exact method, or an opaque OperationalMcpContext belonging to those identical registry/authority objects. The actor's origin is null for owner or the verified grant ID for MCP; neither adapter accepts role/origin/workspace/key/clock from wire parameters. MCP checks live author scope before input/object lookup and after every asynchronous read; owner checks exact method/registry/private initial-proof marker. Author scope is the shared workspace catalog and works with no server targets or executor. Missing profile/revision is FORBIDDEN.

`OperationalProfileOwnerApi` supports exactly automation.profiles.list/get/create/update/compare/validate/archive. Each method takes the corresponding public tool arguments from mcp.md and returns that tool's success data object (validation failure is its normal valid:false result). Mutations use the explicit body requestId, independently of the Local API envelope ID. Existing foundation profiles.* remain server connections and are never routed here. Owner preparation copies/validates input synchronously; its prepared invocation executes only after actual initial proof. Owner mutation and read publication retain the existing channel's final proof.

`ProfileCatalogMcpServices` supports only the seven profiles_* tools and refuses every other tool with UNSUPPORTED and no work. It never supplies a generic method proxy. It returns a McpServiceOperation whose cancellation drops response interest; a mutation already admitted under the native gate continues with its original durable requestId. It forwards fixed domain errors through McpToolResult and never exception text. This adapter alone is not the complete production McpToolServices composition or installed startup.

One runtime owner closes the shared service before closing its store/registry or externally owned custody/key. Service close stops new intake synchronously and shares one completion which observes outstanding proof/gate cleanup and drains actual admitted mutation callbacks; it never force-releases native work. Adapters do not independently close the shared store/key. Pure read interests may be retired on cancellation, but late native work is observed and remains bounded/accounted until physical completion.

## Mutation admission and history

Capture and normalize the complete command before the first await, including name/description/body. Use existing AutomationBody grammar, canonical digest and explicit parameter defaults; no YAML/Jinja/effects are executed. Create generates its profile UUID internally only for an admitted new command; that generated UUID is not part of the caller's canonical request digest. Update fills omitted name/description from the head inside serialization, never from a stale earlier read. Its canonical request distinguishes omitted fields from explicitly provided values; body is always complete. Missing create description defaults to the empty string.

Before storage admission acquire the same registry's runAuthorityMutation gate, revalidate the actual native actor within the original owner RPC budget or MCP operation budget (each individual proof/acquisition at most5s), then recheck author/current binding. No StateStore queue is held while waiting for the gate. A caller/session retirement before this admission cannot begin a late write. After admission, cancellation/disconnect does not cancel the physical effect or release its lease. Hold the actual lease through commit/rollback, complete readback and callback completion; physical release failure is SERVICE_UNAVAILABLE. Grant replacement/revoke cannot interleave inside this gate. Inside the serialized writer recheck store/lease/key and the admitted MCP grant's exact revision/current author policy at the writer's effective time; a historical receipt never supplies fresh authority. Once physically admitted, owner disconnection alone does not interrupt a write.

The MCP service starts one internal30s budget at start, matching the router operation lifetime; no wire timeout override. Individual gate/proof deadlines are min(5s, remaining budget). Owner uses its original request remaining5s. Check remaining time before actual storage admission; after physical admission a logical timeout only ends response interest and cannot release a live write.

Pending automation IDs carry their initiating nullable grant ID as well as digest. All grant/catalog writers check foreign pending origin before sharing/conflict disclosure. An exact same-origin pending command shares one result; changed operation/input conflicts. Foundation and automation IDs remain mutually exclusive at actual serialized admission. Durable receipt replay checks current actor authorization, then exact origin/operation/private canonical digest, before CAS/quota/body preparation. A foreign-origin receipt is FORBIDDEN, including null-owner versus MCP origin. Exact replay returns its original acknowledgement after later head changes/archive/restart, without generating a UUID or rewriting rows. The existing owner-grant pending path must preserve this origin isolation too.

For a fresh command, enforce permanent receipt10000, profile250 including archived, at most20 retained revisions per profile, bounded native IDs and integer revision exhaustion before any write. No history or receipt eviction. Update requires the exact expectedRevision at the current head and appends its successor with parentRevision=head. Metadata-only or byte-identical body changes still append a new revision; no previous delegation is transferred. Preserve unrelated rows/native IDs and every old revision exactly.

Create/update atomically write metadata, one immutable full body revision and stable receipt result {profileId,revision,digest}. Revision authorGrantId equals initiator; objectGrantId is null. Create is revision1/parent null. Update retains the profile's archived flag: it never silently unarchives. Archive checks current head CAS, sets archived true and writes {profileId,revision:<current head>,archived:true}; it appends no body revision and does not consume the20 revision quota. A new request to archive an already archived profile with the correct CAS persists the same stable acknowledgement under its new request ID. Updating an archived profile remains authoring only: it stays archived and cannot produce a new runnable plan. Existing historical plans/jobs and their bodies are never rewritten by any catalog operation; their admission rules remain the plan/job contracts.

Use service UTC millisecond time read inside serialization, floored by all retained foundation/automation receipt timestamps and revision.createdAt values. Receipt time equals the newly appended revision time. Native authority reads are unavailable during commit/publication. Persist the complete expected retained graph atomically, then use actual Isar/DPAPI loading to validate all ten collections and foundation state before publishing the new cache. On verified rollback restore the old readiness/cache; on uncertain commit/readback fail STORAGE_BLOCKED and keep sole-writer ownership until explicit complete reopen. No file/credential write is part of a profile mutation. Keep foundation storeRevision/settings/connection profiles and all other automation rows unchanged.

## Reads, pagination and pure validation

profiles_get defaults to head revision and returns {profile:<current metadata>,revision:<immutable revision record>}. Explicit revision returns that historical body/parent/digest/author with current metadata. Reads include archived objects when addressed explicitly; list hides archived by default. List items are metadata records without bodies, ordered by UUID string ascending, with {items,nextCursor?}. limit default50/range1..100; includeArchived defaultfalse. Filter/order/head changes invalidate a continuation; never mix snapshots or silently restart.

Read/compare processing captures one immutable catalog snapshot after native proof. Recheck current authorization and metadata snapshot after asynchronous processing before service completion; a changed snapshot is REVISION_CONFLICT (CURSOR_EXPIRED for a continuation). Retained historical revisions remain addressable. Reads do not promise that a subsequently mutated head remains the latest forever.

Cursor is a strict ASCII base64url payload plus base64url HMAC, total at most512 characters, no padding or alternate encodings. Domain-separate its HMAC using the existing private workspace receipt key and the constant profile-catalog-cursor-v1. Payload exact fields {v:1,w:<workspace UUID>,g:<grant UUID or null owner>,r:<grant revision or0 owner>,a:<includeArchived bool>,h:<SHA256 of canonical sorted complete metadata snapshot>,l:<last emitted UUID>,t:<issued UTC milliseconds>}. Recompute current snapshot digest; verify signature with constant-time comparison, role/grant/revision/filter/workspace, last ID membership and t<=now<t+300000 before paging. Malformed/foreign/expired/changed cursors return CURSOR_EXPIRED after live author/owner authorization. Cursor has no reusable access authority. No persisted cursor table or unbounded cache is introduced.

profiles_compare reads two retained bodies from one current snapshot and returns {changes,truncated}. changes is a deterministic structural JSON diff with objects visited by sorted keys and arrays by increasing index; each change is {op:add|remove|replace,path:<RFC6901 pointer>,before?:<typed JSON>,after?:<typed JSON>}. Add has only after, remove only before, replace both. No coercion or synthetic field/step text; parameter and step paths refer to their actual body JSON locations. Stop before the next change would exceed256KiB encoded result or2048 changes and set truncated true. Equal canonical bodies produce an empty list. Native proof/current author is checked again before result publication.

profiles_validate is pure local syntax/normalization, at most1s with the fixed body limits. Valid data is {valid:true,issues:[],digest,normalizedBody,normalizedEffects}; normalizedEffects is the validated normalized steps array, not expanded/qualified executor effects. Invalid syntax/schema is {valid:false,issues:[{field:"body",code:"VALIDATION"}]}; no arbitrary parser message/input echo. Timeout is fixed TIMEOUT. This endpoint neither resolves a remote registry/recipe nor promises apply feasibility; expanded effects/preflight remain plan/compiler work. No Ansible invocation, SSH connection or installation occurs during authoring/read/validation.

Outer argument/schema errors retain the existing protocol INVALID_PARAMS path before service start. valid:false applies to body validation failures that reach the service under the catalog's argument schema; owner input follows the same outer shape. Validation never supplies a bypass for create/update admission.

## Required evidence and integration boundary

Pure tests cover body normalization/digests/defaults, update omission semantics, exact receipts, cursor signature/identity/filter/order/TTL/snapshot boundaries, typed deterministic diff escaping/truncation, invalid validation and quotas. Native schema2/DPAPI tests cover owner and two distinct author grants, empty workspace, shared catalog reads, immutable parent/author chains, CAS races, foreign pending/receipt and foundation-ID isolation, current revocation/expiry before admission, durable replay after head/archive/restart, all ten retained collections/native IDs, 32 shared admission, lifetime quotas, native MapFull rollback and postcommit blocked recovery. Observe actual gate lifetime and disconnect/cancellation boundaries; no fake storage callback qualifies transactions.

Actual owner and MCP channel/router fixtures must exercise these seven tools through this same backend, denied read-only/no-author/foreign-native contexts, revoked delayed reads, same durable request IDs and retained mutation after response cancellation. Other tool services remain explicitly unavailable until implemented. Mandatory checks and independent review precede closure. This component does not activate startup, SSH, plans/jobs, executor/recipes/UI or the complete021 acceptance.
