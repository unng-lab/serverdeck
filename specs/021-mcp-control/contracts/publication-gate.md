# Native publication gate — 021 API1.1

[Gateway and mutation ordering](gateway.md), [channel](operational-channel.md), [tasks](../tasks.md).

## Component and identity

T113 implements OperationalPublicationGate/OperationalPublicationLease in packages/serverdeck_windows/lib/operational_publication_gate.dart, a part of pipe_worker.dart. The factory is OperationalPipePeer.publicationGate(generation). Only a private actual native peer can reach its worker's peerPublicationIdentity operation. That operation revalidates the exact epoch/self/peer and returns its retained owner SID, normalized lowercase Windows bundle root and native local role. No external lock name, root, SID or role parameter exists. generation is a canonical UUID supplied by trusted bootstrap composition: authenticated session hello on the bridge, the exact OperationalSessions generation on locald. It is never taken from tool parameters. The gate is synchronization only; it does not establish a session, grant, tool scope or permission to publish/mutate.

The factory reopens/validates the actual format2 bundle and retains its own real process identity and VerifiedBundlePeer proof. The role must match the worker-retained local role. Subsequent acquire checks revalidate this actual self-image/bundle proof; this gate can outlive the particular channel used to mint it, so it does not depend on that channel's later connection epoch. Publication still needs the gateway's fresh session/grant ping and final expiry/interest checks. Owner target/grant services still need their ordinary authority checks. Restoring changed manifest bytes never revives a gate whose proof already failed.

The mutex name uses the exact UTF8 transcript and digest in gateway.md. The root spelling is p.normalize(worker-verified bundle appRoot).toLowerCase() on Windows, identically in both processes. The companion poison event is the mutex name plus `.poison`. Names are private implementation state, never returned to an MCP client. Both objects require exact protected owner/SYSTEM-only ACLs; canonical allowed rights add EVENT_ALL_ACCESS (0x1f0003), retaining the closed existing file/mutex/pipe rights vocabulary. A handle alone is not mutex ownership.

## Acquire, actual ownership and limits

acquire(deadline: remainingBudget) returns an opaque lease. Default and maximum logical acquisition budget is5seconds; a larger duration is capped, nonpositive duration fails TIMEOUT without work. This budget includes self proof, native worker startup and contention. The existing MutexLease worker acquires/releases on one uninterrupted native stack; await boundaries never transfer Windows thread ownership. Contention uses bounded10ms backoff/remaining budget, not network/effect replay. A native attempt may finish after the logical timer; its future remains observed/charged, and any late acquired ownership is closed before capacity is reusable. No unsafe thread cancellation, forced unlock or unbounded retry queue.

At most16 acquisition/lease interests are admitted by one gate. Excess fails RESOURCE_LIMIT before starting another native attempt. activeAcquisitions/activeLeases expose immutable counts, not locks or authority. TIMEOUT retires only that acquisition interest. The actual acquisition and its native cleanup remain tracked until settled. A successful lease owns its mutex until its shared close completes. Lease close/done are the same actual completion; concurrent/reentrant release invokes the native close once. The gate itself never forces a live publication lease to release.

Gate close stops admission synchronously, retires pending acquisition results with SERVICE_UNAVAILABLE and waits for every actual attempt and held lease's real completion before closing retained identity/kernel handles. Concurrent calls share one completion, including failure. An active lease's owner must release it after actual publication/mutation completion as specified in gateway.md; closing the gate cannot substitute for stdout termination. Closed objects cannot acquire again. No native peer disconnect, pipe reader/writer, workspace owner mutex, Isar or remote operation is owned by this component.

## Abandonment and generation lifetime

Each gate retains an unowned mutex keeper handle in addition to the poison event handle. This preserves the kernel mutex object if its owning process dies; otherwise the last handle could disappear and erase abandoned state. WAIT_ABANDONED is never treated as ordinary successful acquire. The detecting gate first signals the shared manual-reset poison event and fails SERVICE_UNAVAILABLE, then releases its newly acquired native mutex safely. Identity failure and failed native ownership cleanup also poison the generation. MutexLease.acquire does not distinguish a safe startup failure from an error in startup-timeout native cleanup; any exception from that actual acquire worker therefore conservatively signals poison and retires this generation. A later restored ACL or restored bundle cannot silently enable it. Other gate objects/processes sharing this generation refuse acquire when the event is signaled. No component resets that event or silently retries poisoned authority.

Operational locald composition must create and retain its gate/keeper for the entire registry generation before admitting MCP publication or authority/target mutations, including while individual MCP channels close. It must close/retire the affected workspace/session interests on poison, keep readiness fail-closed, and recover with a new generation; it must not close every keeper and rebind the same poisoned generation. Bridge failure also retires its client/interests. These composition obligations remain T110, not an automatic side effect of adding this helper. A healthy individual gate can close while another gate remains active; that does not itself poison their generation. Native release, poison or handle cleanup failures are fixed SERVICE_UNAVAILABLE, never a success claim of safe reuse. Native proof failure uses fixed UNAUTHORIZED, resource/deadline failures use RESOURCE_LIMIT/TIMEOUT; no raw paths, errors, secrets or transcript diagnostics.

## Evidence boundary

Actual same-format2 PE/native bootstrap tests use the real gate, owner-only kernel objects and native MutexLease workers: cross-process contention/hand-off; actual default5s timeout and later reuse;16waiting/17th denial and1held+15waiting capacity; cancellation/close before a native acquire returns; close while a lease remains held; shared close/done completion; independent generation namespace; native pipe I/O while gate held; actual owner/MCP/locald self roles; process death and abandonment detection with a keeper; a second gate object refusing the poisoned generation; and permanent local retirement after manifest identity change. Exact owner/event ACL masks and extra grants are checked with real Windows descriptors. A test-only helper restricted to an owned temporary fixture namespace retains its mutex handle, temporarily removes the new worker's access via actual kernel DACL, then restores it; both existing gates must remain denied after the real native startup failure. This tests conservative acquire-error handling, not a fabricated callback exception or a claimed reproduction of ReleaseMutex failure.

This suite qualifies kernel synchronization/ownership only. It does not open schema2 storage or perform protected grant-open, stdout-to-mutator serialization, target-change fence, grant commit integration, executor/SSH effects or installed executable acceptance. T104/T109/T110/T112 retain those production obligations and readiness remains false until they pass. Adding a gate API does not complete any of those tasks.
