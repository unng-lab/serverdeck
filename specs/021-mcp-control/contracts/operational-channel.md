## Ownership and dispatch

`packages/serverdeck_locald/lib/api/operational_server.dart` owns ordinary Local API dispatch referencing the exact same OperationalSessions, OperationalMcpAuthority and McpRouter. Mismatched ownership is a configuration error. It never opens storage, selects bootstrap mode, mints sessions or starts SSH. Future owner endpoint adapters use these same services/durable coordinator after the native owner gate; missing functionality returns UNSUPPORTED and does not activate an incomplete product.

`lib/api/operational_channel.dart` owns one accepted private OperationalPipePeer and OperationalServerHandshake. Handshake and dispatcher share the exact registry; all I/O uses the handshake's retained native peer. No caller-selected role or raw read/write transport replaces this peer. The pipe-pool owns worker creation/acceptance and physical reuse; closing one channel never stops the workspace registry/router or disconnects a replacement connection.

Envelopes retain Local API v1 correlation: request v/id/sessionId/method/params, response v/id/generation and exactly one object result/error. id/generation are UUIDs, sessionId a canonical nonce, params an object; reject unknown fields. API1.1 is established by its separate bootstrap, never selected by an envelope. Strict malformed UTF8/duplicates/nonobject/invalid envelope closes without reflecting input; no legacy1.0 handshake fallback. Method-specific validation follows native role/session admission.

Central methods: readiness.get, session.ping, session.close, mcp.open, mcp.invoke, mcp.close. Ping/readiness/close require empty params. Ping returns leaseSeconds60; close returns closed:true and closes this session/channel. Readiness returns the separate OperationalReadiness DTO specified below with generation matching registry, preserving legacy ReadinessView unchanged. mcp.open uses existing current protected-grant/one-attempt rules; mcp.invoke uses existing router/strict DTOs. MCP role cannot invoke owner endpoints; owner cannot invoke mcp.*. Gate before method payload/object lookup. Owner adapters must enforce their endpoint readiness and the same native/session authority; an internal injected implementation cannot bypass this gate.

Unknown owner method returns UNSUPPORTED, unlisted MCP method FORBIDDEN. Readiness/ping never connect servers or install runtime. Operational storage unavailability denies protected open/invoke under existing rules. Public Local API errors use fixed existing ErrorCode/LocalError vocabulary/retry mapping without exception text/input/path. Tool-domain failures remain inside tool results. Invalid invocation union is Local API VALIDATION; catalog tool/argument errors keep done/protocolError -32602. Missing/expired/native-invalid session closes without data.

## Operational readiness

Implement a separate immutable closed DTO in `packages/serverdeck_protocol/lib/mcp/readiness.dart`, never change legacy API1.0 ReadinessView. Fields are exactly state/reason/product/apiMajor/apiMinor/workspaceSlot/workspaceId/generation/storageSchema/features/clientPlatform. Identity constants are serverdeck-next/1/1/default/2/windows-x64; storageSchema describes supported operational schema, not an untrusted incompatible disk's observed version. generation is registry UUID. workspaceId is UUID or null until known; ready requires the current validated workspace UUID. States are starting/recovering/ready/storage-blocked/incompatible/stopping/unavailable. reason is respectively NOT_READY/NOT_READY/null/STORAGE_BLOCKED/INCOMPATIBLE/SERVICE_UNAVAILABLE/SERVICE_UNAVAILABLE, with no other combination.

Features is a closed object containing boolean profiles/ssh/jobs/backend/mcp, all present on wire, constructor defaults false. All must be false outside ready. Within ready they describe actually configured service capabilities, not a particular target's runtime prerequisites: profiles means owner target-profile CRUD; ssh means shared state/log SSH adapter; jobs means durable job engine; backend means executor adapter; mcp means compatible executable/client/channel/router plus all24 tool service implementations wired. No feature defaults true. Central storage/session dispatch may be ready while unimplemented features remain false; this does not satisfy product activation. Current standalone channel fixture must advertise mcp=false, never imply the uninstalled executable/owner/services are complete. Actual product activation T008 requires the specification's complete installed component set independently of central ready. Runtime availability/permission for a selected target remains a separate plan/tool check. No new arbitrary feature registration.

The wire test verifies these constants against authenticated1.1 hello/format2 schema2 bundle, all defaults and state/reason combinations, generation/workspace consistency, unknown fields and false partial capabilities. Shared parsing/encoding remains bounded and immutable.

## Failed grant-open terminal response

An initial failed mcp.open still detaches its session eagerly before returning, preserving existing fail-closed semantics and cleanup hooks. To deliver its promised fixed error, the privately constructed OperationalSessionRequest may issue one sealed OperationalOpenFailure permit only for that same first attempted mcp.open with no successful bound grant. It records a fixed failure code from UNAUTHORIZED/STORAGE_BLOCKED/RESOURCE_LIMIT/TIMEOUT/INCOMPATIBLE; unexpected failures map to UNAUTHORIZED. Invalid grant/proof remains uniformly UNAUTHORIZED. This does not resurrect a session, grant or quota.

The permit has no public constructor, key/peer getter or arbitrary result/bytes method. Its only publication operation takes the correlated UUID request id and an outer remaining deadline and internally constructs exactly the ordinary Local API error envelope with recorded code/LocalError, registry generation and no field/data. It may write once through its original private epoch-bound native peer, within the original RPC5second budget, while registry is not stopping, original lease unexpired, original request not completed and no replacement session exists for that channel. Revalidate native identity before writing, then synchronously recheck these conditions; no await before issuing the fixed write. Mark the permit consumed before native write; failure cannot retry. It retains the already admitted request's pending interest until finally, never reserves a new slot or key operation.

On failure recognition the channel stops intake and drops every other queued publication except an already-issued write. Serialize only this terminal error after that issued write, bounded by the original remaining budget, then bounded drain/disconnect. If time/native/custody conditions no longer permit safe delivery, close without data; the client preserves its ordinary timeout/transport authentication failure. Never permit terminal output for second open after a bound grant, native failure, registry stop, replaced physical connection or grant-derived queued results after revoke/replacement/expiry. Those close without a special error publication. Role-denial errors before an open attempt still use the ordinary live-session guard. This is the sole exception to the ordinary error-publication live-session requirement below.

Native wire tests must prove exact STORAGE_BLOCKED/UNAUTHORIZED for safe initial store/proof failure, EOF without retry on second bound open/native failure or expired budget, no subsequent invocation/data output, one pending-interest release and retained late key-work accounting.

## Bounds and publication

Frames are uint32 little-endian length plus exact payload. Bootstrap max8KiB, request256KiB, response8MiB, JSON depth16. Operational responses preserve observed Unicode/scalar identity using the MCP-preserving encoder; no NFC-normalization. Empty/oversized frames close. Read chunks at most64KiB. Idle read is bounded by60second lease; after first byte one absolute5second partial-frame deadline applies. Bootstrap has one absolute5second budget including native verification/hello/authenticate/authenticated writes.

At most16 active RPCs/channel including replies waiting for the one serialized writer; stop frame intake at that bound. One partial frame is separately bounded256KiB. Session pending interest remains reserved through execution/encoding/writer wait/native validation/actual write and completes exactly once in finally. One RPC has an absolute5second budget beginning before native session admission; every stage uses remaining time, never a fresh budget. Timeout closes/retire response interest; durable operations and actual unfinished cleanup retain existing ownership/quota.

After waiting for previous writes, immediately before issuing a native write, revalidate native peer plus the same session/current grant under remaining RPC budget. Check the tuple synchronously again after that await, with no intervening await before issuing write. Revoked/replaced/expired queued results must not be written. Failure disconnects via existing eager router hooks and closes this channel, dropping queued buffers. Error responses also require live native/session authority, except the sealed initial failed-open terminal error above. A role-denied request may reserve an ordinary ping interest for the same authenticated session solely for this publication guard, without dispatching the denied method; this still shares the original RPC deadline/bounds.

Publication commits when the checked native write is issued. Already-issued bytes cannot be unsent; later authority loss forbids all subsequent queued publications. Tests distinguish already-issued write from waiting reply. Native write retains worker epoch/self/peer image checks. Native error/timeout/partial publication closes without retry, regenerated reply or automatic effect replay.

A completed WriteFile may leave unread frame bytes in the kernel buffer. The channel retains the original deadline of its last issued ordinary write; on close it stops intake/detaches authority eagerly, then allows only that write's remaining budget for native outbound-buffer consumption before physical disconnect. A later queued reply rejected after revocation must not discard that committed frame tail while delivery is still possible within this budget. Drain checks native identity only and publishes no additional data after authority loss. Ordinary replies do not each wait for native drain; continuously reading clients must receive all17 correlated replies in the16active backpressure test within original RPC deadlines. A delayed-tail native test leaves at most64KiB unread long enough for write completion, then receives the entire first frame and EOF for the denied queued reply. Failed drain/abandoned reader still proceeds to physical cancellation/disconnect without replay or added delivery time; only a confirmed disconnect can release the slot.

## Close and acceptance

Accepting close stops new intake. Earlier queued replies may precede its fixed acknowledgement if still authorized. After acknowledgement write and bounded native drain, detach and physically disconnect the owned connection; later queued replies are dropped. EOF/error/concurrent close is idempotent, releases each RPC interest once and does not await remote tool results or cancel durable jobs. Session-detach hooks retire response/read interests. Native disconnect cancels/drains outstanding read; physical slot cannot be reused before that barrier succeeds. Failed disconnect remains failed for pipe-pool owner.

Physical cleanup uses the retained peer's server-only epoch-bound disconnect, exempt from the ordinary worker quota3. Current-epoch cleanup remains possible after native identity rejection; stale-epoch cleanup cannot disconnect a replacement. Channel close publishes its shared completion before invoking detach hooks, so reentrant close observes the same attempt. Unexpected worker loss or unconfirmed physical disconnect makes that shared completion fail SERVICE_UNAVAILABLE; it cannot report successful slot release. Native drain includes accepted writes still starting native I/O, not only bytes already visible in kernel quota. These rules retain the common [foundation teardown barrier](../../001-service-foundation/contracts/local-api.md).
