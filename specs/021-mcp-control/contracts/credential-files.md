# Credential files and grant publication

[Envelope](client-credentials.md), [MCP](mcp.md), [loading](loading.md), [records](records.md), [tasks](../tasks.md).

## Components and paths

`packages/serverdeck_windows/lib/mcp_credential_files.dart` is the shared bounded file layer; locald `mcp/grants.dart` owns mutation serialization, live policy, receipts/CAS and publication/recovery order. The verified bridge only calls its read path. Neither layer exposes keys or file paths through MCP. Existing Windows protected file/atomic replacement/CurrentUser DPAPI primitives are reused. No backend or new OS service is needed.

The only root is `<localAppData>/ServerDeckNext/v1/workspaces/default/mcp-credentials/`. localAppData must pass existing fixed-drive/local/path rules. Existing ServerDeckNext, v1, workspaces and default must be regular directories with expected owner-only ACL; check them before any private read or child creation. Never repair their ACL, initialize a missing workspace, follow a reparse or load another workspace. The workspaceId/ownerSid come from the validated foundation manifest and current user; supplied ownerSid must equal currentUserSid. Under the root, names are canonical grant UUIDs; under each grant directory only `<secretRef>.dpapi`, `current.json` and `current.json.<32lowerhex>.pending` are accepted. All directories/files have the existing owner-only ACL and no reparse components. Unexpected names, depths/types, duplicate identities or unsafe paths block storage. No caller-selected filename or absolute credential path.

Ciphertext files are immutable CREATE_NEW, flushed before returning from stage, size1..16384; never overwrite a credential, including a same-request retry. A crash may leave an empty/partial unreferenced blob or pending lookup; retain it for explicit recovery. A referenced blob must fully open with its exact five-field binding. Grant revocation leaves the latest blob and issuedAt intact; historical replaced blobs are not needed to validate the retained current grant. No filesystem operation may make a grant current.

## Lookup format and bridge read

Startup composition uses the read-only inventory and recovery-lookup preflights in [native loading](loading.md). Every committed grant blob and existing lookup is validated before the first pointer publication; the file layer's single publish method cannot establish that global invariant by itself.

`current.json` is strict foundation UTF8 JSON at most4096 bytes, exactly `{format:1,product:"serverdeck-next-mcp-lookup",workspaceId,grantId,secretRef,ownerSid,issuedAt,revoked}`; revoked is bool, identity fields follow the envelope binding. It contains no raw key, token, scopes, expiry or server credentials. Parse with duplicate/unknown field refusal and exact type/binding checks. A well-formed unsupported integer format is INCOMPATIBLE; other malformed/custody/decrypt/provider failures are STORAGE_BLOCKED with no paths/private messages. A valid revoked lookup yields FORBIDDEN before decrypt. Missing lookup/blob is STORAGE_BLOCKED. All errors are subsequently mapped by the bridge's readiness/tool boundary, never echoed verbatim.

Bridge reads and closes a bounded protected lookup snapshot, validates configured grantId, expected workspace/current owner, then opens its bounded protected blob and returns a private key handle plus immutable binding. It cannot create directories/files, repair a lookup or consult Isar. Rotation between these reads may return an old key; locald checks against the current grant and rejects it. No stale lookup fallback, scan for the newest filename, old-secret retry or automatic authority renewal. Revocation is enforced by DB/session checks even if a retained lookup still says false. Close every opened handle on any failure; protected atomic snapshot semantics allow an already-open reader to finish against its retained old file.

## Budgets and serialization

The sole writer serializes stage→DB commit→lookup publication/recovery with the common mutation queue; no separate owner or bridge writer exists. File methods themselves do not confer the lease. Before writer operations enumerate only the two defined levels with followLinks=false, validate types/ACL/path, and cap at4096 grant directories,4096 regular files and32MiB total regular-file bytes including all blobs/current/pending files. Stop enumeration at the first count/byte excess, never materialize an unbounded directory tree. Unreferenced empty/partial blobs and well-named pending files consume this budget without decrypting them. Referenced file corruption still blocks startup. No implicit GC or eviction.

Stage admission reserves two file slots, one directory slot if needed, ciphertext size plus4096 bytes for the following lookup publication (pending file becomes current by atomic replacement); retain serialization until publication completes or the service enters blocked recovery. Admission at a count/byte limit is RESOURCE_LIMIT without creating a directory/file or committing a grant. The maximum supported credential history can therefore exhaust earlier than the permanent automation receipt budget. Also require caller-available free space at least128KiB before each write; this supplements quotas and does not promise immunity to later disk failure. A retry/recovery with an already-correct current lookup performs no write and needs no extra reservation. Recovery requiring a write with insufficient budget/space is STORAGE_BLOCKED until explicit cleanup. This budget is separate from Isar's64MiB and automation JSON64MiB limits.

## Durable publication and recovery

Owner request normalization, common-queue/native transaction composition and replay follow the [grant transaction contract](grant-transactions.md).

1. Under the common sole-writer/mutation queue, validate owner role, request identity/origin, grant count/CAS/policy, complete operation input and exact stable receipt. Replay a known request never generates another key or rotates again. A new create/replace chooses a new UUID secretRef and internal random key; stage its immutable blob with the exact workspace/grant/owner/issuedAt binding. Open/verify it, close the staging key, and preserve the file if any later step fails.
2. Atomically commit current grant metadata plus its permanent stable receipt in Isar. Replacement preserves original createdAt, rotates secretRef, advances revision and issue time per the existing grant contract. Revoke changes only revision/revokedAt and commits authority loss/session invalidation before any acknowledgement; no new key file. Transaction failure never publishes a lookup for the candidate. A staged orphan is not evidence of a committed grant.
3. After committed create/replace/revoke, write a new protected pending lookup and atomically rename/replace current.json. Read back the protected snapshot and compare exact content. Acknowledge only after publication is verified; on postcommit failure retain receipt/blobs/pending files, return safe STORAGE_BLOCKED, reject subsequent automation mutations/bridge opens and retain sole-writer ownership for recovery. Owner readiness/recovery remains available. The committed receipt may be returned after successful recovery; no different mutation result or second rotation is generated.
4. On operational schema2 startup, validate complete native/foundation/logical graph and open every current grant blob, including revoked grants, against its retained binding. Do this for all grants before modifying any lookup. Never decrypt a file merely because an unreferenced staged name exists. Then compare each committed grant's exact expected lookup (revoked flag from DB); a valid stale lookup for the same grant/workspace/owner may be replaced, and a missing lookup may be created. A malformed/foreign/unsafe existing lookup is a custody failure: fail closed without repairing it. Fully open the current DB-referenced blob before replacing a stale lookup. Only after all lookups reconcile can startup/authentication become ready. No grant row means a well-formed orphan lookup/file remains inert; no reconstruction of rows/receipts from files.
5. A crash before DB commit leaves only inert files. A crash after commit or during pointer publication is resolved strictly from committed rows/receipts, never timestamps/filename ordering. A receipt replay uses the committed result and publishes that grant's **current** retained lookup; it must not resurrect the secretRef acknowledged by an older replacement. A revoked grant stays revoked. Revoked metadata may be loaded/opened for validation but cannot authenticate. Pending files are never promoted based on their contents; write a fresh pending file from the validated DB state instead.

Explicit cleanup is owner-only maintenance under sole-writer serialization: dry-run inventory first, require an explicit selected set, revalidate the entire committed graph, never delete any current grant-referenced blob/current lookup or any referenced authority/receipt. This release need not offer an automatic cleanup command; quota exhaustion is a documented RESOURCE_LIMIT requiring owner-directed maintenance. Normal runtime must not guess, silently reset or prune unknown artifacts.

## Acceptance

Disk-space failure instrumentation may only raise the required reserve in a child compiled with `SERVERDECK_TEST_MCP_FILE_PROBES=true`; it must still call the actual Win32 available-space query. It cannot reduce/bypass a reserve or replace the native result. Ordinary builds reject installation/access and use the fixed128KiB native gate directly; no runtime environment/argument enables the probe. Test children have bounded deadlines and are reaped. This proves native refusal under an injected unattainable reserve, not a physically filled disk or disk-full DB transaction (T070).

T069 tests real temporary Windows directories and CurrentUser DPAPI, exact layout, staged immutable files, valid lookup read, current/replaced/revoked bindings, bounded snapshots, missing/corrupt/foreign data, duplicate JSON and unsupported format, unsafe ancestor/grant/file ACL, reparses at every level, invalid names and quota/space refusal. Assert forbidden operations leave active lookup/blob bytes unchanged. Test crash-shaped partial orphan/pending files, no inference from timestamps, concurrent retained reader during atomic replacement and no directory creation by bridge reads. Use temporary localAppData roots; never the user's active workspace.

T070 integrates actual native grant/receipt transactions and injected crash/IO boundaries before/after stage, commit, rename, readback and acknowledgement. Prove same-request replay after restart, rollback orphan retention, postcommit recovery, previous receipt versus current replacement, revocation precedence, no second key/revision and no publication before all grant blobs validate. T071 composes operational native schema2 loader/DPAPI/lookup gates and existing schema1→2 migration/bundle prerequisites. A fake transaction callback, JSON graph fixture or file-layer test cannot close T070/T071, T005/T006 or full service acceptance.
