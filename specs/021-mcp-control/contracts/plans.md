# Immutable plans and resource observations v1

[Model](../data-model.md), [records](records.md), [profiles](profiles.md), [executor](executor.md), [tasks](../tasks.md).

This defines structural metadata for T002/T023 and the inputs shared with the trusted compiler/preflight. Parsing a self-consistent digest is not permission, recipe qualification, trustworthy remote attestation or proof that a compiler rendered correct bytes. Actual plan creation/admission additionally checks current session/origin/target/trust, exact registered release/runtime/compiler/catalog hashes, full compiler output and factual prerequisite evidence (T011/T019/T023/T024/T028). No path/module/SQL string in these records becomes a caller-selected executable.

## Bounds, identity and counters

Objects have exactly the listed fields including explicit nulls, except the profile AST's own optional fields. IDs UUIDv4, SHA256 lowercase64hex, timestamps exact UTC milliseconds. Plan document maximum256KiB/depth16; resource observation maximum128KiB/depth16. Metadata names use their existing identifier grammars. Parameter/desired strings use profile rules. Configuration observed text is untrusted data, preserved verbatim as well-formed Unicode, never interpreted as a template/instruction. No raw logs or module output in plan records.

New automation revisions remain int1..2147483647. The following references to existing foundation counters remain decimal strings1..9223372036854775807, never int/coerced: `serverRevision`/observation `targetRevision` is ProfileRecord.revision; `connectionRevision`, observation/plan `accessRevision` is ProfileRecord.credentialRevision, and `trustRevision`. Access revision is a wire name for the existing credential counter, not a new independently advanced counter. Each captured connection/access/trust reference is<=serverRevision/targetRevision, and connectionRevision==trustRevision as in foundation. Labels may conservatively invalidate a captured observation/plan when the serverRevision changes; no permission follows a label.

## ManagedResourceObservation

The counter equality stated above and existing DTO constructors are schema2 rules. Schema3 remote services use explicit [host trust counter parsing](host-trust.md) with connectionRevision<=trustRevision<=captured revision for observations/plans/nested snapshots, without changing persisted JSON fields or historical bytes. A changed current trust revision invalidates freshness/admission, not retained historical structure. No unverified wire flag selects the schema3 parser.

Exactly `{workspaceId,serverId,resourceId,targetRevision,connectionRevision,accessRevision,trustRevision,hostId,resourceRegistryDigest,observedAt,status,value}`. Five resource IDs from the initial resource registry only. Status `known|stale|unknown|unsupported|denied|incomplete|error`. hostId and registry digest may be null only when no value is present; known/stale require both and the typed value below. All other statuses require value null; no fabricated empty/default value on probe failure. Cache is in-memory/bounded only. A stale value preserves last known data/observedAt for display, never authority. Even known is not fresh indefinitely: fresh checks require now>=observedAt and age<=15s, exact current identity bindings and current quality; future timestamps reject freshness.

Config resource value exactly `{exists,fileDigest,baselineDigest,values}`. exists boolean, baselineDigest SHA binds fixed path/ownership/mode/parents/effective dependencies. If absent: fileDigest/values null; if present: fileDigest SHA and values typed below. An absent DB config may be observed but cannot be adopted automatically: qualification/preflight blocks it unless part of a qualified fresh recipe. A regular motd file may be absent or at most64KiB UTF8. Its values are `{text:<verbatim well-formed Unicode text with UTF8 bytes<=65536>}`; control/template characters are data, not executable profile syntax. Unknown/binary/oversized/parse-failed content yields incomplete/unsupported with value null. PostgreSQL/ClickHouse values are exactly the existing registered config field types/ranges, without parameter references. Observed settings outside the supported schema yield unsupported rather than coercion. No arbitrary config keys or paths.

Service resource value exactly `{activeState,unitFileState,mainPid,startMonotonicUs,baselineDigest}`. activeState supported values `active|inactive|failed|activating|deactivating|reloading`; unitFileState `enabled|enabled-runtime|disabled|static|masked|masked-runtime|indirect|generated|transient|linked|linked-runtime|alias|bad`. Adapter maps unrecognized future values to unsupported/null, never guessed boolean. mainPid int0..2147483647; startMonotonicUs decimal0..int64max (0 is absent); baselineDigest includes qualified canonical unit/drop-ins/dependencies. These are observations, not permission to mask/unmask/adopt a unit. Restart postcheck compares actual PID/start evidence under the same boot context.

Observation fingerprint is SHA256 of foundation canonical `{workspaceId,serverId,resourceId,targetRevision,connectionRevision,accessRevision,trustRevision,hostId,resourceRegistryDigest,value}`. Only known/stale values can have a fingerprint; status and observedAt excluded so a fresh read of exactly the same facts can validate a five-minute plan. A config file's exact fileDigest preserves byte-sensitive equality even when canonical JSON NFC processing normalizes text; the public observation value itself is copied/serialized verbatim. Fingerprints are not current freshness or authority.

## QualifiedRecipeDescriptor structural form

Exactly `{format:1,id,version,revision,digest,environment,packagePins,dependencyTransactionDigest,repositoryFingerprints,aptIndexDigests,expectedAbsentPaths,ownedResources,prechecks,postchecks,licenseNotices}`. Maximum128KiB/depth16. id `postgresql16|clickhouse`, version exact selected catalog product version (non-template NFC public string1..256, not case-insensitive latest), revision positive31bit, environment `ubuntu24.04-amd64-systemd`. This version is independent of individual dependency package versions; qualification binds it to the exact package transaction. Source install_recipe.version, derived effect.version and descriptor.version must match exactly; a correct descriptor digest with a different version is invalid. digest SHA256 canonical descriptor excluding only digest. Structural parser recomputes it. It never marks a descriptor qualified merely because it hashes correctly.

packagePins list1..256 unique `(name,architecture)` entries exactly `{name,architecture,version,sha256}`; name `[a-z0-9][a-z0-9+.-]{0,127}`, architecture `amd64|all`, version non-template NFC public string1..256, exact SHA. No `latest` version (case-insensitive). repositoryFingerprints unique1..16 lowercase40hex or64hex; aptIndexDigests unique1..64 SHA. expectedAbsentPaths unique1..32 normalized absolute Linux paths1..256 characters, no empty/dot/dotdot segments, NUL/control/template/backslash; these are trusted catalog metadata, never caller execution paths. ownedResources exactly the matching DB service/settings pair, unique, not NetBird/motd/another program. prechecks/postchecks unique1..32 identifier strings; actual accepted IDs are only bundled compiler/probe IDs from the exact qualified release, unknown IDs fail runtime validation. licenseNotices list1..16 non-template NFC public strings1..2000, LF/TAB allowed. Shared parser establishes shape/digest only; signed repository/dependency/CPU/SQL/absence/ownership/runtime qualification and catalog membership are mandatory T019/T028 evidence before any descriptor becomes executable.

## Preflight capsule

Exactly `{format:1,operationId,hostId,environment,profileDigest,inputDigest,runtimeVersion,runtimeLockDigest,compilerDigest,registryDigest,bootIdHash,packageSnapshotDigest,expectedPackageSnapshotDigest,netbirdSnapshotDigest,aptIndexDigests,recipes,baseObservations}`. Capsule maximum256KiB/depth16, runtimeVersion public string1..100. Other digest fields SHA, operationId/hostId UUID, environment fixed. aptIndexDigests unique list0..64; recipes list0..2 descriptors, unique id/digest, matching capsule environment and all recipe apt index digests contained in capsule indexes. baseObservations list0..5 exactly `{resourceId,fingerprint}` with unique initial resource IDs/SHA. Snapshot/hash values are actual preflight evidence, never all-zero placeholders to represent missing data. A legitimately computed all-zero digest is not syntactically rejected; absence is explicit null at the outer capsule field.

Capsule profileDigest/inputDigest bind the validated body and complete resolved parameter map. The root preflight cache/spool retains full baseline evidence (package membership/index/absence/unit/parent config and service runtime identity), whereas local plan stores fingerprints/digests and declared public recipe pins. Preflight cache must persist until its five-minute expiry and copy necessary full evidence into durable admitted job receipt before acknowledgement. A missing/expired cache refuses submit; it never reconstructs arbitrary evidence from caller hashes. Before each launch root revalidates required full facts, not just the caller's digests. Capsule digest is SHA256 of its whole canonical object. Job submission binds this preflightDigest, planDigest, exact profile tuple and expected host. No secret/SSH/auth data in capsule.

## Plan record

Exactly `{workspaceId,id,requestId,profileId,profileRevision,profileDigest,serverId,serverRevision,connectionRevision,accessRevision,trustRevision,hostId,registryDigest,exactParams,inputDigest,desired,baseObservations,effects,checks,preflight,preflightDigest,status,reasons,createdAt,expiresAt,originGrantId,digest}`. originGrantId nullable owner origin as in records contract. expiresAt exactly createdAt+5min, never extended by status reads. Digest is SHA256 of entire canonical Plan excluding only digest; includes exact profile tuple, origin, timestamps, recipe/runtime/preflight/effect/check/fingerprint data. inputDigest hashes canonical complete exactParams. Loading resolves the retained immutable AutomationRevision, requires workspace/full tuple match, revision.createdAt<=plan.createdAt, complete typed parameters including explicit defaults, and desired exactly the resolved steps in original order. No head-following or replacement with equivalent body at another revision.

desired is resolved profile step list,0..32; no parameter objects remain. baseObservations uses the capsule reference shape. Effects/checks are bounded typed compiler output below, not free-form descriptions. status `runnable|blocked`. reasons list0..32 unique exact `{code,field,stepId}`; code is from the safe record-code vocabulary, field `executor|runtime|trust|recipe|packages|paths|qualification|memory|step_limit|observation`, stepId null or existing source step. No raw exception text.

Runnable requires reasons empty, non-null hostId/registryDigest/preflight/preflightDigest; exact capsule digest, profile/input/host/registry/fingerprint bindings, complete derived effect/check coverage, no unsupported conflicting resources. Blocked requires at least one reason and empty effects/checks; preflight may be null (then hostId/registryDigest/preflightDigest null and baseObservations empty) or a completely validated actual capsule with matching bindings. It never becomes runnable later; create a new explicit plan after prerequisites change. Oversized facts/capsules/plans return RESOURCE_LIMIT before a durable plan acknowledgement; never truncate executable evidence to fit.

Creation/apply checks use current same-target known observations age<=15s and match every captured fingerprint; re-read age may be fresh even if original plan is older. No arbitrary new observed value silently rebases an approved plan. Existing plans may be loaded as history after expiry/stale/revoke; loader validation does not restore live permission. At admission locald additionally recomputes trusted compiler output from the bound revision/params and verified preflight/qualified catalog, compares the complete effect/check program/digests and current policy. A structurally plausible caller-created program/capsule can never authorize itself. T002 parsers are not a substitute for this T019/T023/T028 validation.

## Effects and postchecks

Every effect is exactly its union fields plus `{id,sourceStepId}`. IDs follow profile identifier grammar, unique1..32; sourceStepId must exist in desired. Order is compiler-defined and immutable. Closed kinds:

| kind | Additional fields | Structural relationship |
| --- | --- | --- |
| service_state | resourceId,state | Registered DB service, state started/stopped/restarted; exact source service state or derived restarted for matching DB config activation. |
| service_enabled | resourceId,enabled | Registered DB service, boolean; exact source service enabled. |
| config_file | resourceId,values,renderedDigest | Registered config resource, exact source resolved values; renderer digest SHA from qualified compiler. |
| install_recipe | recipeDigest,version | Exact source recipe/version and matching capsule qualified descriptor; no package/repository/path arguments. |

Runnable output has exactly one config_file effect for each source config, followed by one matching service_state restarted activation for DB settings, none for motd. Each source service yields service_state then optional service_enabled. Each source recipe yields one install_recipe effect. Flattened order follows desired order; compiled total>32 is a blocked step_limit RESOURCE_LIMIT plan. Descriptor owned resources cannot overlap another recipe or an explicit service/config step. For profiles without install recipes expectedPackageSnapshotDigest==packageSnapshotDigest. For installations the qualified root simulator/gate proves exact additions; hashes alone are not proof.

Every check has `{id,effectId,resourceId,kind}` plus the exact kind fields. IDs unique; effectId references one effect. At most96 checks. Compiler check ordering is deterministic by effect order and the following order; compare whole objects rather than treating a subset as sufficient.

| effect | Required checks in order |
| --- | --- |
| config_file | file_digest `{digest:renderedDigest}`; for DB settings additionally settings `{values:<exact effect values>}` (trusted postcheck runs after activation) |
| service_state | service_state `{state:active|inactive}` (inactive only for stopped); restarted additionally service_restarted `{baselineFingerprint:<matching base service fingerprint>}`; started/restarted additionally sql `{expected:1}` |
| service_enabled | service_enabled `{enabled:<exact boolean>}` |
| install_recipe | recipe `{recipeDigest}` with resourceId `recipe.postgresql16|recipe.clickhouse` from descriptor; bundled qualified recipe expands all required exact package/version/local SQL/resource checks in root receipt |

For ordinary check kinds resourceId matches effect resource. Baseline fingerprint references must be present for all source/derived service and config resources; install-only profiles may have no resource observation if all factual absence/package/CPU checks are in capsule. Check/renderer/probe execution comes only from bundled trusted compiler IDs and root receipt evidence. Fixed SQL is SELECT1, never a supplied query. Job's32-result summary is bounded UI history, not a replacement for the full required postcheck evidence. Succeeded admission outcome must compare the whole required checks/recipe postchecks against the durable executor evidence.

## Implementation and acceptance

Shared structural records live in protocol automation/plan_records.dart and observation_records.dart (T002), with exact descriptor/capsule types/digests and immutable input snapshots before any await. Plan/reference/freshness helpers do not admit effects. Complete live checks/compiler/preflight/reference resolution belong to locald plans/store and root compiler/recipes (T007/T019/T023–T028). Schema2 startup must validate all stored plan shapes/digests/revision references; it must not discard unknown nonempty collections.

Tests cover runnable/blocked nulls, empty vs missing evidence, exact TTL, full tuple/default parameters, digest recomputation/input mutation during async hashing, foundation64-bit counter encoding, raw observed Unicode/template data, observation statuses/freshness/fingerprint change, descriptor unknown/duplicate/unsafe fields and hashes, correct recipe digest with wrong product version, program coverage/order/resource conflict/check tampering, cross-workspace/server/host/registry/revision bindings and historical parse vs live permission. These are structural tests; actual root fact/renderer/apt/SQL/systemd Docker/VM qualification and transactional startup/admission remain separately required.
