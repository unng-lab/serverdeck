# Native MCP invocation composition — 021 API1.1

[Protocol](mcp.md), [handshake](handshake.md), [plan](../plan.md), [tasks](../tasks.md).

## Ownership and authority

T090 implements the shared strict invocation DTOs in packages/serverdeck_protocol/lib/mcp/operations.dart and the locald McpRouter in lib/mcp/router.dart. T010/T086 then connect this router to the operational Local API channel; T009 connects the bridge gateway. These components never select a bootstrap mode, open Isar independently, issue an owner role or start an SSH connection themselves. One router belongs to one OperationalSessions registry/workspace generation and the same tool services used by owner UI endpoints. No partial product activation or fallback to API1.0 follows from adding the router.

Only an mcp.invoke OperationalSessionRequest may enter the router. It checks native/session/current grant authority before reading method-specific input, tool schema, handle or object state. OperationalMcpContext is privately minted by that native-backed request; it retains the immutable session/grant binding independently of one completed RPC interest. Its authorize and revalidate methods consult the same registry/current grant and peer; owner/missing/open-less sessions cannot mint it. Async tool services receive this context and a validated immutable input. They must revalidate before/after awaits and before each remote effect, resolve only allowed target/object/origin, and apply exact plan/delegation/approval checks. The router also checks every tool required scope and any explicit serverId before calling the service. It does not infer target ownership of planId/jobId from caller text; their service resolves retained objects after scope checks and enforces origin/target before returning them.

McpToolServices is a trusted internal interface returning one McpServiceOperation with a result future and an idempotent cancelInterest future. Production composition must supply all24 registered tool implementations before declaring ready; interface fakes may qualify routing only. A result is public data or an allowlisted domain failure, not an exception/log echo. Durable mutations/jobs outlive transport interest and remain governed by their existing receipts/authority. cancelInterest never means jobs_cancel or transaction rollback. The router owns operation records and unfinished service work; closing it denies new work and retires interests without closing durable job storage.

### Lifecycle notification composition

The service composition constructs the router with its exact OperationalSessions registry and operational StateStore authority. The router itself subscribes once to trusted internal synchronous session-detached and grant-published hooks, and unsubscribes on close; it does not depend on the bridge issuing another invocation or on UI code remembering a secondary router call. OperationalSessions emits detach after removing the exact session and before completing its detach path; existing owner lifecycle callbacks remain connected. StateStore emits the affected grant ID after durable commit plus validated snapshot/file publication, while its temporary authority-unavailable gate is still held, before reopening authority and before returning the stable owner acknowledgement. Create/replace/revoke all emit; an unchanged idempotent receipt replay does not emit a false replacement. Notification contains public identity/revision only, no key/secret. Trusted listeners cannot change roles or grant records. A listener failure cannot restore authority or produce a success acknowledgement: the owner service stays fail-closed STORAGE_BLOCKED, preserving its durable receipt for explicit recovery; restart creates a new generation, never restores old sessions.

Each hook synchronously marks matching operation records retired, clears response data and starts the one shared interest-cleanup request, before returning to its publisher. Actual service/cleanup futures remain charged until settled; the publisher does not await a remote read or roll back a committed mutation. Router close first removes hooks, denies intake and retires all interests. A late callback from an old session/record cannot retire a reused identifier. Registry lease expiry and native failure use the same detach path. For idle grant expiry, router's single nearest-deadline scheduler includes the bound grant expiry and rechecks wall-clock authority before retirement; timer wake never grants authority. Tests revoke, replace and disconnect with no subsequent invocation/poll, check immediate cache retirement and one cleanup request, then resolve a delayed result and prove no resurrection or freed unfinished-work capacity. Product channel/bootstrap wires the same registry/authority/router once; it must not construct independent per-channel routers or bypass these hooks.

Publishers notify every registered trusted listener once even if an earlier listener throws, then apply their fixed fail-closed error; an unrelated observer failure cannot suppress router retirement or the existing owner lifecycle callback. Timer scheduling uses the immutable bound grant lifetime/current lease, not a fresh store lookup inside a temporary publication/replay gate; this hint never admits work or output. Actual admission/publication/poll still revalidates native/current store authority. An unchanged receipt replay must not retire otherwise idle cached interests merely because its validated reload temporarily gates reads. Listener-failure acceptance includes reopening the actual protected store and replaying the committed stable acknowledgement without another grant revision or false publication event.

## Strict shared wire

Input is exactly one of `{catalog:{}}`, `{request:{name,arguments}}`, `{poll:{operationId}}`, `{cancel:{operationId}}`. Empty catalog, required string tool name1..256codepoints and object arguments, UUIDv4 operationId, no unknown/extra/combined/null variants. Input is bounded256KiB/depth16 including union framing. Snapshot original JSON scalars/keys without NFC normalization or number coercion before the first await; exposed nested maps/lists are immutable, serialization returns fresh containers. The ordinary Local API envelope is separate and retains its own bound. Public parse errors have fixed VALIDATION without original input.

Replies are exactly `{tools:[definitions]}`, `{done:false,operationId}`, `{done:true,result:<MCP tool result>}`, `{done:true,protocolError:{code:-32602}}`, or `{cancelled:true}`. Unknown tool or invalid tool argument JSON schema uses the protocolError variant and is translated by the bridge into external JSON-RPC Invalid params; it never looks up an object or starts service work. Missing scope is FORBIDDEN before schema/object work. Structurally valid profile semantic validation remains profiles_validate's documented data/issues, rather than an invocation parser error. Malformed internal invocation shape is ordinary Local API VALIDATION. No other protocolError code is accepted. Backend/domain failures use the existing tool envelope with content text JSON and identical structuredContent/isError; they do not become JSON-RPC internal errors. The shared domain error allowlist contains existing foundation codes plus the additions in mcp.md, boundary local/remote/executor and the five documented retry values; no arbitrary error message/field/source.

Tool argument JSON schemas are the catalog's closed supported schema vocabulary, validated centrally before service admission; UUID/timestamp/integer/string/array/object/oneOf constraints are checked without coercion. Semantic constraints, exact profile AST/resource ranges and object graph/authority remain service checks, not an arbitrary JSON Schema plugin. Catalog replies use the fixed shared definitions filtered by live policy; the bridge cannot add tools from cached scopes. Results preserve observed Unicode/text and integer identity. Strict duplicate-safe parsing is used on bytes. Tool results and cached replies are bounded to8MiB minus4096bytes for outer Local API/MCP envelopes; oversize/invalid backend output becomes fixed INTERNAL, never partial output. The depth16 limit includes both done.result and the Local API response result wrapper: a standalone tool result must fit depth14 and an invocation reply depth15. Validate this reservation before accepting backend output. Encoding failure maps to fixed INTERNAL while preserving the owned handle/cache lifecycle; only authority failure retires the handle. Test the maximal accepted depth through the actual outer wire and one level beyond for inline and pending/poll results. Catalog is at most24 distinct known definitions and is checked against the shared definitions rather than accepting backend-supplied schemas.

The deeply nested authoring schemas must fit the unchanged depth16 limit when wrapped by both internal catalog and external JSON-RPC tools/list. Their static input schemas use root $defs and same-document #/$defs/<generated identifier> references, following [JSON Schema modular structure](https://json-schema.org/understanding-json-schema/structuring). Compiler-generated definitions are acyclic, deterministic and contain the same closed constraints; hoisting changes representation only, never admits an additional argument/step/resource. No external URI/reference, runtime schema registration or caller-selected resolver is allowed. The central validator resolves only these fixed local definitions, with a bounded reference traversal; it rejects unresolved/cyclic/unsupported schemas. Full24-tool internal and actual external-wire catalog encoding/decoding plus argument-equivalence regression tests are mandatory; testing only two shallow definitions does not qualify discovery. No protocol depth increase or replacement of the real catalog by a reduced fixture.

## Operation state, bounds and recovery

Admission reserves workspace32/session16 slots synchronously before starting a service; every unfinished service unit counts even after disconnect/cancel/timeout. Handle metadata is likewise at most32 workspace/16session, includes completed cached records, and is scoped to exact sessionId/grantId/revision/secretRef. UUIDv4 IDs are random, never durable requestId. A caller cannot select owner origin, operation ID or grant binding. Quota refusal does not start work. Catalog allocates no handle. An already-resolved result may return inline and release its record if its handle has never been exposed; otherwise response is done:false and subsequent poll observes the same operation without restarting it.

Poll/cancel checks current binding first, then owner-of-handle; unknown/foreign/expired handle uniformly FORBIDDEN. Cancel is idempotent for its retained owned record, returns cancelled:true and invalidates its cached result/response interest; it requests service interest cleanup once. Completed result retained at most60seconds from completion, using monotonic time; there is no expiry of durable receipts/jobs. At exact expiry the handle is unavailable. Cancel/disconnect/revoke/router close discards response data immediately but cannot free an unfinished service unit until its actual result and any requested cleanup futures have settled. Late completion cannot repopulate retired data. This prevents cancellation-created capacity and unbounded detached work. One cleanup request is shared; caller waits at most5seconds for it, then receives TIMEOUT while the unit remains charged until actual cleanup settles. Cleanup exceptions are sanitized and do not revive result interest. At most32 units, each with at most one result and one cleanup future; no repeated detached cleanup futures per poll/cancel.

Service reads/preflight have an absolute30second operation lifetime from admission, never reset by polling; at deadline discard/deny late data and request interest cleanup, retain fixed TIMEOUT for an exposed owned handle until completion-cache expiry. Mutation timeout likewise drops transport interest only, never cancels the admitted durable mutation/job; original durable requestId remains usable through normal tool replay/status. Each local invocation and native revalidation is bounded by a single5second RPC deadline. A router deadline/cleanup timer and a single nearest-expiry sweep belong to this router, not an unbounded timer per poll. Native lease/generation/current grant still gates every poll and result after awaits. Timer expiry alone never admits a new physical effect or releases unresolved work.

Acceptance covers strict union/duplicate/Unicode/snapshot/byte limits; every catalog schema and invalid argument case; actual native mcp.open then router catalog/call/poll/cancel against real schema2/DPAPI; cross-session/owner/scope refusal before service/object lookup; result isolation on revoke/replace/expiry/native failure;32/16 admission and deadline/cleanup/late completion/ID ownership/cache boundaries. Controlled service futures test scheduling/cancellation but do not prove remote behavior or close full startup/bridge/systemd Docker/VM acceptance. Legacy API1.0 remains independently tested. Mandatory checks and fresh independent review precede handoff/closure.
