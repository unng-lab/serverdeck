## Components and admission

T104 implements `packages/serverdeck_mcp/lib/src/local_gateway.dart` as LocalMcpGateway, a McpGateway for the existing stdio McpServer. Its configured async factory LocalMcpGateway.connect receives one actual native OperationalClientSession, requires native mcp role and an already completed protected grant-open, then claims its OperationalApiClient. Wrong role/missing grant fails FORBIDDEN before claim/I/O and does not close a caller-owned session. No transport/role/credentials callbacks, locald/Isar/SSH import, arbitrary Local API proxy, key retention, reconnect or effect replay. Gateway owns its claimed client, timers, invocation interest and cleanup; locald remains owner of authority, operations and durable jobs.

connect claims the ordinary client only after that preflight, then derives its native publication gate from the same peer/authenticated hello generation. It returns a usable gateway only after actual gate creation. Failure after claim retires the claimed client, observes any late gate factory completion and closes the late gate; it never returns an unconfigured fallback. An already-claimed session is denied without closing its other owner. The bridge retains only public grant expiry metadata for its synchronous final UTC check, not a grant key. The concrete API has no runtime timeout overrides or injected RPC/role/provider callbacks.

An explicit unconfigured constructor has no client/native I/O: valid tools/list returns tools:[], valid tools/call returns the fixed FORBIDDEN tool envelope. This is not a fallback for bundle/native/transport failure. A configured connection that becomes unusable remains terminal; transport failure returns fixed errors, never silently pretends it was an empty live catalog. Subsequent construction needs a fresh explicitly authorized bootstrap. Gateway start after close uses SERVICE_UNAVAILABLE, never old data.

Maximum16 gateway invocations, including cancelled work whose actual local RPC/cleanup has not settled. Excess never starts work: tool call RESOURCE_LIMIT envelope; list uses the fixed service error below. One shared client permits16 pending RPCs, serialized writes/one reader; gateway tracks all local futures, including heartbeat/publication/cancel, without unbounded detached work. Before admission a queued bridge invocation can be cancelled without starting RPC. Once admitted to its bounded local RPC, it may reach locald; cancellation waits for that single acknowledgement, never resends it. Durable requestId and arguments are immutable snapshots; external wire ID is not passed as a mutation ID.

## Standard method mapping

The pinned [official schema source](https://raw.githubusercontent.com/modelcontextprotocol/modelcontextprotocol/main/schema/2025-11-25/schema.ts) permits optional arguments and request metadata. tools/list accepts only optional object _meta; any cursor is invalid because this bounded catalog is one page and never issues nextCursor. tools/call requires nonempty name≤256codepoints and accepts optional object arguments (default{}), optional object _meta; task augmentation and other top-level fields are rejected -32602. Metadata is ignored, not forwarded/logged/reflected or treated as authority; no progress notification promise. Tool arguments remain subject to locald's strict registered schema/scope checks. Generic method-shape validation precedes unconfigured fixed responses and never looks up a private object. Unknown forwarded method is -32601. Preserve original Unicode/scalars by encoding the bounded snapshot before any await; max256KiB/depth16 includes the external method parameters.

tools/list maps once to mcp.invoke{catalog:{}} and validates a catalog McpInvokeReply before returning its exact live tools. No bridge catalog or policy cache/filter. tools/call maps once to mcp.invoke{request:{name,arguments}}. Inline done returns exactly its validated McpToolResult; initial protocolError maps to -32602 without source echo. Pending stores that exact operation UUID; poll the same ID every250ms until done, cancellation or the35second monotonic invocation budget. Never restart request or substitute a durable ID. A poll may return pending only with the original UUID, or done with a valid result; other variants/mismatched ID are INTERNAL and retire the connection. A catalog returning any other variant is likewise INTERNAL. Cancel expects exactly cancelled:true. Typed parse/validation failure is fixed INTERNAL, no raw response/data diagnostic.

Every local admission/writer/response RPC stage is bounded by one5second outer budget, also capped by remaining35second invocation time or5second cancellation/publication budget. Waiting for an occupied local slot consumes that same budget. If a slot is full, wait only for tracked actual RPC completion, not a growing retry/effect queue. A timed-out already-admitted RPC closes the claimed client, observes its eventual completion and retires session interests; it is not reissued. The client retains native buffers through actual cleanup. Poll timers are cancellable and do not add a new35second window. A tool TIMEOUT leaves durable IDs/status queryable through a subsequent explicit authorized session/call.

## Fixed failures and stdout publication

Add McpGatewayFailure carrying only an existing ErrorCode to `lib/src/server.dart`. McpServer translates it to JSON-RPC -32000/message fixed wire code for tools/list, or its existing safe local tool failure for tools/call; never use arbitrary exception text. For ordinary RPC errors the gateway returns a McpToolResult.failure with its validated code and unchanged LocalError retry mapping; UNAUTHORIZED is normalized to FORBIDDEN. Unexpected internal exceptions use INTERNAL. Native/closed transport is SERVICE_UNAVAILABLE or its validated TIMEOUT/UNAUTHORIZED mapping, not an empty catalog. Only locally synthesized fixed failures from these validated RPC errors, overload or the explicit unconfigured mode may use no-I/O publication callbacks: they contain no server data, private IDs, input echo or optional requestId. They preserve the original LocalError retry advice even when UNAUTHORIZED's public code is normalized to FORBIDDEN. A server-returned McpToolResult, including a domain failure, still takes the real native guard/lease; an error flag is not a bypass. All configured invocation objects carry the three trusted callbacks, even when those callbacks are immediate for a data-free fixed failure. Immediate cancellation/release also share their one completion. Unknown tool/schema remains -32602. Remote/executor domain errors already inside a validated tool result pass unchanged.

Extend McpInvocation with an optional trusted beforePublish callback and a matching afterPublish release callback, plus a synchronous validatePublication callback. Configured gateway always supplies all three. beforePublish retains its invocation-owned publication lease until afterPublish; McpServer invokes afterPublish in finally after success, guard/write failure or cancellation, and observes late guard completion so a timed-out acquire cannot leak a subsequently acquired lease. The engine retains and observes the original issued stdout write/flush future as well as the guard; a logical timeout never releases the gate while actual flush is live. Shared idempotent release completion remains charged through actual native cleanup. Logical exit2 stays bounded; installed executable terminal shutdown must close its owned stdio/process, with release only after actual flush settlement or confirmed physical transport termination. A never-settling actual write keeps the gate held until process termination/native abandonment, which remains fail-closed for mutators; no forced unlock or false successful mutation. The concrete gateway close immediately stops admission/retires interests, but never force-releases a publication-owned lease: that lease stays charged and observed until afterPublish following actual guard/flush settlement or confirmed physical transport termination. close shares and waits for these real cleanup completions; McpServer may bound its logical wait/report CLOSE_FAILED while native ownership remains held until actual cleanup/process termination. Late afterPublish and concurrent close use the same idempotent release, never two release attempts; physical release failure is terminal SERVICE_UNAVAILABLE, never false gate reuse. Legacy generic protocol fixtures can omit both callbacks. The configured LocalMcpGateway always supplies it for its returned data/catalog; the unconfigured gateway may use an immediate no-I/O guard for its fixed empty/denied results. Existing generic protocol test fixtures may omit the callback; the executable must compose the concrete gateway, not an unguarded arbitrary provider.

McpServer invokes the guard after its serialized stdout writer wait, before issuing bytes from a gateway result, then synchronously invokes validatePublication and rechecks current invocation identity/cancellation/transport. The guard performs fresh session.ping through the same claimed native client, validates exactly leaseSeconds60, and thereby checks server native/session/current bound grant tuple. It never refreshes a grant revision or authorizes a new scope. No await follows the final current-interest check before issuing stdout write. Results retired while queued must not be published.

Target identity changes also invalidate publication, even when the grant is unchanged. OperationalSessions owns a conservative workspace-wide MCP target-change fence: beginTargetChange() synchronously blocks new protected MCP opens, then asynchronously acquires the shared native publication gate before detaching every existing MCP session or changing target identity. The returned future completes with an opaque, idempotently releasable lease only after acquisition and retirement; mutation code must await it before accessing/changing target identity. Fence intent alone is not a committed identity change; an already authorized publication may finish while that intent waits. Acquisition is bounded by the original5second owner RPC budget; timeout/failure makes no mutation and keeps old sessions retired once acquisition actually settles, with late leases released and actual work observed, not a detached mutator. No lock is forcibly released while its owning native work remains live; overlapping changes retain the fence until every lease settles. Owner sessions remain usable. A protected open checks the fence both before credential work and immediately before binding the grant; an in-flight open cannot escape retirement. A blocked protected open fails fixed UNAUTHORIZED and closes its attempted MCP session, using exactly the existing sealed failed-initial-open permit and its unchanged allowlist in operational-channel.md; no automatic retry. Check the fence before opening the grant key, so a blocked open performs no grant credential read/decryption. Test the exact terminal UNAUTHORIZED response, EOF/closed session and zero key access, not merely a thrown error. The owner service must hold the lease through commit/rollback and all identity/cache/read-interest invalidation, releasing in finally only after actual work settles, including failure. This applies to target deletion, connection identity/address/user changes, credential replacement/removal and host-key trust acceptance/replacement/revocation. Releasing the fence never revives old sessions or their queued data; a new explicit bootstrap is required. A failed mutation may therefore conservatively retire MCP sessions. This deliberate workspace-wide policy avoids gateway target-policy caches, result tokens, credentials or new wire methods. T109 implements and tests the registry/open fence; the original target/credentials/trust service tasks must acquire it before any such mutation, and product remote readiness remains false until those integrations pass. After fence acquisition/completion, an earlier publication has either finished issuing/flushing its stdout bytes or retired without issuing them; no successful buffered ping can authorize a later publication across that completed fence. A guard starting after retirement fails and replaces queued data with the fixed failure. A future connection cannot publish the former invocation.

The synchronization primitive is a separate same-user Windows named mutex, not the workspace owner mutex, held by a dedicated uninterrupted native worker stack across Dart awaits (as with existing MutexLease). Its name is Global\ServerDeckNext.v1.<sha256>, digest over UTF8 `serverdeck-next-publication-v1\n<ownerSid>\n<verified canonical bundle root>\n<generation>`; owner SID/root come from retained worker-verified native bootstrap, generation from that same authenticated session/registry. Both processes use identical encoding and Windows canonical root identity from bootstrap, never a caller-selected path/name/role or remote input. Owner-only ACL and actual acquire wait prove ownership; opening a handle does not. Native abandonment is fail-closed and closes affected session/workspace interests pending explicit recovery. No arbitrary external lock/configuration endpoint. The gate is separate from private pipe I/O workers, so holding it cannot block the ping that proves current authority. No generic injectable mutex callback qualifies production acceptance.

The bridge acquires this gate after stdout writer acquisition and before its fresh ping, holds it through the final identity/expiry check and actual stdout write/flush, then releases in afterPublish. Every owner mutation that can invalidate published data or authority (grant replace/revoke, target identity/access/trust change, operational storage shutdown/recovery) acquires the same gate before its committed change/retirement, and holds it through durable commit, authority/snapshot notification and actual invalidation. Existing temporary store authority gates stay in force. Mutation admission may mark intent early, but success/visible committed revision occurs only inside this gate. A successful ping buffered in the pipe remains safe because its publication owns the gate: the mutator cannot commit until publication releases, or the bridge fails/terminates and native cleanup releases it. A blocked stdout still uses the original single5second budget, never makes mutation wait indefinitely, and already-issued bytes keep their established irrevocable semantics. No service mutation may await a bridge-owned ordinary RPC while holding the gate. Heartbeat/poll/open do not acquire it. Before the final synchronous stdout issue, the gateway validatePublication callback additionally checks its bound grant expiresAt against current UTC and local client/interest state with no await before issuing bytes; it never extends expiry. Timer/detach handles expiry/native loss normally. Startup binds the gate to the native generation; restart never reuses an old gate.

Guard plus actual flush share the existing single5second writer budget from acquisition of that writer, not two new windows. A fixed guard failure replaces the queued response with a fresh safe failure (list -32000/code; call tool failure, local/retry none), discards its old data, and writes only within remaining budget; unknown failure maps INTERNAL. Timeout/I/O failure closes stdio with fixed diagnostic/exit2 and no retry. Recheck identity after the guard even if another wire request reuses the same external ID. Local protocol/timeout/overload errors synthesized by McpServer contain no gateway data and need no native guard. The35second deadline bounds producing the invocation result; stdout queue/flush keep their separate existing bounded transport semantics. Already-issued stdout bytes cannot be unsent.

## Cancellation, heartbeat and close

Each invocation exposes one shared cancelInterest completion, created before callbacks. Cancellation marks interest retired/stops poll scheduling immediately and suppresses any late result. If its initial RPC is still in flight, wait for that actual single acknowledgement within the original5second cancellation budget, recording any returned handle before signaling settlement. If a handle exists, send one mcp.invoke cancel for it; never jobs_cancel. Inline completion/catalog has no remote handle to cancel. If cancellation cannot establish/retire its admitted interest within budget, close the client/session; do not launch late detached cancels or assume a durable job was cancelled. Wait for a needed local slot only within this same budget. Repeated cancellation shares the original attempt, no extra cleanup operations or capacity. Actual unfinished RPC/cleanup remains charged until settled or confirmed native client close; completing the wire interest alone does not free capacity.

One nonoverlapping heartbeat every20seconds sends session.ping when a native slot is available; skip a full-slot tick (admitted requests already renew the60second lease), no heartbeat queue. Validate leaseSeconds60. Any failure except a pre-I/O local RESOURCE_LIMIT retires this configured gateway/client without reconnect; heartbeat/publication never grant new authority. Close cancels heartbeat/poll timers, stops admission, retires every invocation interest and closes the native client once. Closing that client is not proof that a stdout publication has physically ended: publication leases follow the separate actual-flush/afterPublish lifetime above. It need not sequentially send cancels for each handle when dropping the entire session; server detach owns interest cleanup, durable jobs remain. Concurrent/reentrant close shares its completion, including physical cleanup failure; late results cannot revive it. No remote wait or unsafe cancellation of running jobs.

## Process stdio runner

packages/serverdeck_mcp/lib/src/stdio.dart exposes serveMcpStdio(LocalMcpGateway), the concrete executable composition for stdin plus stdout.nonBlocking. The pinned Dart SDK's ordinary Stdout is synchronous: its add may block the isolate inside an issued write, preventing any Dart deadline from firing. Neither a Future wrapper nor flush.timeout makes such a synchronous add cancellable. The runner therefore uses the actual nonBlocking IOSink for stdout and stderr, observes their done futures, and delegates flush completion to McpServer's existing absolute writer budget. It emits only fixed MCP:<engine-code> diagnostics, at most32 per process, and allows at most1second for best-effort final diagnostic flush. It never closes/force-unlocks a live output publication in order to claim success. On nonzero return the installed executable must physically terminate its owned process without awaiting the live publication/gateway close again; normal EOF uses actual gateway/native cleanup. Bootstrap/discovery/installation remain T009, and accepting a concrete gateway here does not mint authority.
