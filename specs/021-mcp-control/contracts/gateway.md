## Components and admission

LocalMcpGateway.attach receives the actual authenticated portable McpClient and its generation-bound native PublicationGate from McpProcessBootstrap. The root uses WindowsMcpConnector and bundle4/descriptor2 of the already running application. Both configured and grantless modes retain this same connection. No caller role/app-root/transport/credential callbacks, process launch, writer lease, Isar/SSH/domain Host, arbitrary API proxy, reconnect or effect replay. Application Host remains owner of policy, operations and durable jobs.

Root startup owns actual client, gate, vault, retained identity and all failed/late attempts before awaiting them. It requires Ready/MCP, optionally performs one protected grant proof, then attaches the gateway only after native gate creation. Failed startup never becomes unconfigured fallback. The gateway retains only public grant expiry metadata and uses the EngineClock monotonic/UTC port; there are no runtime CLI timeout/role/provider overrides. Close is shared/idempotent and drains native/interest/actual publication work.

There is no autonomous unconfigured constructor. Without grant, valid tools/list returns tools:[] and valid tools/call returns fixed FORBIDDEN only after the same live application binding is established, with real native publication guards. An unavailable connection remains terminal and never pretends to be an empty live catalog. Missing app yields a local connector error without starting it. Gateway start after logical retirement uses SERVICE_UNAVAILABLE.

Maximum16 ordinary tool interests, including cancelled actual RPC/cleanup work, plus one fixed publication interest for the active writer/overload reply. Excess tools/call returns fixed RESOURCE_LIMIT with the same live native guard, and list uses a safe fixed service error. One shared client permits16pending RPCs with serialized writes/one reader; fixed liveness uses native proof without consuming a new RPC slot. Gateway tracks heartbeat/publication/cancel futures without detached effect queues. Cancellation waits one actual acknowledgement and never reissues it. Durable requestId/arguments are captured independently of external wire IDs.

## Standard method mapping

The pinned [official schema source](https://raw.githubusercontent.com/modelcontextprotocol/modelcontextprotocol/main/schema/2025-11-25/schema.ts) permits optional arguments and request metadata. tools/list accepts only optional object _meta; any cursor is invalid because this bounded catalog is one page and never issues nextCursor. tools/call requires nonempty name≤256codepoints and accepts optional object arguments (default{}), optional object _meta; task augmentation and other top-level fields are rejected -32602. Metadata is ignored, not forwarded/logged/reflected or treated as authority; no progress notification promise. Tool arguments remain subject to application Host's strict registered schema/scope checks. Generic method-shape validation precedes unconfigured fixed responses and never looks up a private object. Unknown forwarded method is -32601. Preserve original Unicode/scalars by encoding the bounded snapshot before any await; max256KiB/depth16 includes the external method parameters.

tools/list maps once to mcp.invoke{catalog:{}} and validates a catalog McpInvokeReply before returning its exact live tools. No bridge catalog or policy cache/filter. tools/call maps once to mcp.invoke{request:{name,arguments}}. Inline done returns exactly its validated McpToolResult; initial protocolError maps to -32602 without source echo. Pending stores that exact operation UUID; poll the same ID every250ms until done, cancellation or the35second monotonic invocation budget. Never restart request or substitute a durable ID. A poll may return pending only with the original UUID, or done with a valid result; other variants/mismatched ID are INTERNAL and retire the connection. A catalog returning any other variant is likewise INTERNAL. Cancel expects exactly cancelled:true. Typed parse/validation failure is fixed INTERNAL, no raw response/data diagnostic.

Every local admission/writer/response RPC stage is bounded by one5second outer budget, also capped by remaining35second invocation time or5second cancellation/publication budget. Waiting for an occupied local slot consumes that same budget. If a slot is full, wait only for tracked actual RPC completion, not a growing retry/effect queue. A timed-out already-admitted RPC closes the claimed client, observes its eventual completion and retires session interests; it is not reissued. The client retains native buffers through actual cleanup. Poll timers are cancellable and do not add a new35second window. A tool TIMEOUT leaves durable IDs/status queryable through a subsequent explicit authorized session/call.

## Fixed failures and stdout publication

McpGatewayFailure carries only existing ErrorCode: list maps to JSON-RPC -32000/fixed code, call to safe local McpToolResult.failure. Validated RPC code/retry advice is retained and public UNAUTHORIZED becomes FORBIDDEN; no arbitrary exception text/private IDs/input echo is added. All locally synthesized fixed RPC errors, overload errors, unconfigured empty/denied results and builtin/protocol frames require real gate plus fresh native verifyLive before stdout. No no-I/O callback exception remains. Fixed data needs liveness rather than grant-policy ping; every server-returned domain result (including domain failure) still requires full policy ping/expiry fencing. Unknown tool/schema is -32602. Validated remote/executor tool failures otherwise pass unchanged.

Extend McpInvocation with an optional trusted beforePublish callback and a matching afterPublish release callback, plus a synchronous validatePublication callback. Configured gateway always supplies all three. beforePublish retains its invocation-owned publication lease until afterPublish; McpServer invokes afterPublish in finally after success, guard/write failure or cancellation, and observes late guard completion so a timed-out acquire cannot leak a subsequently acquired lease. The engine retains and observes the original issued stdout write/flush future as well as the guard; a logical timeout never releases the gate while actual flush is live. Shared idempotent release completion remains charged through actual native cleanup. Logical exit2 stays bounded; installed executable terminal shutdown must close its owned stdio/process, with release only after actual flush settlement or confirmed physical transport termination. A never-settling actual write keeps the gate held until process termination/native abandonment, which remains fail-closed for mutators; no forced unlock or false successful mutation. The concrete gateway close immediately stops admission/retires interests, but never force-releases a publication-owned lease: that lease stays charged and observed until afterPublish following actual guard/flush settlement or confirmed physical transport termination. close shares and waits for these real cleanup completions; McpServer may bound its logical wait/report CLOSE_FAILED while native ownership remains held until actual cleanup/process termination. Late afterPublish and concurrent close use the same idempotent release, never two release attempts; physical release failure is terminal SERVICE_UNAVAILABLE, never false gate reuse. Every concrete LocalMcpGateway output supplies actual beforePublish/validatePublication/afterPublish callbacks, including fixed and grantless results. McpServer obtains gateway.protect for builtin/protocol frames with no existing invocation. Only RAM protocol doubles may use synthetic callbacks; they do not qualify runtime. The executable composes the actual gateway.

McpServer invokes the guard after serialized stdout writer wait and before issuing bytes, then synchronously validates current invocation/transport. Domain output performs fresh session.ping through the same client, validates exactly leaseSeconds60 and current server-bound grant tuple. Fixed/builtin output uses client.verifyLive under the same native gate, without permission refresh or another RPC slot. Neither grants a new scope or revision. No await follows the final current-interest check before stdout issuance; queued retired output is discarded.

Target identity changes also invalidate publication, even when the grant is unchanged. EngineSessions owns a conservative workspace-wide MCP target-change fence: beginTargetChange() synchronously blocks new protected MCP opens, then asynchronously acquires the shared native publication gate before detaching every existing MCP session or changing target identity. The returned future completes with an opaque, idempotently releasable lease only after acquisition and retirement; mutation code must await it before accessing/changing target identity. Fence intent alone is not a committed identity change; an already authorized publication may finish while that intent waits. Acquisition is bounded by the original5second owner RPC budget; timeout/failure makes no mutation and keeps old sessions retired once acquisition actually settles, with late leases released and actual work observed, not a detached mutator. No lock is forcibly released while its owning native work remains live; overlapping changes retain the fence until every lease settles. Owner sessions remain usable. A protected open checks the fence both before credential work and immediately before binding the grant; an in-flight open cannot escape retirement. A blocked protected open fails fixed UNAUTHORIZED and closes its attempted MCP session, using exactly the existing sealed failed-initial-open permit and its unchanged allowlist in operational-channel.md; no automatic retry. Check the fence before opening the grant key, so a blocked open performs no grant credential read/decryption. Test the exact terminal UNAUTHORIZED response, EOF/closed session and zero key access, not merely a thrown error. The owner service must hold the lease through commit/rollback and all identity/cache/read-interest invalidation, releasing in finally only after actual work settles, including failure. This applies to target deletion, connection identity/address/user changes, credential replacement/removal and host-key trust acceptance/replacement/revocation. Releasing the fence never revives old sessions or their queued data; a new explicit bootstrap is required. A failed mutation may therefore conservatively retire MCP sessions. This deliberate workspace-wide policy avoids gateway target-policy caches, result tokens, credentials or new wire methods. T109 implements and tests the registry/open fence; the original target/credentials/trust service tasks must acquire it before any such mutation, and product remote readiness remains false until those integrations pass. After fence acquisition/completion, an earlier publication has either finished issuing/flushing its stdout bytes or retired without issuing them; no successful buffered ping can authorize a later publication across that completed fence. A guard starting after retirement fails and replaces queued data with the fixed failure. A future connection cannot publish the former invocation.

The synchronization primitive is a separate same-user Windows named mutex, not the workspace owner mutex, held by a dedicated uninterrupted native worker stack across Dart awaits (as with existing MutexLease). Its name is Global\ServerDeckNext.v1.<sha256>, digest over UTF8 `serverdeck-next-publication-v1\n<ownerSid>\n<verified canonical bundle root>\n<generation>`; owner SID/root come from retained worker-verified native bootstrap, generation from that same authenticated session/registry. Both processes use identical encoding and Windows canonical root identity from bootstrap, never a caller-selected path/name/role or remote input. Owner-only ACL and actual acquire wait prove ownership; opening a handle does not. Native abandonment is fail-closed and closes affected session/workspace interests pending explicit recovery. No arbitrary external lock/configuration endpoint. The gate is separate from private pipe I/O workers, so holding it cannot block the ping that proves current authority. No generic injectable mutex callback qualifies production acceptance.

The bridge acquires this gate after stdout writer acquisition and before its fresh ping, holds it through the final identity/expiry check and actual stdout write/flush, then releases in afterPublish. Every owner mutation that can invalidate published data or authority (grant replace/revoke, target identity/access/trust change, operational storage shutdown/recovery) acquires the same gate before its committed change/retirement, and holds it through durable commit, authority/snapshot notification and actual invalidation. Existing temporary store authority gates stay in force. Mutation admission may mark intent early, but success/visible committed revision occurs only inside this gate. A successful ping buffered in the pipe remains safe because its publication owns the gate: the mutator cannot commit until publication releases, or the bridge fails/terminates and native cleanup releases it. A blocked stdout still uses the original single5second budget, never makes mutation wait indefinitely, and already-issued bytes keep their established irrevocable semantics. No service mutation may await a bridge-owned ordinary RPC while holding the gate. Heartbeat/poll/open do not acquire it. Before the final synchronous stdout issue, the gateway validatePublication callback additionally checks its bound grant expiresAt against current UTC and local client/interest state with no await before issuing bytes; it never extends expiry. Timer/detach handles expiry/native loss normally. Startup binds the gate to the native generation; restart never reuses an old gate.

Guard plus actual flush share the existing single5second writer budget from acquisition of that writer, not two new windows. A fixed guard failure replaces the queued response with a fresh safe failure (list -32000/code; call tool failure, local/retry none), discards its old data, and writes only within remaining budget; unknown failure maps INTERNAL. Timeout/I/O failure closes stdio with fixed diagnostic/exit2 and no retry. Recheck identity after the guard even if another wire request reuses the same external ID. Local protocol/timeout/overload errors also require the live native fixed-response guard; no-op guards are forbidden. Failure of fresh native proof stops stdio without output. A domain-policy/expiry error can precede any proof or lease. Before fallback, settle/release its original publication with no issued stdout, then obtain a separate fixed gateway.protect interest with fresh gate+verifyLive. Do not reacquire while the original lease is held. Use the same original writer budget; failure stops without output and no recursive fallback. The replacement lease follows actual flush settlement. The35second deadline bounds producing the invocation result; stdout queue/flush keep their separate existing bounded transport semantics. Already-issued stdout bytes cannot be unsent.

## Cancellation, heartbeat and close

Each invocation exposes one shared cancelInterest completion, created before callbacks. Cancellation marks interest retired/stops poll scheduling immediately and suppresses any late result. If its initial RPC is still in flight, wait for that actual single acknowledgement within the original5second cancellation budget, recording any returned handle before signaling settlement. If a handle exists, send one mcp.invoke cancel for it; never jobs_cancel. Inline completion/catalog has no remote handle to cancel. If cancellation cannot establish/retire its admitted interest within budget, close the client/session; do not launch late detached cancels or assume a durable job was cancelled. Wait for a needed local slot only within this same budget. Repeated cancellation shares the original attempt, no extra cleanup operations or capacity. Actual unfinished RPC/cleanup remains charged until settled or confirmed native client close; completing the wire interest alone does not free capacity.

One nonoverlapping heartbeat every20seconds sends session.ping when a native slot is available; skip a full-slot tick (admitted requests already renew the60second lease), no heartbeat queue. Validate leaseSeconds60. Any failure except a pre-I/O local RESOURCE_LIMIT retires this configured gateway/client without reconnect; heartbeat/publication never grant new authority. Close cancels heartbeat/poll timers, stops admission, retires every invocation interest and closes the native client once. Closing that client is not proof that a stdout publication has physically ended: publication leases follow the separate actual-flush/afterPublish lifetime above. It need not sequentially send cancels for each handle when dropping the entire session; server detach owns interest cleanup, durable jobs remain. Concurrent/reentrant close shares its completion, including physical cleanup failure; late results cannot revive it. No remote wait or unsafe cancellation of running jobs.

serveMcpStdio(LocalMcpGateway, McpStdioPort). The port is mandatory: no direct
stdin/stdout/stderr or nonBlocking IOSink compatibility path remains. The same
serverdeck.exe's future T274 headless branch owns the private native carrier;
this composition never starts the desktop application or mints domain authority.
It requires an already live main application, including tray mode.

The pinned SDK can emit its own stdout logs, and its ordinary Stdout.add can
block the Dart isolate. A Future wrapper or flush.timeout cannot make that
synchronous call cancellable. The required carrier therefore captures original
inherited handles before SDK initialization, isolates SDK logs from the MCP wire,
and performs blocking native I/O outside the platform/Dart thread. Its write
future completes only after all frame bytes are actually written, not queued.
McpServer retains the publication lease through this physical completion, under
its unchanged absolute5second writer budget. Logical timeout does not wipe a
still-used frame or release that lease. Native close must acknowledge actual
cancellation/drain and handle disposal; no logical-close success or force-unlock.

ownership, fixed error sanitation and no-UI binding are specified in the T313

codes with at most32 operations per incarnation and one diagnostic pending,

actual gateway/connector and then carrier, whose confirmation is bounded by5s.
