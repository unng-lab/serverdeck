# Operational Local API 1.1 authentication

[MCP](mcp.md), [bundle](bundle.md), [credentials](client-credentials.md), [tasks](../tasks.md).

## Shared wire and responsibility

The operational handshake is a separate strict protocol in packages/serverdeck_protocol/lib/mcp/handshake.dart. Legacy API1.0 models, parsers, transcripts and SessionRegistry remain unchanged and cannot parse these messages. Product activation still requires the complete T004/T006/T008 composition; adding these models never selects a bootstrap/runtime mode. Use the existing little-endian length-prefixed framing, StrictCodec duplicate-safe UTF8 parser, 8192-byte handshake bound and single absolute5second authentication deadline. All named fields below are required, extra fields rejected, integer literals must have integer runtime type. All DTOs snapshot lists before validation, expose immutable values and serialize fresh maps. Public malformed wire errors are FormatException('VALIDATION'), without private input/provider text; role/version/build mismatch at authentication maps to fixed INCOMPATIBLE or UNAUTHORIZED as below.

OperationalRole is exactly owner|mcp, independent of Windows/native types. It is a wire value, not authority: the server adapter obtains the role only from an OperationalPipePeer of this accepted connection, and clients require a locald peer plus their own verified image role. No JSON-supplied role can construct a native peer or authorize a session. Protocol validation cannot establish identity. Local API envelope version v:1 remains the framing envelope version, distinct from apiMajor:1/apiMinor:1.

## Exact bootstrap messages

Server sends exactly `{hello:{product:"serverdeck-next",apiMajor:1,apiMinor:1,workspaceSlot:"default",generation,serverNonce,buildId,clientRole}}`. generation is canonical UUIDv4; buildId follows the existing lowercase SHA/configuration build grammar; clientRole is the server's verified owner|mcp peer role. Nonces, proofs and session IDs are canonical unpadded base64url of exactly32bytes, including zero unused padding bits. Server generates fresh serverNonce for every accepted physical connection, never user-chosen/reused. Client checks discovery generation, own verified buildId and own verified role against hello before signing; the locald native proof is revalidated around all awaits.

Client sends exactly `{authenticate:{clientNonce,clientBuildId,requestedCapabilities,proof}}`. clientNonce is independently generated random32bytes. No role field. requestedCapabilities is exactly ["owner"] for owner or ["mcp"] for mcp; sorted/unique lists, no negotiation, unknown/mixed/empty values refused. These are role dispatch gates, not ClientGrant scopes. The operational owner UI has owner operations; MCP gate allows only readiness.get, session.ping, session.close, mcp.open, mcp.invoke, mcp.close. Existing owner methods and new owner management methods cannot be reached through mcp. ClientGrant author/read/logs/plan/apply policy remains an additional independent gate. Operational API1.1 does not offer the legacy arbitrary requested capability subset.

Server sends exactly `{authenticated:{sessionId,clientRole,capabilities,idleLeaseSeconds:60,proof}}`, with the same role/capabilities, fresh random sessionId and server proof. Client must verify exact equality with its request and expected own role, not just a subset. Never reuse an authentication attempt/challenge after failure, timeout or success. Repeated hello/authenticate closes the channel. Unsupported API/build is INCOMPATIBLE; malformed, invalid proof/role/capability, stale identity or replay is UNAUTHORIZED. Neither failure creates a session. Handshake failure closes its token copy and channel; no diagnostic includes input. Native disconnect/reaccept requires a new handshake instance.

## Exact bootstrap transcripts

All transcripts are bytes from StrictCodec.canonical of the specified object; object key order on the wire is immaterial. No newline concatenation, optional field, caller text or alternate encoding. HMAC-SHA256 uses the32byte bootstrap token; compare all32bytes without early content-dependent exit. Encoded proof is canonical unpadded base64url. Temporary owned token/key/transcript buffers are wiped/destroyed; no raw token in DTOs/logs. Shared pure functions return transcript bytes only, never perform signing or expose a MAC endpoint.

Client transcript is exactly `{purpose:"serverdeck-next-bootstrap-client-v1.1",product:"serverdeck-next",apiMajor:1,apiMinor:1,workspaceSlot:"default",generation,buildId,clientRole,serverNonce,clientNonce,requestedCapabilities}`. Server transcript has purpose "serverdeck-next-bootstrap-server-v1.1" and all those fields plus `{sessionId,capabilities,idleLeaseSeconds:60}`. requestedCapabilities and capabilities must both be the exact singleton for clientRole. Different purposes prevent reflection; changing generation, version, image role, build, either nonce, session or capabilities invalidates the proof. Proof fields themselves are never part of a transcript. Legacy newline/API1.0 proof cannot authenticate API1.1 and vice versa.

## Session and live peer gates

Operational session registry in locald owns immutable generation/channel/sessionId/verified role, fixed capability singleton and original serverNonce; role is set only by the native adapter. Max8 total live sessions including at most4 mcp sessions; pre-auth channels are bounded by the existing8 native slots, never an unbounded pending registry. Register only after final peer revalidation and before response; registration failure/response failure disconnects the new session. Lease60seconds, ping20seconds, max16 in-flight per session; expire at now >= expiry, remove once and cancel outstanding read interests. No session resurrection on ping, queued completion or clock callback. Owner and MCP count against the same pool. Readiness cannot reveal owner data to an MCP session. Role is checked before method parsing/object lookup; unknown/nonpermitted owner method through MCP returns FORBIDDEN without side effects. Closed/stale/wrong channel/session/generation returns UNAUTHORIZED. Session close/mcp.close drops interests, not admitted durable jobs.

Adapters hold one OperationalPipePeer for the accepted physical connection and revalidate before and after every handshake, MAC/credential and dispatch await, before registration, before publishing a response, and before admitting each durable mutation. An after-await failure discards results, disconnects registry/channel, and cannot relabel a reused pipe. All later live-policy/effect checks remain mandatory. Server handshake consumes at most one client authenticate. Close during await prevents later registration; registration and final result publication are guarded synchronously in the owner isolate. Neither a public protocol enum nor bootstrap-token possession establishes owner authority.

## Grant authentication after bootstrap

Only mcp role can call mcp.open, once per bootstrap session. Request is exactly `{grantId,clientNonce,proof}`; UUIDv4 grantId, fresh random32byte nonce and canonical32byte proof. It is separate from bootstrap clientNonce. Server uses the immutable bootstrap serverNonce/sessionId and loads the current retained grant and private client key through validated operational storage/file custody. No revoked/expired/stale revision is accepted. Request proof transcript is exactly `{purpose:"serverdeck-next-mcp-open-client-v1.1",product:"serverdeck-next",apiMajor:1,apiMinor:1,workspaceSlot:"default",workspaceId,generation,buildId,clientRole:"mcp",sessionId,serverNonce,clientNonce,grantId,secretRef}`. secretRef is current UUIDv4, obtained from protected current lookup on bridge and committed grant on server; it is not accepted as authority from request fields. The protected lookup deliberately has no revision; the bridge does not guess one or read Isar. Replacement always rotates secretRef/key, even after multiple replacements. A stale lookup fails, never silently chooses a previous key. HMAC uses ClientKey, not bootstrap/SSH/receipt keys.

Success result exactly `{workspaceId,grantId,revision,expiresAt,proof}`. expiresAt is current canonical UTC-millisecond grant expiry. Server proof uses the same object as client transcript with purpose "serverdeck-next-mcp-open-server-v1.1" and adds `{revision,expiresAt}` from the current retained grant; revision is a positive integer at most2147483647 (the existing ClientGrant revision bound). Bridge obtains revision only from this result and verifies the server MAC covering it, expiry and all expected bindings before using the open session. Grant binding immutable {workspaceId,grantId,revision,secretRef} is installed only after proof and fresh peer/current grant checks after await; no second mcp.open, changing grant or replacement on the same bootstrap session. Any failed open closes the session, releasing its quota; bridge may keep its external stdio lifecycle alive with empty tool list/FORBIDDEN. Reconnect is explicit, never automatic after generation change. Wrong/revoked/expired/missing/replaced grant or invalid proof yields UNAUTHORIZED uniformly; unavailable protected store yields STORAGE_BLOCKED, both close local session. No existence oracle. mcp.close is an idempotent close of the current session, never credential revoke. Every invoke/poll/result/effect rechecks current revision/scope/target/expiry/revocation; replacement/revoke makes existing binding unusable immediately and drops cached interests. Grant-derived cached result must not survive that gate. This binding does not replace approvals/delegations.

## Implementation and acceptance

### Grant-open service composition

T086 uses one OperationalMcpAuthority per workspace/locald generation, owned by the service composition, with the existing operational StateStore as current metadata/key source. Store auth reads require live held lease/current owner/receipt-key custody and settled operational authority before lookup. In-progress grant publication refuses auth with STORAGE_BLOCKED without converting that temporary unavailable gate into permanent corruption. An observed receipt-key/file/key custody failure latches storage blocked; missing/revoked/expired/replaced grant is UNAUTHORIZED without blocking an otherwise healthy store. Referenced key reads recheck the same grant tuple/current lifetime after their await and dispose any stale key; no key getter/export route is added to Local API/MCP. Server key work is trusted internal storage service only.

OperationalSessionRequest admits open only for its native-bound mcp role and mcp.open method, consumes its session's one attempt before any credential await and installs the immutable binding only after both proofs and final peer/current-grant checks. Before open, mcp.invoke is FORBIDDEN. After open every request liveness check/revalidation and authorizeMcp scope/target check consult the bound authority/current tuple; invalidated bindings detach session/read interests before any cached result publication. Owner role cannot open a grant; role checks precede parsing caller payload. The ordinary Local API envelope v:1/id/sessionId/method/params and matching response id/generation are used for mcp.open; no raw challenge side channel. Client open is in Windows operational_auth_client.dart, gets only protected readForBridge binding/key (no revision), generates fresh nonce and validates the exact signed result/correlation/expiry around native peer awaits. Its key closes on all exits and it never reconnects/retries an open automatically.

Open has one absolute5second RPC deadline including request admission, file/key/MAC work and result checks, separate from the bootstrap deadline. Each authority has at most4 admitted open work units; deny excess RESOURCE_LIMIT before any file/key work. A timeout, disconnect or expiry detaches caller interest promptly but cannot release that work unit or leak a late-created key: owned work keeps its slot until its actual file/MAC futures settle and finally disposes its key. No unbounded detached opens or cancellation-created capacity. Closing authority denies new work and late bindings, not admitted durable jobs. Tests use actual same-format2 PE/native pipe/Isar/CurrentUser DPAPI for open after multiple replacements, all retired credentials/replay/expiry/revoke/current-policy/close/error cases; controlled awaited custody scheduling may additionally prove deadline/late cleanup/pool behavior without substituting for that native acceptance. These service/helper tests do not close full startup/router/UI/bridge/external-client/VM integration gates.

Native integration uses Windows operational_auth_client.dart for bounded epoch-bound handshake framing and the one-attempt client bootstrap; locald api/operational_auth.dart with operational_sessions.dart owns server bootstrap/private registration and role-aware request interest. The native OperationalPipePeer additionally carries immutable localRole from its worker's retained self proof, rechecked with role/build/epoch on verification; the client has no caller-selected expected role. Server consumes bounded input copied before its first authentication await. Registration is private to the native-backed server handshake. The enclosing channel must deliver the authenticated response under the same absolute handshake deadline, close/detach on delivery or subsequent IO failure and revalidate request interest around all dispatch awaits; standalone bootstrap/session helpers do not install a product router, perform mcp.open or activate the compatible bundle. An MCP bootstrap session has no ClientGrant authority. Native tests of these helpers must not be reported as full T086 or product acceptance.

T085 implements the shared strict immutable DTOs and transcript builders only, with independent canonical/HMAC test vectors, every bound field, canonical nonce padding, grant revision boundaries2147483647 accepted/2147483648 rejected, malformed/unknown/duplicate/oversize wire and reciprocal legacy refusal. Types have no Windows/storage/crypto signing dependencies and never issue identity/session authority. T086 composes native proof, server/client handshake and immutable role-aware session registry, explicit owner/MCP dispatch gate and mcp.open current protected key/grant policy; it must cover actual owned PE/kernel-pipe roles and grant replay/expiry/revoke/replacement/concurrent-close/quota/await cases, including actual bridge lookup with no revision after multiple replacements, successful current secretRef/key open and refusal of every retired secretRef/key, not qualify authentication with protocol roundtrips alone. Existing API1.0 tests remain intact. T006 remains open until integrated T086 plus compatible startup/build/schema2; final actual external clients/VM acceptance remains mandatory.
