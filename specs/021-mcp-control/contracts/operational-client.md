# Operational Local API client — 021 API1.1

[Handshake](handshake.md), [channel](operational-channel.md), [MCP bridge](mcp.md), [tasks](../tasks.md).

## Responsibility and exclusive ownership

`packages/serverdeck_windows/lib/operational_api_client.dart`, part of `operational_auth_client.dart`, implements OperationalApiClient over an actual OperationalClientSession from the native1.1 bootstrap. It does not accept caller-provided raw transport callbacks, roles, generation or credentials, select bootstrap mode, launch locald or connect to servers. It is usable by the owner UI and MCP bridge; their method authority remains server-enforced. Legacy client/bootstrap and API1.0 remain unchanged.

Construction claims one ordinary-RPC reader/writer owner on that exact session. Closed/already-claimed sessions fail local SERVICE_UNAVAILABLE before I/O. A started protected open with no successfully assigned grant is also refused before claim/I/O; this refusal must leave that original open intact. For MCP, protected `session.openGrant` finishes before attachment when configured; after attachment direct openGrant is refused SERVICE_UNAVAILABLE before I/O without disturbing its owner. The claim is one-way; never attach a replacement reader after close/failure. Direct public peer access remains a trusted internal primitive, not an external tool; production composition must use the claimed client exclusively. Closing either the bootstrap/session or client invalidates that same transport. No session/key clone or alternate role is minted.

MCP executable/gateway, discovery, heartbeat and grant configuration remain T009/T086/T104; adding the client does not install them or activate any readiness capability. Owner adapters remain T010. Unconfigured or failed grant behavior follows the bridge contract, not this general RPC client.

## Calls, buffers and authority

`call(method, params)` returns a fresh immutable result object, or OperationalRpcException containing an existing validated ErrorCode, optional validated field and OperationalRpcFailureOrigin enum local|remote|transport, with fixed safe toString. local means pre-I/O constructor/input/admission rejection; remote means a validated correlated Local API error; transport means terminal framing/native/deadline/explicit-close failure. The terminal getter is true exactly for transport. Its LocalError/retry mapping is unchanged. It never returns an unvalidated error string, raw frame, peer or key. Identical SERVICE_UNAVAILABLE/TIMEOUT codes are distinguishable by origin: a remote error fails only its call; transport failure retires all calls and denies further use. Direct session.openGrant retains its existing StateError interface and rejects post-claim use before I/O.

Client exposes read-only pendingRequests and isClosed plus done, the single physical-cleanup completion shared with close(). isClosed becomes true before pending callers are retired; done completes only after native cleanup and may fail SERVICE_UNAVAILABLE. The completion exists before any cleanup callbacks and is observed internally even without a caller listener; no unhandled late failure. These state observations confer no role or policy authority.

Generate independent random UUIDv4 correlation per call, never caller-selected and never substituted for a durable requestId in params. Snapshot/encode the complete v/id/sessionId/method/params envelope synchronously before the first await using the Unicode-preserving MCP encoder. Method must be nonempty at most256codepoints; exact envelope/request limit256KiB/depth16 applies. Invalid local input returns VALIDATION without native I/O or closing other calls. Preserve original Unicode/scalars and all durable mutation IDs.

At most16 pending calls including queued writes and replies; excess returns RESOURCE_LIMIT without allocation/start/closing admitted calls. One writer serializes complete uint32LE length+payload frames; at most16 bounded frames are retained, no separate unbounded queue. No arbitrary caller write path. Every write uses only the remaining original RPC budget and the retained native peer checks. A completed write may leave buffered output as defined by the server channel; client close makes no delivery/replay promise.

One reader collects exactly a4byte length then payload, reading chunks at most64KiB, response at most8MiB/depth16. Empty/oversized/partial/invalid UTF8/duplicate fields/invalid envelope fail closed. One bounded response buffer plus native chunk and the16 bounded request frames; no unsolicited response/event cache. Response v/id/generation and result/error schema are validated. Require exact current session hello generation and a currently pending UUID; unknown, duplicate-completed or foreign correlation/generation closes without delivering data. Responses may arrive out of order and complete only their exact pending call. Native peer read/write revalidate the retained self/locald identity and epoch; no client-side Isar/current-policy cache replaces the server's checks. Synchronously recheck client/session ownership and original deadline before delivery, after decoding/freezing bounded data.

## Deadlines and teardown

Each admitted call has one absolute5second monotonic budget from before encoding/admission through writer wait, actual native write, response collection/decoding and delivery. One timer per pending call closes the entire connection on expiry, fails all pending futures once with TIMEOUT, cancels their timers and drops queued frames. Never retry or reconnect, regenerate a reply or replay an effect. Late native completions cannot deliver to another caller or revive a closed client. Remote normal Local API errors fail only their correlated call and preserve the connection.

Idle response read at most60seconds; after first frame byte use one absolute5second partial deadline, never refresh on fragments. An earlier pending-call timeout still closes/cancels this native read. Native timeout maps TIMEOUT; identity/schema/correlation failure maps UNAUTHORIZED; other native/worker failures map SERVICE_UNAVAILABLE. Admission RESOURCE_LIMIT is nonterminal; unexpected native quota exhaustion is a terminal transport failure rather than permission to interleave/retry. No input/path/exception text in errors or normal diagnostics.

Explicit `close()` publishes one shared completion before retiring the session/failing pending callers SERVICE_UNAVAILABLE and cancelling timers. Concurrent/reentrant close observes that same future, including failure. It closes the owned client PipeWorker and waits for actual native cancellation/buffer cleanup; it never calls the server-only peer disconnect or claims server slot reuse. Native close failure leaves the client terminal and its close completion failed SERVICE_UNAVAILABLE. EOF/auth/native/malformed/deadline termination uses the same cleanup; no orphan reader, timer or unobserved late result is allowed. Durable transactions/jobs remain service-owned and are never cancelled by closing this transport.

## Required evidence

Actual same-format2 PE/native pipe/Isar/CurrentUser DPAPI tests must use the production client against OperationalApiServer/Channel: protected open then attach, owner/MCP role enforcement, exact Unicode/integer result and fixed errors followed by healthy calls,16calls/17th admission refusal, out-of-order replies, input snapshot, same session double-attach/direct-open refusal, remote/session close and concurrent client close. Compare the same SERVICE_UNAVAILABLE and TIMEOUT codes from validated remote replies versus native failure/actual deadline: origin/terminal differ, remote failure preserves the next successful call, transport failure retires every pending call and denies the next call. Controlled native-backed peers additionally send wrong generation/id, duplicate/malformed/oversized/fragmented response, EOF and delayed response beyond actual5second budget. Verify every pending future retires, no late publication/replay, failed client cannot reattach, native child/handle cleanup and legacy preservation. These prove transport/authority composition, not remote effects, installed startup or full external MCP acceptance.
