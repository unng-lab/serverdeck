## Client credential custody

Client secret32 CSPRNG bytes exists only locald/bridge bootstrap custody under CurrentUser DPAPI, stored as protected blob alongside grant transaction, never returned by tools or normal UI reads. Exported client config has absolute verified MCP executable and --grant-id UUID only. Bridge resolves protected credential internally and proves possession in mcp.open against locald nonce; no secret argv/env. Same-user unrestricted process compromise is outside OS threat boundary, same as existing DPAPI. This is client configuration scoping, not a sandbox against a hostile fully privileged same-user agent.

## Review correction — exact profile authority

Execution identity is the tuple `(profileId, revision, bodyDigest)`; body digest alone identifies content, not permission. Delegation entries contain all three, unique by profileId/revision. Plan digest includes all three; job/approval persist that tuple through the immutable plan, jobs also keep indexed copies checked against plan. Admission and every fresh step authority check compare the complete tuple. New revision with identical body, metadata-only update, another profile with same body and forged tuple mismatches never reuse prior authority. Historical running jobs retain the originally approved tuple; head changes do not rewrite it or auto-revoke that exact still-valid authority (explicit revoke/archive policies apply separately).

## Workspace-only author grants

Grant scopes subset{author} (including empty default-deny scope) has `serverIds:[]`; nonempty targets rejected for this mode. If any server scope read/logs/plan/apply is present, serverIds must list1..250 unique existing permitted server profiles. Author does not imply read and never exposes servers. Owner may grant author in an empty workspace. Adding target scopes later is explicit owner grant replacement with credential rotation/revision invalidation; no implicit wildcard or future-server inheritance. Delegations always require nonempty explicit targets and apply/plan/read scopes.

## DTO wire details — implementation021

ClientGrant additionally persists/publicly exposes required `issuedAt` UTC milliseconds for the current credential issuance. createdAt remains immutable original creation. Create sets issuedAt=createdAt; explicit owner replace retains createdAt, increments revision/rotates secretRef and resets issuedAt plus expiry5min..30days/default8h from replacement. An expired nonrevoked grant may be explicitly renewed; revoked is permanent/newID. Revoke preserves issuance/expiry and increments revision. Shape validation requires createdAt<=issuedAt<expiresAt and revokedAt>=issuedAt where present; current checks require issuedAt<=now<expiresAt and revokedAt null. Initial revision1 has issuedAt==createdAt. Snapshot history checks original create receipt against createdAt, current replacement against issuedAt, revoke against revokedAt and all grant revision acknowledgements. Missing issuedAt fails closed: automation schema2 has not shipped and no active compatibility fallback is introduced.

ClientGrant and Delegation persist required workspaceId with the fields in the entity table. ClientGrant.createdAt/expiresAt are strict UTC millisecond timestamps; historical expired/revoked records remain readable as history, not current authority. Delegation creation/expiry validation is evaluated against the current grant and issuance time supplied by the owner coordinator; issuedAt is not accepted from MCP. A missing/foreign target reference fails owner admission rather than being added automatically. Public grant views omit secretRef; custody never appears in MCP output.

Parameter predicates use exactly `{type:"enum",values:[...]}` or `{type:"integer",minimum,maximum}`. Integer bounds are0..1000000 inclusive and min<=max. Enum has1..32 unique same-type public scalar values (boolean, bounded integer, or NFC string<=4096characters); strings may contain LF/TAB public text, but no other control/NUL or template tokens{{,{%,{#. Maximum32 named predicates, names use the profile parameter identifier grammar. Enum mixed types/coercion/regex/additional fields are rejected. Effective resolved parameters, including defaults, must have exactly the same keys as predicates: absent/extra unconstrained values never match a delegation. Owner must inspect/approve that complete set or use a one-plan approval. JSON body/input byte/depth limits still apply. This closes the wire representation of the existing exact enum/range requirements, not a new executable parameter type.
