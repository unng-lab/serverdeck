# Состав сервиса и границы расширений

Полное описание сервиса, обязанностей, жизненного цикла и первоначального результата находится в [001 — Основа сервиса](001-service-foundation/spec.md). Это общий указатель, не 21-я спецификация и не отдельный MR.

ServerDeck состоит из пользовательского клиента и локальной службы текущего пользователя. Клиент ведёт интерфейс и согласие. Авторизованный Local API соединяет его с единственным locald пространства. locald владеет защищёнными данными, credentials/trust, SSH-чтением и координацией заданий. Первая реализация Windows читает существующий Linux-хост напрямую; облачный backend и privileged installer для этого не требуются.

001.1 создаёт исполняемый каркас с защищёнными профилями. 001.2 даёт реальный маршрут подключения и чтения. 001.3 закрывает lifecycle/recovery и fixture основу jobs. Нельзя заменить этот результат библиотекой хранения или demo UI. Защита включена с первого сохранения, а не добавляется после него в 002.

002 расширяет integrity/recovery защиты. 003/004 развивают интерфейс уже существующего продукта. 005 поставляет совместимые клиент/службу. 006 впервые подключает ограниченный настоящий executor и host-side механизм, подготовленный администратором. Остальные серверные модули используют эту исполнительную границу. Только 020 добавляет отдельный backend; он не исполняет SSH-задания и не владеет локальной БД.

| Пакет | Расширяемые компоненты | Ответственность |
| --- | --- | --- |
| [001](001-service-foundation/spec.md) | Клиент, locald, Local API, store/custody, SSH, jobs | Определить и создать сам сервис с первым реальным результатом |
| [002](002-security-storage/spec.md) | locald, защищённое хранилище и provider защиты ОС | Основной владелец данных уже создан в 001. Этот пакет расширяет проверку охвата/индексов/полноты, recovery и платформенные failure gates; UI получает безопасный статус, не ключ. SSH, executor и backend для проверки хранения не нужны. |
| [003](003-design-system/spec.md) | пользовательский клиент и общая визуальная система | Расширяет базовый UI 001 с сохранённым брендбуком. locald/Local API/модель состояния не заменяются; UI не получает прямой доступ к БД или SSH. Полировка не является условием существования первоначального сервиса. |
| [004](004-server-workspace/spec.md) | пользовательский клиент, connection orchestration и наблюдения locald | Развивает уже работающий маршрут 001: компактные карточки, guided connect и контекстные переходы. Использует существующие авторизованные запросы/подписки, не создаёт второй транспорт или новую БД. |
| [005](005-client-distribution/spec.md) | упаковка клиента и locald, клиентский updater, readiness/shutdown службы | Поставляет вместе совместимые компоненты 001; не заменяет их разработку installer-ом. Startup и состояние базы принадлежат locald; update проверяет его безопасный shutdown. Production Windows gate требует защиты 002; другие платформы имеют собственную приёмку. |
| [006](006-software-installation/spec.md) | каталог рецептов и job coordinator locald, ограниченный executor и host-side исполнение | Первый интегрированный путь настоящих записей расширяет fixture основу 001. locald владеет планом/approval/events, executor выполняет только одобренный вариант, хост удерживает физическую блокировку/квитанцию. Privileged runtime заранее подготовлен администратором; чтение его не устанавливает. |
| [007](007-software-adoption/spec.md) | read-only SSH адаптеры и registry locald, UI регистрации | Читает доказательства существующей установки, сохраняет локальную связь через тот же защищённый владелец состояния. Host-side installer не нужен; никакой запуск/repair/изменение ПО не добавляется в inspection. |
| [008](008-fleet-workspace/spec.md) | inventory/capability модель и registry locald, общий поиск клиента | Расширяет базовый инвентарь 001: типы/экземпляры/сводный поиск. Registry отделён от observation cache внутри одного пространства. Открытие возможности не готовит runtime на хосте. |
| [009](009-observability/spec.md) | read adapters, subscriptions/buffers и наблюдения locald, UI журналов/метрик | Базовые журналы/метрики уже работают в 001. Пакет добавляет источники и историю в его resource budget. Исходный lifecycle сборщика — locald с активным клиентским интересом; непрерывный сбор после закрытия UI не заявляется без отдельного явно принятого варианта. |
| [010](010-system-service-management/spec.md) | адаптеры systemd/системы, job coordinator/executor, UI управления | Чтение поступает через locald. Изменение службы, настроек или питания использует единый plan/approval/lock, права и declared host action. Нет второй очереди/daemon-а для кнопок службы. |
| [011](011-access-management/spec.md) | read adapters аккаунтов/сессий, coordinator/executor, credentials provider и UI | Доступные сведения отделены от privileged изменения. Пароль хранится/передаётся в защищённой границе, а не event/log payload; locald повторно проверяет сохранность пути управления до эффекта. |
| [012](012-backup-recovery/spec.md) | управление расписанием и метаданные locald, серверный планировщик/executor, выбранное хранилище | Копируются данные сервера в выбранное хранилище. Сервер исполняет расписание и сохраняет результаты независимо от клиента/locald по ограниченному серверному разрешению; locald настраивает и читает результаты. Отзыв SSH-доверия не выдаётся за остановку расписания. Копии не находятся в основной БД; полного DR машины нет. |
| [013](013-files-diagnostics/spec.md) | ограниченный файловый/диагностический адаптер locald, executor записей, UI просмотра и явного получения файлов | Обычное чтение ограничено и не запускает shell произвольного ввода. Файл передаётся в выбранное пользователем назначение; правка/удаление идут через план и конфликт исходной revision. Отчёт — результат процедуры и явный экспорт, не автоматическая отправка backend. |
| [014](014-software-maintenance/spec.md) | адаптер пакетов и каталог поддержанных переходов locald, coordinator/executor | Реестр источников/версия/compatibility входят в согласованный план; инструменты пакетов запускаются на хосте в ограниченной исполнительной границе. Product update 005 и remote software update различаются. |
| [015](015-storage-management/spec.md) | адаптер устройств/томов locald, coordinator/executor и UI зависимостей | Сведения хранятся как наблюдения; destructive операции имеют data scope/backup gate. Не создаётся собственный storage controller, обходящий host-wide writer или принятые средства ОС. |
| [016](016-network-management/spec.md) | сетевой read adapter locald, coordinator/executor и host-side механизм возврата доступа | UI не правит сеть напрямую. Операция привязана к поддержанному варианту и verified rollback/independent access; защита NetBird действует во всех модулях и формах. |
| [017](017-compute-management/spec.md) | адаптер поддержанной среды контейнеров/VM locald, coordinator/executor | Использует существующий объявленный runtime хоста; отсутствие runtime не запускает установку автоматически. Контейнер/VM/сеть/том имеют отдельную identity/data scope, state observations и проверенный результат. |
| [018](018-security-controls/spec.md) | сбор security evidence и policy evaluation locald, отдельно разрешённый executor исправлений | Проверка политики read-only; remediation — отдельное согласие/job. Чувствительный сбор объявляет место, права, срок и lifecycle; backend ничего не получает автоматически. |
| [019](019-specialized-capabilities/spec.md) | встроенный capability catalog/адаптеры locald, UI модулей и ограниченный executor | Дополнительный модуль расширяет определённый компонент 001 и не загружает произвольный исполняемый plugin. Новые runtime/prerequisites объявлены до включения; HA read-only и image build не получают полномочия failover/reinstall. |
| [020](020-metadata-sync/spec.md) | sync coordinator locald, UI opt-in, отдельный backend авторизации/метаданных | Первый пакет с обязательной интеграцией backend: separate public repo, own authorization/revisions, без SSH executor. Locald остаётся владельцем локального состояния, secrets/trust/approval не синхронизируются; отказ backend не блокирует core 001. |
