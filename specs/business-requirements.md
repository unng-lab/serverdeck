# Бизнес-требования новой реализации ServerDeck

**Baseline**: hard cutover, 2026-10-10. **Stage**: Spec Kit Specify.

Продукт помогает владельцу уже существующих Linux-серверов находить проблемы и выполнять поддержанные изменения с понятными последствиями. Доступ напрямую по SSH, локальная работа без обязательного облачного аккаунта. Первая клиентская платформа Windows, первая среда изменений Ubuntu 24.04 amd64/systemd.

## Правило замены сервиса

Первая установка новой реализации создаёт пустое пространство в отдельной области данных и с собственной идентичностью локального сервиса. Данные, credentials, доверие, задания и настройки старого ServerDeck не импортируются. Нет мостов миграции, старого API, автоматического fallback и обязанности предварительно мержить старые MR. Старый runtime и его файлы не удаляются этой спецификацией.

Сохранение истории старых документов не требуется: старые планы, задачи, контракты и evidence исключены из рабочего набора. Это не отменяет долговечной истории новых заданий и сохранения данных при последующих обновлениях новой реализации. Существующие базы и программы на удалённых серверах сохраняются; чистая установка и безопасная регистрация остаются разными действиями.

## Сам сервис

[001 — Основа сервиса](001-service-foundation/spec.md) определяет продукт целиком, обязательные компоненты, границы владения, Local API, bootstrap/readiness/shutdown/recovery и первый исполняемый результат. [Карта компонентов](service-overview.md) связывает все функциональные пакеты с этой основой. Ни хранение, ни экран профилей по отдельности не считаются сервисом.

## Управление требованиями

Этот документ — общий каталог, не отдельная 21-я спецификация и не один большой MR. [20 пакетов и порядок](README.md), [владельцы требований](traceability.md). Каждый FR имеет ровно одного владельца; потребители применяют его правила. Локальные FR пакета дополняют каталог и не заменяют общие запреты.

## User Scenarios & Testing

Основные пользователи: владелец серверов, оператор сопровождения и администратор с правами изменения. Это роли в сценариях, а не требование немедленно создать корпоративную систему ролей. Каждый сценарий независимо проверяется на заранее подготовленном стенде; разработка других будущих функций для его проверки не требуется. P1 — основная ценность и обязательства, P2 — ближайшее развитие, P3 — специализированные возможности.

### User Story 1 — Подключить сервер и определить возможности (Priority: P1)

Пользователь проходит добавление, подтверждение идентичности, сохранение доступа и соединение. Ограниченные функции объясняют причину недоступности.

**Why this priority**: Без достоверного подключения нельзя осознанно наблюдать и изменять систему.
**Independent Test**: Доступный сервер, ограниченный пользователь и недоступный адрес; установка ПО не требуется.
**Acceptance Scenarios**:

1. **AC-001 Given** новый сервер, **When** пользователь завершает настройку, **Then** видны идентичность и результат соединения; отмена сохраняет редактируемый профиль.
2. **AC-002 Given** ограниченный доступ, **When** открыт обзор возможностей, **Then** чтение доступных сведений работает, закрытые действия объясняют недостающие права.
3. **AC-003 Given** изменившаяся идентичность, **When** запрошено соединение, **Then** чтение и запись заблокированы до отдельного пересмотра доверия.

### User Story 2 — Найти сервер и установленное ПО (Priority: P1)

Оператор ищет программу или версию по всем профилям, различает экземпляры и переходит к нужному объекту без потери цели.

**Why this priority**: Сводный инвентарь сокращает время поиска и риск изменения другого сервера.
**Independent Test**: Несколько профилей с разным ПО, один недоступен, два содержат одноимённые экземпляры.
**Acceptance Scenarios**:

1. **AC-004 Given** несколько серверов, **When** выполнен поиск программы, **Then** результат содержит сервер, фактическую версию, тип установки и время наблюдения.
2. **AC-005 Given** недоступный сервер с сохранёнными сведениями, **When** выполнен поиск, **Then** сведения остаются с отметкой устаревания.
3. **AC-006 Given** одноимённые экземпляры, **When** открыты детали, **Then** их серверы и идентичности различимы, неподтверждённые связи со службами отмечены явно.

### User Story 3 — Найти причину проблемы по журналам и ресурсам (Priority: P1)

Оператор открывает проблемную службу и относящиеся записи, сопоставляет события с ресурсами, сохраняет фильтры и контекст.

**Why this priority**: Диагностика должна предшествовать изменениям.
**Independent Test**: Журнал с известной ошибкой и пропуском, измерения с разрывом, отдельный отказ чтения.
**Acceptance Scenarios**:

1. **AC-007 Given** служба, **When** открыт её журнал, **Then** она уже выбрана, доступны поиск, период, приоритет и детали записи.
2. **AC-008 Given** пауза и фильтр, **When** пользователь меняет экран или тему, **Then** выбранный сервер, фильтры и пауза сохраняются.
3. **AC-009 Given** разрыв данных, **When** показана история, **Then** пропуск виден, ложные нули и непрерывные кривые не создаются.

### User Story 4 — Выполнить согласованное изменение (Priority: P1)

Пользователь рассматривает последствия, подтверждает конкретный план, наблюдает задание и получает проверенный результат либо явно неопределённый исход.

**Why this priority**: Ошибочная цель и повторное выполнение способны повредить работающую систему.
**Independent Test**: Разрешённая операция, повторное нажатие, обрыв связи и повторный запуск клиента.
**Acceptance Scenarios**:

1. **AC-010 Given** план, **When** подтверждение повторено, **Then** существует одно задание и один набор эффектов.
2. **AC-011 Given** потеря ответа после запуска, **When** клиент открыт снова, **Then** проверяется прежняя операция без автоматического повторения.
3. **AC-012 Given** завершённый исполнитель и неуспешная итоговая проверка, **When** показан результат, **Then** успех не заявляется.

### User Story 5 — Управлять службой (Priority: P2)

Администратор отдельно меняет состояние службы и её автозапуск, проверяет результат и связанные ошибки.

**Why this priority**: Это частая операция сопровождения установленного приложения.
**Independent Test**: Одна разрешённая служба с успешным запуском и предсказуемой ошибкой.
**Acceptance Scenarios**:

1. **AC-013 Given** остановленная служба, **When** подтверждён запуск, **Then** показаны фактическое состояние и свежие записи.
2. **AC-014 Given** работающая служба без автозапуска, **When** включён автозапуск, **Then** состояние сейчас и поведение после загрузки показаны отдельно.
3. **AC-015 Given** защищённая служба или отказ прав, **When** выбрано действие, **Then** оно запрещено с причиной, другие службы не изменены.

### User Story 6 — Установить или зарегистрировать приложение (Priority: P1)

Владелец явно выбирает чистую установку либо регистрацию существующей; реестр отражает подтверждённую версию и состояние.

**Why this priority**: Существующие данные требуют другого процесса, чем чистый сервер.
**Independent Test**: Чистый сервер и заранее установленная поддерживаемая база.
**Acceptance Scenarios**:

1. **AC-016 Given** чистая поддерживаемая среда, **When** выполнена установка, **Then** проверены версия, служба и работоспособность приложения.
2. **AC-017 Given** существующая установка, **When** она зарегистрирована, **Then** данные и конфигурация сохранены, служба не запущена автоматически.
3. **AC-018 Given** неоднозначная установка, **When** выполнена проверка, **Then** показана причина отказа; регистрация не заменяется новой установкой.

### User Story 7 — Обновить ПО и проверить его источники (Priority: P2)

Администратор оценивает обновление, влияние на зависимости и данные, отдельно управляет источниками пакетов.

**Why this priority**: Действующая система требует сохранения данных и контроля перерыва обслуживания.
**Independent Test**: Обновление одного приложения и отдельное изменение источника.
**Acceptance Scenarios**:

1. **AC-019 Given** обновление, **When** открыт план, **Then** показаны текущая и целевая версии, совместимость данных, копия и перезапуск.
2. **AC-020 Given** запрещённое удаление или понижение версии, **When** план проверен, **Then** выполнение заблокировано.
3. **AC-021 Given** непроверенный источник, **When** запрошено подключение, **Then** доверие не принимается автоматически и зависимое ПО не устанавливается.

### User Story 8 — Настроить систему и питание (Priority: P2)

Администратор меняет разрешённые параметры системы и отдельно планирует перезагрузку или выключение.

**Why this priority**: Типовые настройки должны выполняться без запоминания команд.
**Independent Test**: Тестовая машина с известными параметрами и разрешённой перезагрузкой.
**Acceptance Scenarios**:

1. **AC-022 Given** поддерживаемая настройка, **When** изменение подтверждено, **Then** повторное чтение показывает фактическое значение.
2. **AC-023 Given** отложенное питание, **When** действие отменено вовремя, **Then** сервер подтвердил отмену, история её сохраняет.
3. **AC-024 Given** перезагрузка, **When** связь восстановлена, **Then** подтверждён новый запуск системы и проверены выбранные службы.

### User Story 9 — Проверить и изменить сеть (Priority: P2)

Администратор видит интерфейсы и правила доступа, а перед опасным изменением проверяет возможность сохранить управление.

**Why this priority**: Сетевое изменение может лишить пользователя доступа.
**Independent Test**: Одноразовая машина с альтернативным доступом и подготовленным правилом.
**Acceptance Scenarios**:

1. **AC-025 Given** несколько интерфейсов, **When** открыта сеть, **Then** видны известные адреса и состояния, недоступные данные обозначены отдельно.
2. **AC-026 Given** изменение рабочего адреса без способа возврата, **When** проверен план, **Then** запуск заблокирован.
3. **AC-027 Given** затронут защищённый канал, **When** открыт план, **Then** запрещённый эффект указан, изменение не выполняется.

### User Story 10 — Проверить и обслужить хранилище (Priority: P2)

Администратор видит устройства, тома и монтирования, понимает зависимые данные и выполняет только поддерживаемую операцию.

**Why this priority**: Нехватка места и ошибочные действия с томами влияют на приложения.
**Independent Test**: Отдельный диск с известными данными и занятым томом.
**Acceptance Scenarios**:

1. **AC-028 Given** несколько файловых систем, **When** открыт обзор, **Then** заполнение каждой отделено от скорости ввода-вывода.
2. **AC-029 Given** занятый том, **When** подготовлено изменение, **Then** видны зависимые приложения и условия сохранения данных.
3. **AC-030 Given** неподдерживаемое хранилище, **When** открыты детали, **Then** доступны достоверные чтения, изменение не имитируется.

### User Story 11 — Управлять пользователями и доступом (Priority: P2)

Администратор создаёт, изменяет и блокирует аккаунты, управляет сессиями, сохраняя собственный путь администрирования.

**Why this priority**: Управление доступом не должно случайно лишать владельца контроля.
**Independent Test**: Тестовый пользователь и независимый администратор.
**Acceptance Scenarios**:

1. **AC-031 Given** новый пользователь, **When** создан аккаунт, **Then** повторное чтение подтверждает пользователя и выбранные группы.
2. **AC-032 Given** чужая сессия, **When** она завершена, **Then** закрыта выбранная сессия, собственная управляющая сохранена.
3. **AC-033 Given** потеря последнего административного доступа, **When** проверен план, **Then** изменение запрещено без подтверждённого восстановления.

### User Story 12 — Просматривать файлы и править конфигурацию (Priority: P2)

Администратор находит разрешённый файл, сравнивает изменения и сохраняет конфигурацию без потери конкурентных правок.

**Why this priority**: Чтение помогает диагностике; редактирование требует отдельной защиты.
**Independent Test**: Доступный файл, запрещённый файл и конкурентная правка.
**Acceptance Scenarios**:

1. **AC-034 Given** разрешённый файл, **When** он открыт, **Then** видны содержимое, размер, права и ограничение просмотра.
2. **AC-035 Given** внешняя правка, **When** пользователь сохраняет, **Then** показан конфликт без скрытой перезаписи.
3. **AC-036 Given** невалидная конфигурация, **When** запрошено применение, **Then** рабочий файл сохранён, служба автоматически не перезапущена.

### User Story 13 — Выполнить диагностическую процедуру (Priority: P2)

Оператор выбирает известную процедуру чтения и получает ограниченный результат с понятными правами и временем.

**Why this priority**: Повторяемая диагностика снижает зависимость от знания команд.
**Independent Test**: Разрешённая и недоступная процедуры, прерывание чтения.
**Acceptance Scenarios**:

1. **AC-037 Given** процедура чтения, **When** она выполнена, **Then** настройки не изменены, результат связан с сервером и временем.
2. **AC-038 Given** недостающие права, **When** выбрана процедура, **Then** ограничение объяснено без скрытого повышения прав.
3. **AC-039 Given** прерывание, **When** показан результат, **Then** частичный вывод и причина остановки обозначены.

### User Story 14 — Управлять контейнерным приложением (Priority: P3)

Оператор различает контейнеры, образы, стеки и постоянные данные; выбирает ограниченное действие.

**Why this priority**: Контейнеры расширяют применимость после основных системных функций.
**Independent Test**: Контейнер с томом данных и отдельно подготовленный стек.
**Acceptance Scenarios**:

1. **AC-040 Given** контейнер, **When** открыты детали, **Then** состояние, образ, порты и постоянные данные показаны отдельно.
2. **AC-041 Given** выбранный контейнер, **When** подтверждён перезапуск, **Then** другие контейнеры и тома не изменены.
3. **AC-042 Given** изменение стека, **When** открыт план, **Then** различимы заменяемые ресурсы и сохраняемые данные, неизвестные эффекты блокируют запуск.

### User Story 15 — Управлять виртуальными машинами (Priority: P3)

Администратор наблюдает VM и их ресурсы; действия существующей машины отделены от создания и удаления данных.

**Why this priority**: Виртуализация нужна отдельной части пользователей.
**Independent Test**: Тестовая VM и образ для независимой проверки создания.
**Acceptance Scenarios**:

1. **AC-043 Given** VM, **When** открыты детали, **Then** показаны состояние, ресурсы, диски и сети.
2. **AC-044 Given** обычное выключение не завершилось, **When** предлагается принудительная остановка, **Then** она требует отдельного подтверждения.
3. **AC-045 Given** удаление определения, **When** открыт план, **Then** диски по умолчанию сохраняются; их удаление является отдельным эффектом.

### User Story 16 — Создать копию и восстановить данные (Priority: P3)

Владелец выбирает данные и место хранения, видит проверку копии и отдельно выбирает цель восстановления.

**Why this priority**: Файл копии без проверки не доказывает возможность восстановления.
**Independent Test**: Небольшой набор, подтверждённая копия и отдельная цель восстановления.
**Acceptance Scenarios**:

1. **AC-046 Given** выбранные данные, **When** копия создана, **Then** видны состав, время, проверка и ограничения согласованности.
2. **AC-047 Given** копия, **When** запрошено восстановление, **Then** сначала выбраны цель и конфликтующие данные.
3. **AC-048 Given** повреждение или недоступный ключ, **When** копия проверена, **Then** восстановление запрещено без удаления исходных данных.

### User Story 17 — Проверить состояние и безопасность (Priority: P3)

Администратор собирает отчёт, смотрит аппаратные сведения и нарушения политики; исправления отделены от проверки.

**Why this priority**: Расширенная диагностика полезна для сопровождения и поддержки.
**Independent Test**: Известная проблема и частично недоступные сведения.
**Acceptance Scenarios**:

1. **AC-049 Given** сбор отчёта, **When** он завершён, **Then** собранные и недоступные категории перечислены, отправки наружу нет.
2. **AC-050 Given** нарушение политики, **When** показан результат, **Then** причина объяснена, настройки не изменены автоматически.
3. **AC-051 Given** экспорт, **When** пользователь выбирает состав, **Then** секреты исключены, приватные сведения включаются только явно.

### User Story 18 — Включать специализированные возможности (Priority: P3)

Администратор подключает нужную возможность для домена, сетевого сервиса, кластера или образа системы без усложнения базовой работы.

**Why this priority**: Специализированные задачи не нужны каждому пользователю.
**Independent Test**: Одна совместимая и одна несовместимая возможность без установки остальных.
**Acceptance Scenarios**:

1. **AC-052 Given** совместимая возможность, **When** она выбрана, **Then** видны назначение, права, среды и границы действий.
2. **AC-053 Given** несовместимая среда, **When** открыт раздел, **Then** причина понятна, основная работа сохранена.
3. **AC-054 Given** изменение специализированного ресурса, **When** оно запущено, **Then** применяются общие правила плана, истории и проверки результата.

### Edge Cases

- **EC-001**: Удаление профиля во время чтения не переносит результат другому профилю; незавершённое изменение блокирует удаление своей цели.
- **EC-002**: Два имени одного физического сервера не позволяют одновременно выполнять конфликтующие изменения.
- **EC-003**: Отказ доступа, недоступность сети и отсутствие данных различаются; последнее наблюдение сохраняет возраст.
- **EC-004**: Частичный ответ не делает весь экран успешным; полнота каждого показателя остаётся видимой.
- **EC-005**: Разные часы сервера и устройства не искажают порядок событий незаметно; временные привязки объяснены.
- **EC-006**: Большой инвентарь, файл или журнал ограничивается с видимым сообщением, отменой и продолжением просмотра.
- **EC-007**: Закрытие клиента не считается отменой удалённой работы; её история сохраняется.
- **EC-008**: Запрос отмены в неделимой операции остаётся запросом до подтверждения остановки, откат не обещается.
- **EC-009**: Внешнее изменение ресурса делает прежний план неактуальным до нового просмотра.
- **EC-010**: Нехватка места и отказ сохранения не объявляются успешным заданием.
- **EC-011**: Потеря ключа локального хранилища не создаёт пустую БД, новый ключ или открытый режим автоматически.
- **EC-012**: Неподдерживаемый после обновления объект сохраняет идентичность и объяснение закрытых действий.
- **EC-013**: Необычные символы имени не позволяют затронуть другой объект; неподдерживаемый ввод отклоняется.
- **EC-014**: Исчезнувшая точная версия не заменяется автоматически доступной альтернативой.
- **EC-015**: Несогласованная с БД файловая копия не называется проверенной копией приложения.
- **EC-016**: Обновление клиента сохраняет неопределённое задание и не запускает его повторно.
- **EC-017**: Проблема защищённого сетевого клиента может отображаться, но его исправление запрещено.


## Requirements

### Бизнес цели

- **BR-001**: Сократить поиск проблемного сервера и причины сбоя; критерии SC-001–002.
- **BR-002**: Исключить ошибочную цель и повторное изменение после неопределённого исхода; SC-004–005.
- **BR-003**: Объединить существующие серверы разных провайдеров с явной совместимостью; SC-003, SC-014.
- **BR-004**: Сохранить самостоятельную локальную работу; SC-006.
- **BR-005**: Разделять установку, регистрацию, обслуживание и восстановление приложения; SC-007, SC-011.
- **BR-006**: Сохранять достоверность неполных и устаревших наблюдений; SC-008.
- **BR-007**: Сохранить контроль владельца над секретами и приватными сведениями; SC-009.
- **BR-008**: Поставлять самостоятельные небольшие результаты без одного общего MR; SC-015–016.
- **BR-009**: Сохранить согласованные настольные и узкие пользовательские сценарии; SC-010.
- **BR-010**: Разделять обновление ServerDeck и изменения ПО сервера; SC-012.


### Functional Requirements

- **FR-001**: Профили, сохранённые наблюдения и история должны открываться без облачного аккаунта и интернета. Живые сведения требуют достижимости самого сервера; эти два условия не смешиваются.
- **FR-002**: Пользователь должен видеть отдельно поддержку клиентской платформы и удалённой функции. Успешная установка клиента не должна показывать недоступную операцию как готовую.
- **FR-003**: Для вида действия на конкретном сервере должны различаться «доступно», «нужна подготовка», «нет прав», «не поддерживается» и «не удалось определить», с причиной и допустимым следующим шагом.
- **FR-004**: Определение возможностей не должно устанавливать компоненты, исправлять права, включать службы, менять конфигурацию или открывать порты.
- **FR-005**: Отсутствующая или отключённая дополнительная возможность не должна мешать доступным подключениям, чтениям и просмотру истории.
- **FR-006**: Первая поддержанная среда серверных изменений — Ubuntu 24.04 amd64/systemd; первый каталог — PostgreSQL и ClickHouse. Новые ОС, архитектуры и способы установки включаются явно для каждой функции.
- **FR-007**: Пользователь должен создавать, редактировать и удалять профиль с именем, адресом, портом, пользователем и тегами. Секреты не являются обычными полями профиля.
- **FR-008**: Первое подключение должно объяснять последовательность идентичности, доступа и соединения. Сохранение без соединения и отмена сохраняют профиль без удалённых изменений.
- **FR-009**: Подготовленный профиль должен подключаться одним основным действием без повторного подтверждения уже проверенной идентичности и неизменного доступа.
- **FR-010**: Неизвестная идентичность требует подтверждения; изменившаяся блокирует подключение. Автоматическая замена доверия или продолжение чтения после такой ошибки запрещены.
- **FR-011**: В списке должны работать поиск и фильтры по имени, адресу, тегу и состоянию. Недоступный сервер остаётся в списке и отличается от удалённого профиля.
- **FR-012**: Ошибка или медленный ответ одного сервера должны сохранять доступность остальных профилей, их данных и пользовательских действий в пределах действующих лимитов подключений.
- **FR-013**: На экране объекта и в подтверждении изменения должны быть видны имя и адрес целевого сервера. Навигация не должна незаметно подменять цель подготовленного действия.
- **FR-014**: Пустое пространство должно предлагать добавление сервера без автоматически появляющихся демонстрационных профилей, программ и измерений.
- **FR-015**: Запись ПО должна содержать фактическое имя и версию, источник, тип установки, сервер и время наблюдения. Неизвестная версия остаётся неизвестной, а не подставляется из каталога.
- **FR-016**: Система должна различать пакет ОС, пользовательскую программу, службу, контейнер и экземпляр приложения. Невыполненный поиск по типу не считается подтверждением отсутствия объектов.
- **FR-017**: Одноимённые экземпляры должны иметь отдельную идентичность. При неоднозначности регистрации пользователь получает ограничение, а система не выбирает первый экземпляр автоматически.
- **FR-018**: Общий поиск должен показывать серверы с выбранным ПО и версией, явно разделяя свежие, сохранённые и неполные результаты. Область поиска должна быть понятна до интерпретации списка.
- **FR-019**: Связь приложения со службой, процессом и данными показывается как установленный факт только при подтверждающем наблюдении. Предполагаемая связь обозначается отдельно.
- **FR-020**: Пользователь должен открывать происхождение записи и диагностическое объяснение. Основной список сохраняет компактность и не требует понимания внутренних средств обнаружения.
- **FR-021**: Удаление локальной регистрации должно объяснять, что исчезнет только связь в приложении; удалённое ПО, конфигурация, службы и данные не меняются.
- **FR-022**: Обзор должен показывать известные сведения об ОС, архитектуре, ядре, имени и продолжительности работы. Недоступность отдельного поля не делает остальные поля неизвестными.
- **FR-023**: CPU, занятая память и заполнение корневой файловой системы должны иметь разные понятные подписи и единицы. Заполнение диска не называется нагрузкой ввода-вывода.
- **FR-024**: Карточки сохраняют максимум десять минут и 120 реальных точек истории. Нет данных, устаревание и разрыв не создают нулевой замер или линию до текущего времени.
- **FR-025**: Расширенный обзор должен показывать сетевую активность, ввод-вывод и ресурсы выбранной службы или процесса в поддерживаемых случаях. Скорость, накопленный объём и момент замера различаются.
- **FR-026**: Долговременная история должна объяснять место и период сбора, начало доступной истории и пропуски. Продолжение сбора при закрытом клиенте обещается только для отдельно поддержанной возможности.
- **FR-027**: Уведомление о ресурсе внутри работающего клиента должно иметь показатель, порог и длительность превышения. Недоступный замер не подтверждает норму и не создаёт повторное событие без нового основания.
- **FR-028**: Подробные показатели открываются отдельно от компактных карточек. Их добавление не нарушает ранее согласованное расположение основных графиков и доступность текстовых значений.
- **FR-029**: Пользователь должен открывать общий журнал сервера и журнал конкретной службы либо приложения с уже выбранным объектом и понятным источником записей.
- **FR-030**: Просмотр сохраняет поиск текста, период, приоритет, службу, структурированные поля, явное копирование, паузу и возобновление. Часовой пояс времени записи должен быть понятен.
- **FR-031**: Базовая история сохраняет запрос 1–1000 записей с начальным значением 100 и буфер 500 записей на сервер. Новые источники не обходят эти ограничения молча.
- **FR-032**: Переключение экранов и тем сохраняет выбранный сервер, фильтры, паузу и ограниченный буфер текущей сессии; смена источника обозначается явно.
- **FR-033**: Пропуски, отброшенные записи, повторения, неполная загрузка и отказ прав должны быть видны. Ни одно из этих состояний не называется успешным пустым журналом.
- **FR-034**: Каждый новый источник логов должен иметь собственные границы чтения и совместимость. Наличие системного журнала не означает чтение произвольных файлов приложения.
- **FR-035**: Перед изменением должны быть видны цель, исходное состояние, параметры, ожидаемые эффекты, предварительные условия, возможный перерыв и критерий результата. Неизвестные существенные эффекты блокируют запуск.
- **FR-036**: Согласие относится к неизменному плану. Изменение сервера, доступа, версии, параметров или существенного исходного состояния требует нового просмотра и подтверждения.
- **FR-037**: Просмотр и проверка готовности не выполняют эффекты плана и не исправляют условия автоматически. Пользователь различает проверку, подтверждение и фактический запуск.
- **FR-038**: Конфликтующие изменения одного физического сервера не выполняются одновременно даже через разные профили. Причина ожидания или отказа должна быть понятна.
- **FR-039**: Повторное подтверждение возвращает прежнее задание. Потерянный ответ и повторное нажатие не дают основание заново выполнить уже начатые эффекты.
- **FR-040**: История сохраняет цель, согласованный план, начало, этапы, завершение и причину ошибки после закрытия клиента. Сохранение истории не должно раскрывать секреты.
- **FR-041**: Отмена до запуска не изменяет сервер; после запуска означает запрос остановки в допустимой точке. Пользователь видит разницу между запросом отмены, остановкой и сохранёнными эффектами.
- **FR-042**: Потеря связи или подтверждения сохраняет неизвестный исход до проверки прежнего задания. Автоматический повтор записи и освобождение конфликтующей цели без проверки запрещены.
- **FR-043**: Успешный итог требует повторного чтения фактического состояния и применимой проверки работоспособности. Завершение исполнителя без проверки не считается успехом.
- **FR-044**: Запрещено менять NetBird и его клиенты: пакеты, службы, конфигурацию, данные, доступ и зависимости с такими эффектами. Ограничение действует и для дополнительных модулей.
- **FR-045**: Новая установка и регистрация существующей остаются явно разными процессами. Их название, подготовка и последствия не должны путать пользователя.
- **FR-046**: Каталог должен показывать поддерживаемые программы, точные версии, среды и ограничения. Недоступная версия не заменяется автоматически похожей или более новой.
- **FR-047**: Существующие данные, конфигурация и несовместимое состояние должны блокировать чистую установку. Очистка, понижение версии и преобразование не включаются скрыто.
- **FR-048**: Регистрация читает существующую установку и сохраняет локальную связь. Остановленная служба не запускается ради проверки; недостаток доказательств объясняется отдельно.
- **FR-049**: Обновление должно показать текущую и целевую версии, совместимость формата данных, необходимость копии, перерыв, проверку и условия восстановления.
- **FR-050**: Первая поставка обновления приложения охватывает одно приложение и один объявленный переход версий. Обновление всех программ или всех серверов не включается в этот этап.
- **FR-051**: Удаление приложения должно разделять пакет, конфигурацию и данные. Удаление данных требует отдельного выбранного эффекта и проверки пригодной копии.
- **FR-052**: Неподдерживаемые ремонт, понижение и преобразование нестандартной установки должны давать отказ с причиной, сохраняя исходное состояние без скрытого сброса.
- **FR-053**: Детали службы должны различать состояние сейчас, автозапуск и последнюю известную ошибку. Остановленная служба не считается отсутствующим приложением.
- **FR-054**: Запуск, остановка и перезапуск поддерживаемой службы — отдельные согласуемые действия с последующим чтением состояния и доступным журналом.
- **FR-055**: Изменение автозапуска отделяется от текущего запуска. Оба эффекта могут совмещаться только при их явном включении в согласованный план.
- **FR-056**: Для расписания и объекта активации должны отображаться связанная служба, время последнего и ближайшего выполнения в доступных случаях. Неизвестное ближайшее время не выдумывается.
- **FR-057**: Изменение расписания показывает часы, часовой пояс, пропущенные запуски и конфликт. Принятый график подтверждается повторным чтением сервера.
- **FR-058**: Ошибка выбранной службы должна открывать её записи без ручного поиска. Право действия с одним объектом не означает разрешения на соседние службы.
- **FR-059**: Обзор обновлений ОС показывает время проверки и доступные изменения. Недоступный источник либо неуспешная проверка не дают статус «обновлений нет».
- **FR-060**: План пакетного изменения показывает зависимости, удаления, конфликты и перезапуск. Запрещённые эффекты и неизвестные зависимости блокируют выполнение.
- **FR-061**: Установка и удаление обычного пакета имеют отдельный план и результат. Установленный пакет не объявляется настроенным и работоспособным приложением без дополнительной проверки.
- **FR-062**: Источник пакетов должен показывать адрес, включённость и статус доверия. Неудача проверки доверия не заменяется подтверждённым статусом.
- **FR-063**: Добавление, отключение и изменение источника — отдельные задания. Изменение источника не запускает обновление ОС или установку ПО автоматически.
- **FR-064**: Транзакционное обновление ОС различает подготовленное и активное состояние, необходимость перезагрузки и доступные условия возврата; подготовка не считается уже применённой версией.
- **FR-065**: Изменение имени хоста показывает старое и новое значение, влияние на доступ и связанные профили. Другие профили не переписываются автоматически.
- **FR-066**: Время, часовой пояс и источник синхронизации — разные настройки. Неподдерживаемая настройка источника закрывается с объяснением при сохранении доступных сведений.
- **FR-067**: Профиль производительности показывает назначение и применимость. Включение требует отдельного плана, повторное чтение подтверждает активный профиль.
- **FR-068**: Перезагрузка и выключение показывают цель, время и влияние на активные задания. Конфликт с незавершённой записью блокирует запуск.
- **FR-069**: Отложенное питание имеет проверяемое время и отмену до выполнения, если среда это поддерживает. Запрос отмены без ответа не объявляется отменённым расписанием.
- **FR-070**: После возвращения сервера должно появиться новое наблюдение запуска и состояния. Потеря связи после команды не доказывает успешное выключение.
- **FR-071**: Обзор показывает обнаруженные интерфейсы, соединение, адреса, маршруты и DNS с отдельной полнотой данных. Неуправляемый интерфейс не исчезает как отсутствующий.
- **FR-072**: Изменение адреса, маршрута, DNS, моста, VLAN или объединения интерфейсов разрешается только для конкретного объявленного варианта. Одна поддержка не означает поддержку остальных.
- **FR-073**: Изменение с риском потери управления требует проверенного возврата либо независимого доступа. Без него действие запрещено, а причина показана до подтверждения.
- **FR-074**: После сетевого изменения проверяются фактическая конфигурация и связь. Разрыв не считается успешным применением; восстановление сохраняет историю попытки.
- **FR-075**: Обзор правил доступа показывает область, состояние и назначение. Неизвестная подсистема и отказ чтения не изображаются пустым firewall.
- **FR-076**: Изменение правила показывает открываемые и закрываемые доступы, затронутые объекты и защищённые каналы управления; запрет защищённого эффекта нельзя обойти другой формой.
- **FR-077**: Проброс портов, DNS-сервис и сетевой файловый ресурс имеют отдельную область поддержки и подтверждение. Настройка одного не даёт общего разрешения на изменение сети.
- **FR-078**: Туннели и VPN допускают обзор доступных состояний. Изменение защищённых клиентов запрещено независимо от наблюдаемой проблемы.
- **FR-079**: Обзор различает устройство, раздел, том, файловую систему и точку монтирования, показывает вместимость, свободное место и известное состояние.
- **FR-080**: Перед изменением видны данные, приложения и активное использование. Неизвестные зависимости блокируют опасную операцию вместо предположения, что том свободен.
- **FR-081**: Монтирование показывает текущее состояние и поведение после загрузки. Удаление записи монтирования не означает согласие на удаление данных.
- **FR-082**: Расширение тома показывает свободное пространство и ограничения; после применения проверяются размер и доступность данных, а не только завершение команды.
- **FR-083**: Форматирование, уменьшение, удаление и изменение шифрования требуют самостоятельных поставок и проверки сохранности. Они не входят в первое обслуживание дисков.
- **FR-084**: RAID, логические тома, сетевое блочное хранилище и расширенные файловые системы поддерживаются по отдельным вариантам; доступные чтения и изменения перечисляются явно.
- **FR-085**: Обзор аккаунтов показывает доступные сведения о пользователе, группах, блокировке, сроке доступа и сессиях без раскрытия секретов.
- **FR-086**: Создание, изменение групп и блокировка пользователя имеют отдельные планы и повторное чтение результата; служебные аккаунты могут иметь объяснённые ограничения.
- **FR-087**: Изменение пароля и срока действия не сохраняет пароль в истории, профиле или диагностике. Отказ не заменяется открытым способом хранения.
- **FR-088**: Завершение сессии идентифицирует её и предупреждает о потере работы. Собственная управляющая сессия не закрывается этим пользовательским действием.
- **FR-089**: Изменение административных полномочий блокирует потерю последнего рабочего пути управления без отдельно подтверждённого восстановления.
- **FR-090**: Доменные отношения, каталог пользователей и локальные аккаунты — отдельные функции с разными условиями и последствиями. Их поддержка не выводится друг из друга.
- **FR-091**: Файловый просмотр показывает путь, тип, размер, владельца и права. Отказ чтения не выдаётся за пустой файл; ограничение содержимого видно.
- **FR-092**: Поиск различает область, имя и содержимое, ограничивает объём и допускает отмену. Пользователь видит частичный результат и непросмотренную область.
- **FR-093**: Получение файла на устройство требует выбранного файла и назначения. Файлы серверов не отправляются третьим лицам автоматически.
- **FR-094**: Перед сохранением конфигурации показаны различия и проверена актуальность исходного файла. Внешнее изменение создаёт конфликт без скрытой перезаписи.
- **FR-095**: Применение требует проверки формата и подготовленного возврата. Перезапуск зависимой службы включается только отдельным согласованным эффектом.
- **FR-096**: Перенос, удаление, изменение владельца и прав — отдельные действия с объяснёнными последствиями; просмотр и поиск сами их не выполняют.
- **FR-097**: Диагностическая процедура имеет описание, цель, права и ожидаемый результат. Процедура чтения не меняет настройки и не запускает автоматическое исправление.
- **FR-098**: Вывод содержит сервер, время, полноту и причину остановки; лимит вывода и прерванная процедура не превращаются в успешный полный результат.
- **FR-099**: Неограниченный терминал и произвольные пользовательские скрипты исключены из этих поставок. Их будущее включение требует отдельной спецификации прав, истории и ответственности за эффекты.
- **FR-100**: Контейнерный обзор различает контейнер, образ, стек, сеть и постоянные данные. Недоступная среда исполнения не доказывает отсутствие контейнеров.
- **FR-101**: Запуск, остановка и перезапуск выбранного контейнера подтверждаются состоянием. Другие контейнеры и постоянные тома сохраняются.
- **FR-102**: Создание, замена и удаление показывают порты, ресурсы и данные. Удаление образа, сети либо тома не добавляется в план скрыто.
- **FR-103**: План стека перечисляет изменения его ресурсов, порядок и постоянные данные. Поддержка одной среды исполнения не означает взаимозаменяемость с другой.
- **FR-104**: Обзор VM показывает состояние, ресурсы, диски и сети в доступной области. Недоступные сведения обозначаются отдельно от отсутствующих объектов.
- **FR-105**: Обычная и принудительная остановка VM — разные действия с разным подтверждением; неуспешная обычная остановка не запускает принудительную автоматически.
- **FR-106**: Создание и изменение оборудования проверяют ресурсы хоста, совместимость образа, сети и хранения; нехватка условий блокирует запуск без частично выданного успеха.
- **FR-107**: Удаление определения VM по умолчанию сохраняет диски. Удаление дисков — отдельный эффект с точными данными и условиями сохранения.
- **FR-108**: План копирования определяет набор, место хранения, согласование с приложением и исключения. Доступ к месту хранения не становится открытым параметром плана.
- **FR-109**: Копия содержит состав, время, объём и результат проверки доступности. Обещание согласованности соответствует выполненной проверке, а не факту создания файла.
- **FR-110**: Расписание выполняется на управляемом сервере независимо от клиента/locald. Оно показывает часовой пояс, следующий доступный момент, пропущенные моменты, последнее успешное копирование и последнюю ошибку. Серверное разрешение ограничено подтверждённой схемой; его отзыв блокирует новые запуски, пропущенные моменты не исполняются автоматически после восстановления. Полный lifecycle, проверка условий, конкурентные операции и приёмка определены в [012](012-backup-recovery/spec.md).
- **FR-111**: Политика хранения показывает сохраняемые и удаляемые копии. Последняя подтверждённая пригодная копия не удаляется автоматически.
- **FR-112**: Восстановление требует выбранной копии и цели, списка заменяемых данных и возможности сохранить текущее состояние. Открытие списка копий не начинает восстановление.
- **FR-113**: Пробное восстановление в отдельную цель проверяет состав и читаемость, а работоспособность приложения — только если такая гарантия заявлена для этого типа копии.
- **FR-114**: Недоступный ключ, повреждение и несовместимость блокируют восстановление без удаления исходных данных. Полное аварийное восстановление сервера требует отдельной спецификации.
- **FR-115**: Отчёт перечисляет категории, временную привязку, ошибки и неполноту. Отправка наружу требует выбора адресата и разрешённого состава отдельно от сбора.
- **FR-116**: Аппаратный обзор показывает доступные устройства, датчики и состояние дисков. Неподдерживаемый датчик не даёт выдуманный ноль либо норму.
- **FR-117**: Событие безопасности, объяснение и предлагаемое исправление различаются. Просмотр события сам не применяет исправление и не отключает защиту.
- **FR-118**: Проверка соответствия называет политику и версию, область, успешные, нарушенные и непроверенные правила. Непроверенное правило не включается в процент успешных.
- **FR-119**: Исправление нарушения и смена режима защиты имеют отдельный план и повторную проверку. Кнопка сбора диагностики не даёт согласие на эти действия.
- **FR-120**: Запись административной сессии и диагностика сбоев ядра включаются отдельно с указанной областью, доступом, местом хранения и сроком хранения данных.
- **FR-121**: Пароли, приватные ключи и защитные фразы сохраняются в защищённом хранилище пользователя. Его отказ не создаёт открытой копии или запасного незащищённого доступа.
- **FR-122**: Средствами ОС текущего пользователя до первой записи защищаются все секреты доступа: приватные SSH-ключи, пароли и passphrase. Обычные поля профилей, настройки, наблюдения, планы, история и индексы хранятся без шифрования приложения с ограничением доступа по правам ОС. Общего ключа шифрования базы и зашифрованного агрегата пространства нет. Пакет 002-security-storage расширяет аудит и восстановление защиты секретов.
- **FR-123**: Обычная история, ошибки и стандартный экспорт исключают секреты. Включение приватных сведений в экспорт требует явного выбора состава и назначения.
- **FR-124**: Действия соответствуют фактическим правам пользователя; просмотр не повышает их скрыто. Текущий уровень полномочий понятен до запуска изменения.
- **FR-125**: Все экраны поддерживают две темы, клавиатуру, узкую композицию и текстовые значения графиков. Состояния не обозначаются только цветом.
- **FR-126**: Формы объясняют последствия обычным языком. Внутренние протоколы и идентификаторы открываются в дополнительных деталях, если нужны для диагностики.
- **FR-127**: Последующие обновления новой реализации ServerDeck сохраняют её профили, настройки, доступы и историю заданий. Переход со старого сервиса не импортирует их и не инициирует изменения серверов.
- **FR-128**: Каталог дополнительных возможностей показывает назначение, среду, права и доступность. Отключение раздела не удаляет управляемые ресурсы на сервере.
- **FR-129**: DNS-зоны и сетевые файловые ресурсы требуют отдельных границ клиентов, открываемого доступа и влияния на данные. Изменение одного объекта проверяется независимо.
- **FR-130**: Обзор кластера высокой доступности различает узел и общий ресурс; отсутствие ответа одного узла не считается подтверждённым отказом всего кластера.
- **FR-131**: Образ ОС имеет выбранный состав, версию и проверенный результат построения. Подготовка образа не запускает переустановку существующего сервера.
- **FR-132**: Подписки, доменное членство и сервис удалённого рабочего стола — отдельные возможности. Платные условия, изменение доступа и область управления видны до подтверждения.

### Key Entities

- **Профиль сервера**: имя, адрес, пользователь, теги, доверенная идентичность и ссылка на доступ; физическая цель важна для конфликтов операций.
- **Возможность**: назначение, среда, доступность, причина ограничения и необходимые права.
- **Наблюдение**: объект, значение, источник, момент, полнота и свежесть.
- **Установка приложения**: версия, сервер, экземпляр, тип установки и подтверждённые связи со службами и данными.
- **Служба**: состояние, автозапуск, объекты активации, журнал и доступные действия.
- **План**: неизменная цель, исходное состояние, параметры, эффекты, условия и критерий результата.
- **Согласие**: подтверждение конкретного плана, а не неограниченные полномочия.
- **Задание**: цель, подтверждение, ход, отмена, неизвестный исход, проверка и история.
- **Сеть**: интерфейсы, адреса, маршруты, правила и зависимости каналов управления.
- **Хранилище**: устройства, тома, файловые системы, монтирования и данные.
- **Учётная запись**: пользователь сервера, группы, ограничения, полномочия и сессии.
- **Контейнер или VM**: идентичность, среда исполнения, состояние, ресурсы и постоянные данные.
- **Копия**: состав, назначение, время, согласованность, проверка и срок хранения.
- **Отчёт**: категории, наблюдения, ограничения сбора и разрешённый состав экспорта.
- **Этап**: самостоятельный результат, требования, зависимости, исключения и критерий приёмки.


## Success Criteria

### Measurable Outcomes

- **SC-001**: Не менее 4 из 5 участников за две минуты находят проблемный сервер и открывают связанную службу или приложение без подсказок.
- **SC-002**: Не менее 4 из 5 за три минуты находят заданную ошибку через фильтры журналов и правильно называют сервер и время.
- **SC-003**: При 250 профилях и 10 000 записях ПО поиск по сохранённым данным показывает результат за две секунды в 95% из 30 повторов; недоступные серверы не исчезают.
- **SC-004**: Во всех проверках повторного подтверждения возникает одно задание и не более одного набора эффектов.
- **SC-005**: Во всех проверках обрыва после запуска и перезапуска клиента отсутствует автоматический повтор записи; неизвестный итог сохраняется до подтверждения.
- **SC-006**: Без интернета доступны все локальные профили, сохранённые наблюдения и история; достижимый сервер не блокируется отсутствием облачного сервиса.
- **SC-007**: Во всех приёмках явно различаются установка и регистрация; регистрация не меняет существующие данные и конфигурацию.
- **SC-008**: Все подготовленные случаи отсутствия, отказа, несовместимости, неполноты и устаревания имеют разные состояния, ни один не заменён здоровым нулём.
- **SC-009**: Во всех проверках синтетические секреты отсутствуют в обычных профилях, истории, ошибках и стандартном экспорте; нет открытого обхода отказа хранения.
- **SC-010**: Все принятые новые сценарии доступны в обеих темах на согласованных настольных размерах и ширинах 360/390, с клавиатурой и текстовыми значениями графиков.
- **SC-011**: Для каждой схемы копирования выполнено хотя бы одно пробное восстановление в отдельную цель с проверкой состава; повреждённая копия всегда блокируется.
- **SC-012**: Во всех обновлениях новой реализации сохраняются её профили, настройки и история; удалённое ПО автоматически не изменяется. Это не требование переноса со старого сервиса.
- **SC-013**: В каждом изменяющем сценарии успешный итог подтверждён фактическим состоянием; невозможность проверки не считается успехом.
- **SC-014**: У каждой поставленной функции есть непустая матрица с проверенным вариантом; отрицательные варианты показывают причину.
- **SC-015**: Каждый MR относится к одному этапу либо его более узкой части, имеет отдельную приёмку и не включает действия отложенных этапов.
- **SC-016**: После каждого этапа новой реализации сохраняются принятые ранее в этой новой реализации основные сценарии, профили и связи установок.
- **SC-017**: Все опасные сетевые изменения без подтверждённого возврата доступа блокируются; защищённые клиенты не изменяются.
- **SC-018**: Не менее 4 из 5 участников до подтверждения правильно называют цель, эффект и необходимость перерыва без открытия технической диагностики.

## Assumptions

- Проектные ограничения и базовая технологическая линия установлены [конституцией](../.specify/memory/constitution.md); переиспользование конкретного старого кода и схем не обязательно.
- Поддержка среды относится к конкретной функции и версии; Windows Server, массовые записи, cloud provisioning, unrestricted terminal, произвольные scripts и полное аварийное восстановление машины исключены.
- Дополнительный мониторинг при закрытом клиенте не подразумевается. Требования long-term history и modules описывают отдельные этапы и включаются только после их полной приёмки.
- Optional backend нужен только для 020; остальные пакеты не зависят от аккаунта, provider APIs или его доступности.
- Все реальные изменяющие действия требуют продуктового approval на точный план. Разработка использует isolated fixtures; настоящий host не изменяется по факту появления требования.
- Каталог остаётся Specify. Для001.1 созданы [Plan](001-service-foundation/plan.md)/[Tasks](001-service-foundation/tasks.md), реализованы scaffold и часть primitives; полная служба, пересмотренное хранение, CRUD/UI и приёмка не завершены. Plan/Tasks обязательны перед реализацией каждого этапа; архитектурная готовность определяется отдельным ревью пакета, а не этим каталогом.
