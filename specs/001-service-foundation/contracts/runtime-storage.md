## Paths, ownership, native primitives

Новый namespace `%LOCALAPPDATA%\ServerDeckNext\v1`, не старый ServerDeck. `workspaces\default` единственное активное пространство001.1; workspaceId определяется защищённым manifest. Discovery `runtime\default.discovery` отдельно, без raw key/token/private fields.

Directory/file DACL explicit protected без inheritance: owner SID current user и SYSTEM, не Everyone/Users. Проверить до private reads/writes; failure→storage-blocked. Только local fixed-volume path внутри resolved LOCALAPPDATA, без UNC/reparse points в каждом компоненте. Unsafe path не перенаправляется. Admin/full-account compromise вне угроз.

Owner/DACL validation compares actual and expected descriptors in the same native
Windows canonical serialization. Legal SID aliases (for example LA/SY) are
representations of the exact expected SID, never additional allowed principals.
Only the two orders of the owner/SYSTEM allow ACEs are accepted; protected DACL,
ACE flags and exact file/mutex/pipe masks remain mandatory. Foreign owner,
unprotected/null DACL, extra ACEs or different rights fail closed. Descriptor
comparison does not change OS ACLs, tokens or privileges.

Mutex `Global\ServerDeckNext.v1.<SHA256(ownerSid+"default")>` с owner SID/SYSTEM ACL: locald удерживает до create/open и release после Isar close. Восемь pipe slots `\\.\pipe\ServerDeckNext.v1.<sameHash>.<slot0..7>`: каждый отдельное имя и ровно один instance, duplex overlapped byte mode, PIPE_REJECT_REMOTE_CLIENTS и FILE_FLAG_FIRST_PIPE_INSTANCE. DACL даёт current SID только FILE_READ_DATA, FILE_WRITE_DATA, FILE_READ_ATTRIBUTES, READ_CONTROL, SYNCHRONIZE (mask 0x120083), не FILE_CREATE_PIPE_INSTANCE/GENERIC_WRITE. Сервис создаёт восемь разных pipe objects, не дополнительные instances существующего имени. Поэтому ему не требуется grant создания чужого instance через client ACL. CreateFile client запрашивает этот exact mask; FILE_READ_ATTRIBUTES необходим также для внутреннего открытия client endpoint Windows. Не выдавать FILE_WRITE_ATTRIBUTES, WRITE_DAC, WRITE_OWNER или FILE_CREATE_PIPE_INSTANCE. Handles non-inheritable. Невозможность создать любой slot означает unsafe endpoint и останавливает bootstrap, без обхода чужого pipe. Client выбирает свободный slot в пределах deadline; занятые слоты не создают новые pipes.

serverdeck_windows operations: SID/DACL/secure create+flush+rename, DPAPI protect/unprotect, mutex acquire/release, pipe listen/connect/read/write/cancel/peer identity, process image verification. Win32/typed FFI system DLLs kernel32/advapi32/crypt32/bcrypt; CNG SHA256 для image hash, без нового package или runtime download. Handle у одного worker, exactly-once CloseHandle, native buffers freed finally. CancelIoEx deadline, buffer free после completion; blocking waits вне UI isolate. Peer SID читается из process token посредством OpenProcessToken(TOKEN_QUERY), без impersonation или включения debug privilege; ошибку query считать auth failure. Kernel peer PID, retained process handle, creation time, TokenUser и image/hash проверять совместно по Local API. Собственный process/thread token не заменяется ни в одной ветке. Missing bindings — typed lookup, не platform stub.

## Startup/discovery

Native issuance использует typed NtReadFile/NtWriteFile/NtFsControlFile(FSCTL_PIPE_LISTEN) из системной ntdll.dll: возвращаемый NTSTATUS отличает STATUS_PENDING от immediate failure/STATUS_PIPE_CONNECTED без отдельного TLS GetLastError. IO_STATUS_BLOCK хранится в совместимых Internal/InternalHigh полях OVERLAPPED. Перед syscall Status/Internal инициализируется STATUS_PENDING: NT API вправе не менять IOSB до completion, а GetOverlappedResult(bWait:true) использует Internal для решения о wait при cancel-drain. Только возвращаемый NTSTATUS определяет, была ли операция queued; provisional IOSB не разрешает ждать event при immediate failure/STATUS_PIPE_CONNECTED. Event/Information используются только после подтверждённого completion. Это сохраняет обычный duplex byte-mode Win32 pipe и существующие ACL/limits; pending cancellation всё ещё выполняет CancelIoEx и drain до освобождения ресурсов.

Overlapped I/O не должно зависеть от срока жизни временного VM thread: Windows отменяет pending request при завершении issuing thread. Контроллер NativePipe остаётся единственным владельцем handle и buffers; issuance→native wait→completion/cancel-drain каждой операции выполняется на одном непрерывном native call stack в отдельном operation isolate. Контроллер передаёт только тип операции и адреса принадлежащих ему ресурсов, не принимает внешние адреса. Существующий лимит трёх active I/O на pipe ограничивает эти операции; blocking waits не занимают owner/UI isolate. Per-operation cancellation event сигналится при deadline, disconnect и close; cancellation до issuance предотвращает поздний запуск после уже выполненного CancelIoEx. Close/disconnect ждут завершения всех issued operations прежде reuse/CloseHandle/free; event и native buffer не освобождаются по одному timeout без подтверждённого completion. Дополнительная DLL, изменение ACL, heartbeat для удержания VM thread или укороченный idle timeout не требуются.

Каждый start новый token/generation, file replace atomic с protected ACL. Bootstrap identity — неизменный workspaceSlot и поколение, а не ещё неизвестный workspaceId. Перед ready descriptor обновляется с проверенным workspaceId; readiness сообщает ту же identity. UI decrypt wrapper, проверяет kernel peer/image и handshake. Ошибка namespace access предшествует key generation.

## Initial creation/crash recovery

Discovery encoding v1: decrypted UTF8 JSON ≤8KiB, DPAPI wrapper nonempty ≤16KiB; ровно `{format:1,product:"serverdeck-next",apiMajor:1,apiMinor:0,workspaceSlot:"default",workspaceId:null|UUID,generation:UUID,bootstrapToken,buildId,serverPid,pipeNames}`. Generation — CSPRNG UUIDv4 lowercase, token — отдельные CSPRNG32bytes canonical unpadded base64url43chars. BuildId соответствует verified bundle; serverPid integer1..4294967295 лишь discovery hint, peer проверяется kernel API. PipeNames — ровно восемь ordered names slot0..7 заданного owner namespace, без supplied namespace/endpoint. Unknown format/API/build→INCOMPATIBLE; malformed/extra fields/invalid identities/token/endpoint или DPAPI/path/ACL errors→STORAGE_BLOCKED, без input echo. Обновление workspaceId после verified open сохраняет generation/token, не меняет известный workspaceId. Descriptor/token owned copies очищаются при close; receipt key/credentials в schema отсутствуют. Reader не требует mutex; publisher/remover требуют held lease именно owner namespace. Публикации сериализуются, wrapped bytes пишутся protected temporary file с flush и atomic replace. Shutdown ждёт завершения публикаций перед removal/release; удаляет только descriptor своей generation под mutex. Corrupt/missing/foreign generation не считать успешно удалённой. Restart owner может заменить stale descriptor только под mutex; loser ничего не пишет. Partial failed publication не объявляет ready и не заменяет plain-text fallback.

Existing active directory никогда не разрешение create empty. Автоматическое создание только при отсутствии active и pending staging. Под mutex создать `workspaces\default.creating` с protected ACL, CSPRNG workspaceId/receiptKeyId/receiptKey32bytes, DPAPI receipt-key file, обычный manifest и Isar с отдельными начальными StoredWorkspace/StoredSettings. Key/manifest flush, durable Isar transaction/close, validate complete empty staging, same-volume rename→default. Ready/RPC только после promotion/reopen/validation; profile save до этого запрещён.

Crash до promotion сохраняет staging. Restart завершает promotion только полностью валидного пустого staging с matching manifest/receipt-key/schema и без active. Partial/invalid staging, active+staging, отсутствующая часть active→storage-blocked; ничего не удалить/перегенерировать. Нельзя заменить partial новой БД. Reset/import/recovery wizard вне001.1; исходные файлы сохраняются.

Manifest обычный JSON `{product:"serverdeck-next",schema:1,workspaceId,receiptKeyId,ownerSid}`. Receipt-key file `receipt-key.dpapi` — DPAPI CurrentUser wrapper `{format:1,product,workspaceId,receiptKeyId,ownerSid,receiptKey}`; случайный32-byte HMAC key не шифрует базу, не передаётся UI и не совпадает с bootstrap token. CRYPTPROTECT_UI_FORBIDDEN, без LOCAL_MACHINE. Entropy receipt-key/discovery — UTF8 `ServerDeckNext\nv1\ndefault\nownerSid\nreceipt` либо последнее слово `discovery`; credential — `ServerDeckNext\nv1\nworkspaceId\nprofileId\ncredentialId\ncredential`. Подставляются actual IDs. Manifest/store/key identities должны совпасть. DPAPI failure блокирует обычные запросы без замены key/blobs. Same-user compromise вне угроз.

Имя файла workspace identity manifest — `workspace.manifest.json` в active/staging directory. Не путать с `foundation.manifest.json` в app-root, который описывает состав development bundle. Repository открывает только existing workspace под удерживаемым mutex; создание файлов и promotion выполняет workspace coordinator.

Persisted encodings v1: manifest ровно пять перечисленных полей, UTF8≤4KiB. Receipt-key wrapper ровно шесть полей выше; receiptKey — canonical standard base64 с padding для32bytes; decrypted JSON≤8KiB, DPAPI file≤16KiB. Credential wrapper ровно `{version:1,workspaceId,profileId,credentialId,kind,password}` либо `{version:1,workspaceId,profileId,credentialId,kind,privateKey,passphrase}`; passphrase null|string; decrypted wrapper≤256KiB, protectedBlob≤256KiB DPAPI bytes, CredentialRecord JSON≤512KiB. Numeric format/schema/version integer, unknown→incompatible; extra fields/identity mismatch/invalid base64→storage-blocked. Bootstrap tokens/proofs сохраняют API base64url без padding.

Pinned Isar3.3.2/MDBX использует data file `workspace.isar` и настоящий native lock file `workspace.isar-lck`. Оба создать с explicit protected ACL до первого Isar.open; проверять safe path и owner/SYSTEM DACL обоих перед каждым open. `workspace.isar.lock` не native lock и не заменяет эту проверку. Нельзя позволить native runtime впервые создать lock с default DACL процесса. При missing/unsafe lock существующее пространство блокируется без его автоматического пересоздания.

## Ordinary records and secret integrity

Isar instance name `workspace`, file `workspace.isar`; ровно пять generated collections. Поля с именем `payload` — обычные JSON strings по data-model, не шифрованный агрегат.

| Collection | Native fields | Cardinality / UTF8 payload bound |
| --- | --- | --- |
| StoredWorkspace | `id:Id=1`, `payload:String` | Ровно1; ≤4KiB; schemaVersion/workspaceId/receiptKeyId/ownerSid/storeRevision |
| StoredSettings | `id:Id=1`, `payload:String` | Ровно1; ≤4KiB; Settings |
| StoredProfile | `id:Id`, `entityId:String`, `payload:String` | ≤250; ≤16KiB; Profile |
| StoredCredential | `id:Id`, `entityId:String`, `payload:String` | ≤250; ≤512KiB; CredentialRecord с DPAPI protectedBlob |
| StoredReceipt | `id:Id`, `entityId:String`, `payload:String` | ≤10 000; ≤4KiB; MutationReceipt |

Для последних трёх `id` — положительный Isar autoIncrement, не бизнес-ID, не переиспользуется для связи или LocalAPI; исчерпание positive uint63→RESOURCE_LIMIT. `entityId` равен Profile.id/CredentialRecord.id/MutationReceipt.requestId из payload. Единственный индекс каждой из трёх коллекций — unique hash `entityId`, caseSensitive=true, replace=false; никаких links, embedded objects или иных индексов. Обновление существующей entity сохраняет native id; удаление credential и вставка replacement имеют разные business IDs. Profile/Credential/Receipt payload содержит ровно собственную entity, без workspace-wide массивов. StoredWorkspace не содержит profiles/credentials/settings/receipts.

Explicit allowlisted libisar load перед open; `maxSizeMiB:64`, `relaxedDurability:false`, `inspector:false`, no compactOnLaunch. Перед открытием существующей базы её snapshot читается без записи под mutex: native metadata registry обязан совпасть с этими пятью generated CollectionSchema (имена, types/properties, indexes, отсутствие links). Unknown well-formed schema→incompatible, malformed snapshot→storage-blocked; не запускать автоматическое удаление/изменение collections посредством Isar.open. Старый experimental StateEnvelope несовместим и не импортируется. Проверка registry нужна до open, не только после возможной native миграции. Имя/версия manifest также проверяются до open. Native metadata parser соответствует pinned Isar3.3.2 и MDBX; bounded read≤64MiB, отсутствие поддержки другой layout не разрешает запись.

После open и перед ready проверить cardinality, UTF8 sizes, repeated/unknown JSON keys, поля/IDs/refs/revisions и DPAPI availability всех blobs. Расшифрованный credential обязан совпасть с workspace/profile/credential IDs и kind записи; не хранить открытый secret в RAM state. Нельзя подменять DPAPI проверку успешным JSON parse. Персистентная transaction атомарно меняет затронутые entities, deletes, receipt и storeRevision. Перед ней проверяются logical quotas/per-record bounds. Native map-full с доказанным rollback→RESOURCE_LIMIT и прежняя ready модель; другие/неопределённые ошибки→storage-blocked до reopen. Reply only after durable commit.

Секреты защищены средствами ОС от другой ordinary учётной записи и копии файлов без полномочий владельца; DPAPI проверяет целостность blob, entropy и wrapper связывают его с доступом. Обычные метаданные, их индексы и receipts не имеют гарантии криптографической конфиденциальности/аутентичности по копии базы. Их доступ ограничен ACL; structural validation обнаруживает нарушенные инварианты. Не обещаются сопротивление admin/kernel/current-account arbitrary code, защита памяти/swap, согласованная подмена/откат всей базы и скрытие размера/времени файлов. Отказ защиты не создаёт новую пустую БД или открытый секрет. 002 расширяет аудит и recovery секретов.

## Lifecycle

В 001.1 SSH/jobs нет. Закрытие последней session/lease expiry запускает shutdown grace 2s; новый authenticated UI в этот срок отменяет shutdown. Если bootstrap ещё идёт и ни одной session не было, действует startup watchdog 30s, а не grace 2s. Не начатые queued mutations отменяются без эффекта; начатая transaction доходит до commit/failure, затем закрываются Isar, pipe slots, discovery, key buffers и mutex. В stopping ordinary RPC отклоняются, UI ждёт disconnect и выполняет bootstrap, не завершает владельца принудительно. Crash сохраняет committed state/receipts, новое поколение требует handshake. Stale discovery удаляется только owner под mutex, не workspace/key.

Расширение job lifecycle в 001.3 обязательно до появления jobs capability; серверное расписание 012 не удерживает locald. Нельзя включить jobs с этой логикой последнего окна.

Lease/watchdog/grace используют monotonic elapsed deadlines. При задержке timer callback grace считается от фактического deadline последней истёкшей session, а не от времени обнаружения expiry; late authentication после grace не возвращает stopping generation в рабочее состояние. Первый grant либо поздний bootstrap completion не отменяют уже истёкший startup watchdog. Внутренний teardown completion означает завершение закрытия ресурсов, не успешный bootstrap: watchdog сохраняет reason TIMEOUT. Неизвестная ошибка cancel/drain/close останавливает цепочку закрытия с безопасным STORAGE_BLOCKED; последующие ресурсы не считаются освобождёнными, mutex не release до подтверждённого Isar close. Эта generation остаётся stopping, ordinary RPC/grants не возобновляются, файлы не reset/rekey. Transport/entry обязаны обработать результат закрытия; ошибка не выдаётся за clean shutdown.

### Concurrent protected-file snapshots — T188

Protected discovery readers must not prevent the mutex owner from atomically publishing the next descriptor. A read retains one existing regular file object with READ/WRITE/DELETE sharing; it validates owner/SYSTEM protected ACL on that handle before reading, rejects directory/reparse/non-disk handles and retains the existing path/parent checks. No owner mutex is acquired by readers. If replacement happens during a read, the reader finishes the old complete object; a new reader sees the new complete object. Read bounds remain1..64MiB with32MiB default (discovery callers use16KiB). Actual bytes are bounded independently of initial file size; native chunks are copied before buffer wipe. Retained reader is single-use and must close on success/failure; closed/consumed/native failures yield safe STORAGE_BLOCKED, excess yields RESOURCE_LIMIT.

On Windows11 x64, regular-file replace uses FileRenameInfoEx with REPLACE_IF_EXISTS|POSIX_SEMANTICS and retained DELETE|READ_CONTROL source handle, supporting delete-sharing readers without a delete-first gap. The source handle receives the same ACL/regular-file checks. Existing protected write+flush precedes rename; no raw fallback, readonly/security override, privilege escalation or retry of denied actions is added. Unsupported/failed native rename blocks publication; unconsumed temporary evidence is preserved. Non-replacing directory promotion keeps the existing primitive. Schema, namespace, permissions and ownership policy are unchanged.
