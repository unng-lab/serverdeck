# Native artifact provenance and qualification — T232/T233

[Plan](../plan.md), [tasks](../tasks.md), [runtime](runtime-storage.md). Constitution VIII / FR-SVC-001/019 / T045/T207. This is a build/distribution contract; storage schema1, Local API1.0, Dart Isar/core/generator/flutter libs3.3.2, crypto custody and user behavior remain unchanged.

## Decision and activation

The published cached DLL has known release identity but no established resolved Rust graph. A fresh graph cannot retrospectively become its provenance. Build a **new** candidate from the same Isar source commit and pinned libmdbx source, qualify compatibility, then make that artifact the build input. Never label the new output as the original release asset or assert bit-for-bit equivalence across different compilers/hosts. Reproducibility here means immutable complete source/dependency/toolchain inputs, recorded commands/features/output hashes and offline repeatable compilation; byte equality across machines is not promised.

Until T233 qualification and review complete, existing private development builds keep their original cached DLL and distributionReady=false. Qualification is not full001.1/Q/manual acceptance. Once activated, missing/unqualified/mismatched source artifact blocks normal bundle generation; no silent cached/native/PATH/download fallback. Runtime still loads only manifest-bound app-root/libisar.dll and never reads build overrides or downloads anything.
