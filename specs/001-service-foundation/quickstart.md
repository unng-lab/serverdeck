## Setup/build

Windows 11 x64, PowerShell 7.4+, VS2022 Build Tools Desktop C++, VC++2015–2022 x64 runtime, pinned Flutter3.47.7 / bundled Dart3.13.5. Получить SDK из official manifest, проверить SHA256 из [Plan](plan.md). SDK ожидается в `.local/sdk/3.47.7/flutter` либо по абсолютному `SERVERDECK_FLUTTER_ROOT`. Команды из root:

```powershell
. ./tools/foundation-sdk.ps1
Invoke-FoundationCommand $FoundationFlutter @('doctor', '-v')
./tools/run-foundation.ps1 -Configuration Debug -BuildOnly
./tools/run-foundation.ps1 -Configuration Debug
```

Script использует pinned SDK и [runtime layout](contracts/runtime-storage.md), root/package locks, Isar generation и сборку обоих процессов до UI. `-BuildOnly` не запускает UI; без него данные сохраняются в новом namespace текущего OS пользователя, не временном fixture. Отдельный ручной locald start и runtime download не нужны. Второй UI присоединяется к тому же owner/space. Сеть нужна для dependencies; отдельная заблокированная сетью offline приёмка ещё открыта. Exact direct pins и lockfiles обязательны; неподходящий SDK отклоняется без изменения данных.

## Native harness

`tools/test-foundation-native.ps1 -DisposableEnvironment` (default `All`) пока намеренно завершается ошибкой: full harness T043 не завершён. Первый отдельный compiled scenario запускается так:

```powershell
./tools/test-foundation-native.ps1 -Scenario WorkspaceLifecycle
./tools/test-foundation-native.ps1 -Scenario CoreStorage
./tools/test-foundation-native.ps1 -Scenario CommitRecovery
./tools/test-foundation-native.ps1 -Scenario ApiCommitRecovery
./tools/test-foundation-native.ps1 -Scenario InitializationRecovery
./tools/test-foundation-native.ps1 -Scenario SecretMarkers
```

Он собирает normal Debug bundle и отдельный AOT test entry с build-time whitelist нового protected `.local/native-acceptance-<GUID>` и текущего SID. Сценарий проверяет actual Workspace/DPAPI/Isar creation/reopen/staging/corruption/preservation через verified normal bundle; normal test-flag negatives до/после изменения manifest, test manifest/foreign-image/runtime-override negatives и запрет reset использованного fixture. Файлы сохраняются, cleanup использует только retained launched child handle. Это owned filesystem fixture текущего пользователя, не disposable OS user/VM, не compiled crash failpoints и не полная Q01–Q12. Действующие UI scenarios описаны выше; ни один partial scenario не закрывает все native gates.

`CoreStorage` запускает восемь allowlisted cases в отдельных AOT processes одного verified build: workspace, repository, credential snapshots, coordinator mutations, API router, actual native channel, service lifecycle и quotas. Protected exclusive claim не позволяет повторить case, включая failed attempt; данные каждого case изолированы в `cases/<name>`, root/runtime paths не принимаются из CLI. Все required markers уникальны, после каждого positive case проверяется reject reuse; final proof записывается только после всех successes. Fixture budget180s/case, для resource-limits360s по существующей native workload; production RPC/startup limits не меняются. Credential snapshots — repository-level проверки, API router использует controlled session, lifecycle — controlled clock; channel использует настоящие kernel peer checks и native I/O в одном process. Это не полный normal owner/UI или Cross-user/native failure matrix.

`CommitRecovery` проверяет hard crash внутри uncommitted native row transaction и после durable StateStore.commit. Boundary marker flushed; driver ждёт≤30s, проверяет retained launched image/lifetime, завершает только этот child и подтверждает exit≤10s. Новый AOT verifier открывает тот же case: state/profile/credential/receipt0 до commit либо1 после, DPAPI secret после commit доступен. Native-handle invalidation и DPAPI-availability — отдельные controlled fault seams с fresh-process verification, не реальные отказы ОС. Writer/verifier имеют отдельные exclusive claims; verifier требует writer claim и existing directory, не создаёт missing workspace. Повтор фаз отвергается, файлы сохраняются. Это не coordinator/API transaction crash, init/reply crash, reboot или other-user acceptance.

`InitializationRecovery` выполняет девять аварийных остановок настоящего Workspace.open: staging/key/manifest/native files, незавершённые initial rows, durable transaction, before/after promotion и active-opened. Guarded instrumentation включён только compile-time define отдельного TestBuild; обычная сборка не допускает handler и не принимает runtime controls. Writer сохраняет protected metadata-only boundary record и останавливается до завершения open. Новый verifier требует существующие case/record: первые пять стадий остаются STORAGE_BLOCKED с сохранением inventory и key/manifest identities, последние четыре открывают initial-empty state и при необходимости завершают promotion. Остановка внутри transaction следует записи обеих initial rows. DB/lock bytes после native reopen и полный secret-marker scan этим не принимаются. Normal/test guards, phase claims и owned Process cleanup сохраняются; reboot/other-user/reply crash/full All остаются открытыми.

Inventory проверяется по точным именам и типам, не только количеству. Дополнительный single-use negative case заменяет имя owned synthetic workspace.isar на unexpected.isar при неизменном числе4files: verifier обязан отвергнуть это до native open, сохранить bytes replacement и не допустить повтор фаз. Final proof содержит9successfulpairs и отдельный inventoryReplacementRejected=true.

`SecretMarkers` сохраняет2profiles (password и PEM/passphrase) и settings через real coordinator/ApiServer/Workspace/DPAPI/Isar, затем проверяет их новым процессом. Обычные metadata читаются из native payload до DPAPI; секреты раскрываются через CurrentUser protection. Сканируются owned case files до защиты/после commits/close, включая DB/index/lock/key/manifest, и ответы API; raw UTF8/UTF16LE/base64, PEM body и receipt-key markers не должны появляться открыто. Fixture input задаётся только при TestBuild из markers.json, runtime override отсутствует, writer/verifier одноразовые. Strict stdout/stderr allowlist исключает private output. Source/test binaries с намеренными fixture inputs и чужие OS Temp/pagefile/dumps не сканируются. Router session controlled; это native persistence часть Q05, не полный normal owner/UI/auth/diagnostic matrix.

Перед прямым native чтением verifier проверяет owner-only ACL всех файлов. Отрицательная проверка unsafe ACL выделена в `SecretMarkersUnsafeAcl` для подготовленной disposable среды: текущий Set-Acl был отклонён ОС из-за отсутствующей SeSecurityPrivilege и остаётся deferred/open. Не повторять отклонённую операцию другим инструментом/runner. Обычный SecretMarkers её не запускает и явно сохраняет unsafeAclRejected=false; этот proof не закрывает T185/Q06.

Ниже обязательный контракт полного harness, а не выполненная полная приёмка.

Полный harness должен запускать compiled layout в disposable VM/test OS user. Alternate test namespace/failpoints доступны только build с testOnly manifest. Normal dev/prod build должен отвергать test-client/auth/failpoint/root flags: эти пути отсутствуют в его compiled runtime, не включаются правкой manifest. Whitelist создаётся при test build, не через remote API. Normal-build negative test обязателен; fixtures не подменяют normal UI.

Failpoints: before/after commit, after commit/before reply, DPAPI/ACL/native DLL failure, partial frame, init after key/before DB/after DB/before promotion/after promotion. Kill только retained owned harness child с проверенным test manifest и identity, не старый/чужой process. Scan synthetic markers в persistent DB/files/temp/stdout/stderr/logs. Не публиковать unsafe error buffers, VM service auth URI или намеренно раскрытые test secrets. Наличие ciphertext не считать plaintext leak.
