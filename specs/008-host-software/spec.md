# Feature Specification: ПО сервера и работа ИИ через shell

**Feature**: 008-host-software

**Created**: 2026-11-09

**Status**: Таблица ПО C06 и компактный список событий C07 реализованы; unit/static-приёмка и независимое ревью завершены

**Input**: ИИ работает с сервером через существующее SSH-подключение,
ведёт карточки ПО через MCP; пользователь видит карточки и историю действий.

## Цель и границы

ServerDeck предоставляет внешнему ИИ доступ к своей консоли и локальный учёт ПО.
ИИ выбирает команды установки, проверки, изменения конфигов, запуска и удаления,
читает вывод и решает, что делать дальше. Пользователь видит ту же консоль.

Карточка ПО содержит название, версию, службу, пути к данным и конфигам.
Она редактируется как обычная запись. История содержит изменения карточек
и сообщения автора о выполненной работе; доступный вывод команд виден в консоли.

Функция не включает встроенную модель ИИ, каталог установочных рецептов,
автоматические установки и фоновое обследование серверов.

## User Scenarios & Testing

### US-801 — ИИ работает с сервером (Priority: P1)

Пользователь подключился к серверу и поручил внешнему ИИ установить или обслужить ПО.
ИИ использует доступную консоль, выполняет команды и читает результаты.

**Why this priority**: Это основной способ работы с сервером.

**Independent Test**: На подставном подключении проверить общий ввод/вывод UI и ИИ.

**Acceptance Scenarios**:

1. **AC-801** ИИ открывает консоль подключённого сервера; пользователь видит эту
   сессию и её вывод в ServerDeck. Дополнительная установка на сервер не требуется.
2. **AC-802** ИИ отправляет команду и читает вывод. Подтверждение отправки ввода
   не выдаётся за успешное завершение установки. При потере связи результат может
   остаться неизвестным; приложение не отправляет команду повторно автоматически.
3. **AC-803** ИИ читает и меняет конфиг обычными командами, затем при необходимости
   проверяет его и перезапускает службу. Права определяет SSH-пользователь.
4. **AC-804** Отзыв доступа ИИ запрещает следующий ввод и чтение защищённого вывода.
   Пользователь продолжает работать через существующий интерфейс подключения.

### US-802 — Карточки установленного ПО (Priority: P1)

ИИ или пользователь создаёт, читает, изменяет и удаляет карточки ПО выбранного хоста.

**Why this priority**: Учёт остаётся доступным после завершения консоли.

**Independent Test**: Проверить сохранение полей, чтение, конфликт редакций и удаление.

**Acceptance Scenarios**:

1. **AC-805** Сохранённые название, версия, служба и пути одинаково видны UI и ИИ.
   Неизвестные версия или служба могут быть пустыми; приложение не угадывает их.
2. **AC-806** Изменение устаревшей редакции отклоняется без затирания новой записи.
   На одном хосте допустимы несколько карточек одного продукта.
3. **AC-807** Сохранение или удаление карточки меняет только локальный учёт.
   Оно не устанавливает и не удаляет ПО, файлы или службу на сервере.
4. **AC-808** Карточки сохраняются после перезапуска. При смене адреса профиля
   видна исходная цель карточки; она не переносится молча на другой хост.
5. **AC-814** ПО показано таблицей с названием, версией и службой; исходный адрес остаётся
   в подробностях; неизвестные version/service — «Не указана».
   «Подробности» выбирают одну запись и дают все поля, UTC и четыре прежних
   действия в отдельной области. Выбор другой строки заменяет сведения,
   повторное нажатие или «Закрыть подробности» закрывает их.
6. **AC-815** Выбор записи не вызывает owner/MCP/SSH или запись в журнал.
   Refresh сохраняет оставшийся id и обновляет сведения; профиль/страница/фильтр
   ПО сбрасывают выбор. Для другой цели пометка видна рядом с названием ПО; изменение и
   консоль недоступны, локальное удаление/история доступны по прежним pending.

7. **AC-818** В строке ПО есть «Логи»: для текущей цели и корректной systemd
   `.service` открываются «Журналы» того же профиля с поиском этой службы и
   выбранным journal-источником. Существующий источник переиспользуется, включая
   его паузу; отсутствующий добавляется по обычным правилам005. Для другой цели,
   пустой/невалидной службы или недоступных журналов действие disabled с причиной.
   Хост остаётся в подробностях. Ошибки и устаревший контекст не показывают логи
   другой службы/сервера и не затирают ручной выбор пользователя.

### US-803 — История работы (Priority: P1)

Пользователь видит, кто менял карточку и что ИИ сообщил о выполненных действиях.

**Independent Test**: Проверить события сохранения/удаления и заметку ИИ на fake store.

**Acceptance Scenarios**:

1. **AC-809** Создание, изменение и удаление карточки записывают событие с автором
   и временем. Сбой сохранения не оставляет отдельно карточку или её событие.
2. **AC-810** ИИ добавляет краткое сообщение, например «изменён конфиг Redis».
   Интерфейс показывает автора сообщения и сообщённый исход, не превращая текст
   сообщения в автоматически проверенное состояние службы.
3. **AC-811** После удаления карточки её события остаются в истории хоста.
   Постоянный журнал не содержит отдельной записи введённых команд и вывода;
   текущий экран и ограниченная история консоли доступны по её обычным правилам.
4. **AC-816** Событие изначально свёрнуто. Сводка показывает тип и имя ПО
   (либо «Хост»), автора, время UTC, сообщённый исход при его наличии и короткое
   превью сообщения. «Подробности события» за одно раскрытие дают полный исходный
   текст, цель, тип, автора/время и необязательные action/outcome/changedFields.
   При сворачивании остаётся сводка; исходный текст не изменяется и не теряется.
5. **AC-817** Строки списка событий раскрываются независимо по eventId с клавиатуры и указателя.
   Обычный refresh сохраняет раскрытие оставшихся id; смена профиля, страницы
   истории или фильтра истории хоста/карточки сбрасывает его. Раскрытие не читает
   owner/MCP/SSH, не изменяет карточки/журнал и не подтверждает состояние службы.

### US-804 — Анализ сервера (Priority: P2)

Пользователь поручает ИИ найти ПО, при необходимости перечисляя интересующие программы.
ИИ обследует сервер через ту же консоль и предлагает заполненные карточки.

**Independent Test**: Проверить подготовку задания, предложение и обычное сохранение карточки.

**Acceptance Scenarios**:

1. **AC-812** Задание содержит выбранный сервер и пожелания пользователя, без credentials.
   ServerDeck сам не запускает обследование и не требует отдельного анализатора.
2. **AC-813** ИИ может предложить несколько экземпляров ПО и оставить неизвестные
   поля пустыми. Согласованные карточки сохраняются обычным действием сохранения;
   предложение обсуждается во внешнем ИИ-клиенте.

### Edge Cases

- Подключение отсутствует: shell недоступен; локальные карточки и журнал читаются.
- Консоль занята другим вводящим: действуют её обычные правила владения вводом.
- Недостаточно системных прав или конфиг повреждён: ИИ получает вывод сервера;
  ServerDeck не обещает исправление, откат или остановку удалённого процесса.
- Хост сменился, профиль удалён, карточка удалена или одновременно отредактирована.
- Ответ сохранения потерян, история консоли вытеснена, приложение перезапущено.
- Ошибочные поля, слишком большие записи и сообщения отклоняются без усечения.

## Requirements

### Functional Requirements

- **FR-801**: MUST использовать общую существующую консоль выбранного SSH-подключения
  для команд ИИ и пользователя; все действия на сервере инициирует пользователь или ИИ (AC-801–803).
- **FR-802**: MUST сохранять действующие правила доступа, владения вводом и обработки
  потери связи; автоматического повторения команд нет (AC-802,804).
- **FR-803**: MUST дать ИИ работать с конфигами через тот же shell (AC-803).
- **FR-804**: MUST хранить карточки с названием, версией, службой и списками путей
  данных/конфигов, допуская неизвестные необязательные сведения (AC-805,813).
- **FR-805**: MUST предоставить одинаковые CRUD-действия карточек в UI и MCP,
  с проверкой редакции при изменении/удалении (AC-805–807).
- **FR-806**: MUST связывать карточку с профилем и исходным хостом (AC-808).
- **FR-807**: MUST сохранять карточки и журнал локально между запусками (AC-808–811).
- **FR-808**: MUST атомарно фиксировать изменение карточки и его событие (AC-809).
- **FR-809**: MUST принимать краткие сообщения о работе через UI/MCP, назначая
  автора и время в приложении (AC-810).
- **FR-810**: MUST показывать сообщения как сообщения автора и отдельно давать
  доступ к существующей истории консоли (AC-810–811).
- **FR-811**: MUST поддержать подготовку задания на анализ и обычное сохранение
  предложенных ИИ карточек (AC-812–813).
- **FR-812**: MUST сохранять профили, credentials и данные других функций;
  удаление профиля удаляет его локальные карточки/журнал, без команд на хост (AC-807–808).
- **FR-813**: MUST показывать ПО готовой таблицей с полями название/версия/служба
  и отдельными подробностями выбранной записи, сохраняя данные, доступность действий
  и привязку к исходному хосту (AC-814–815). Состав и поведение определяет
  [контракт компактной карточки](contracts/tools.md#компактная-карточка-по--2026-11-10).
- **FR-814**: MUST показывать события готовым компактным списком со сводкой и раскрывать полный текст
  и метаданные по явному запросу, сохраняя происхождение и сообщённый характер
  исхода, порядок/пагинацию/retention истории (AC-809–811/816–817).
  [UI-контракт событий](contracts/tools.md#компактное-событие-истории--2026-11-10).

- **FR-815**: MUST предоставить переход «Логи» от строки ПО к журналу точной
  службы по [контракту перехода](contracts/service-logs.md), сохраняя ограничения
  доверия/соединения/хранения005; не выполнять команды службы или автоматическое
  подключение. В таблице нет колонки хоста, исходная цель доступна в подробностях
  и через предупреждение другой цели (AC-818).

### Key Entities

Интерфейс использует общие C02/C03/C04/C05/C06/C07/C08/C09/C10/C11/C12/C13/C16/C18/C19/C20/C26/C28
из [библиотеки 001](../001-design-system/component-library.md); приёмка проверяет данные и действия.

- **Карточка ПО**: идентичность, исходный хост, название, версия, служба, пути, редакция и время изменения.
- **Событие журнала**: хост, необязательная ссылка на карточку, автор, время, тип события и краткое сообщение.
- **Консоль**: существующая общая сессия ввода/вывода выбранного подключения.

## Success Criteria

- **SC-801**: Один и тот же сохранённый набор полей читается через UI и MCP без расхождений.
- **SC-802**: В сценариях установки и изменения конфига используется одна видимая пользователю консоль.
- **SC-803**: В проверках конкурирующего сохранения — ноль потерянных новых редакций;
  при сбое транзакции — ноль частично сохранённых пар «карточка/событие».
- **SC-804**: Карточки и сообщения переживают перезапуск; удаление карточки не стирает её журнал.
- **SC-805**: Анализ и последующее сохранение проходят теми же действиями, что обычная работа ИИ и CRUD карточек.
- **SC-806**: Все записи показанной страницы ПО читаются как одна таблица с
  тремя полями сравнения; технические пути, время и панель действий не
  повторяются для каждой строки. Полный набор сведений и действий доступен
  за один выбор строки. Functional acceptance — AC-814/815, без геометрии.
- **SC-807**: В исходном состоянии ни одно событие не показывает полный набор
  метаданных и полное многострочное сообщение; все исходные сведения доступны
  за одно раскрытие. Превью ограничено 160 Unicode code points с явным «…» при
  сокращении; многоточие входит в предел160. Для текста длиной160 показываются
  все160, для161 и более — первые159 и «…». Приёмка проверяет данные,
  доступность и переходы AC-816–817,
  без измерения геометрии страницы.

## Assumptions

- Пользователь использует внешний ИИ-клиент с действующим доступом MCP.
- Приложение не выбирает установочные команды и не интерпретирует конфиги за ИИ.
- Результаты обследования, переданные ИИ, являются заполненными им данными.
- Карточки и сообщения не предназначены для паролей, токенов и содержимого конфигов.
- Существующие ограничения хранения истории консоли сохраняются; журнал ПО — отдельные краткие события.
