# Feature Specification: 002 — Приложение, один EXE и системный трей

**Feature**: `002-desktop-runtime`
**Created**: 2026-11-02
**Amended**: 2026-11-03 — по указанию пользователя только юнит-тесты; интеграционная/VM приёмка исключена.
**Status**: Реализация и unit-only приёмка завершены 2026-11-03; независимое ревью без замечаний.
**Input**: Одно приложение Flutter + Isar, поставка одним EXE; закрытие окна скрывает
приложение в трей, завершение пользователем — только через трей. Никаких отдельных
приложений и служб. Встроенный MCP и SSH продолжают работу при скрытом окне.

## Уточнение 2026-11-06: подтверждённое обновление

Constitution4.0.0 и [FR-621–623](../006-install-update/spec.md) добавляют единственное
исключение к историческому правилу tray-only: «Обновить и перезапустить» для
проверенного подготовленного выпуска, с отдельным подтверждением и тем же shutdown.
Ни обычный выход из окна/MCP, ни отдельный перезапуск в трее не добавляются.
Все формулировки tray-only ниже относятся к обычному выходу; контракт обновления
и его приёмка находятся в пакете006. История приёмки002 сохранена.

## Test policy

По прямому указанию пользователя (2026-11-03) обязательны только юнит-тесты
изолированных компонентов, включая функциональные widget tests с подставными
зависимостями и native adapter tests. Acceptance Scenarios и SC ниже описывают
ожидаемое поведение продукта, не команды интеграционного прогона.
VM, end-to-end, release smoke и реальные crash/process-kill сценарии не входят
в задачи, CI или условия завершения. Изоляция не меняет продуктовые требования;
юнит-результаты не подтверждают фактическую интеграцию на чистой ОС.

## User Scenarios & Testing

### Уточнение поставки 2026-11-04 — пакет 006

По подтверждению пользователя скачивается полный офлайн-установщик
`ServerDeckSetup.exe`, устанавливающий самодостаточный `ServerDeck.exe`.
Это заменяет ниже прежнее описание получения одного EXE для прямого запуска
в US1/AC-201/FR-201 и Assumptions. Требования 002 к встроенному runtime,
данным, singleton и трею остаются действующими. Portable-поставка не является
приёмкой новой функции. Установщик, обновление и удаление определены
[пакетом 006](../006-install-update/spec.md); старые task/evidence остаются историей
реализации runtime и не доказывают готовность нового установщика.

### User Story 1 — Запустить готовое приложение (Priority: P1)

Пользователь получает `ServerDeck.exe` и запускает его без установки СУБД,
интерпретаторов, дополнительных приложений или скачивания зависимостей.

**Why this priority**: Приложение должно работать как единый готовый продукт.
**Independent Test**: Юнит-проверки manifest/bounds, singleton adapter и store preflight
на синтетических входах; сборка и статический аудит встроенных зависимостей.

**Acceptance Scenarios**:

1. **AC-201 Given** один файл релиза, **When** он запущен, **Then** открыто одно главное
   окно, доступен трей, локальные данные открыты без сети и сторонних установок.
2. **AC-202 Given** приложение уже работает, **When** запущен тот же EXE повторно,
   **Then** восстановлено/активировано прежнее окно; нет второго владельца базы,
   второго трея, второго MCP-сервера и дублированных SSH-сеансов.
3. **AC-203 Given** сохранённые данные, **When** EXE перемещён или заменён совместимым
   релизом при закрытом приложении, **Then** прежние данные доступны тому же пользователю.
4. **AC-204 Given** база не может быть открыта, **When** приложение запускается,
   **Then** видна ошибка и действие повторить; существующие данные не заменены пустой базой.

### User Story 2 — Закрыть окно и продолжить работу (Priority: P1)

Пользователь закрывает окно и возвращается к приложению из системного трея.
Скрытие окна не прекращает подключений и не меняет хранимые данные.

**Why this priority**: Закрытие окна не должно завершать фоновую работу приложения.
**Independent Test**: Изолированно передать close/restore/tray-loss события в native
adapter и coordinator; проверить тот же owner, черновик и callbacks на fakes.

**Acceptance Scenarios**:

1. **AC-205 Given** работающее окно, **When** нажаты крестик или Alt+F4,
   **Then** окно скрыто в трей, процесс остаётся жив, база остаётся открытой;
   при наличии SSH/MCP они продолжают работу.
2. **AC-206 Given** скрытое окно, **When** выбран пункт трея «Открыть» или выполнен
   двойной щелчок по значку, **Then** восстановлено то же окно и текущие данные;
   это не перезапуск и не автоматическое переподключение к серверам.
3. **AC-207 Given** значок трея не удалось создать/восстановить, **When** запрошено
   закрытие окна, **Then** окно остаётся доступным, показана ошибка и повтор
   инициализации трея; приложение не исчезает без способа восстановления.

### User Story 3 — Полностью завершить приложение (Priority: P1)

Пользователь выбирает «Выход» в трее и завершает всё приложение, включая SSH/MCP,
без потери уже сохранённых данных.

**Why this priority**: Нужна одна явная команда завершения вместо независимых процессов.
**Independent Test**: Передать Exit и ошибки стадий synthetic owners; проверить
admission, drain, deadline, retry и отсутствие повторных операций.

**Acceptance Scenarios**:

1. **AC-208 Given** приложение работает, **When** выбран «Выход» в трее,
   **Then** новые операции не принимаются, незавершённые подключения отменены,
   SSH/MCP закрыты, завершены записи, закрыта Isar, удалён трей и завершён экземпляр.
2. **AC-209 Given** команда выхода уже выполняется, **When** повторно нажат выход
   или пришёл MCP-запрос, **Then** второго shutdown нет, новый запрос получает
   отказ «Приложение завершает работу», сохранённые операции не дублируются.
3. **AC-210 Given** сбой/принудительное завершение, **When** приложение вновь запущено,
   **Then** подтверждённые записи сохранены, частичные изменения не выдаются за успех,
   SSH отключены, ранее обнаруженные предупреждения доверия доступны.

### Edge Cases

- Нет прав на каталог данных или распаковки, нет места, повреждена встроенная библиотека.
- Повторный запуск при старте, скрытом окне, ошибке базы или выполняющемся выходе.
- Explorer перезапущен и значок трея потерян; экран заблокирован или Windows завершает сеанс.
- Ошибка закрытия базы, запись одновременно с выходом, поздний сетевой callback.
- Изменения MCP при скрытом окне; окно содержит несохранённый черновик.

## Requirements

### Functional Requirements

- **FR-201**: MUST поставляться один `ServerDeck.exe` со всеми необходимыми
  runtime-зависимостями. Никаких обязательных соседних DLL/assets, установок
  Flutter/Dart/Isar/SSH/Node/Python, отдельного backend, сервиса Windows или СУБД.
  Установка зависимостей и загрузка из интернета при первом запуске не требуются.
- **FR-202**: Внутренняя распаковка встроенных библиотек/assets MUST происходить
  автоматически в управляемом каталоге текущего пользователя, без admin-прав и
  отдельного устанавливаемого приложения. Неполная/повреждённая распаковка не запускает
  смешанный комплект: либо используется целый комплект версии, либо показана ошибка
  и возможность повтора. Удаление кэша runtime не удаляет пользовательские данные.
  Сам EXE может находиться в каталоге только для чтения.
- **FR-203**: UI MUST быть на Flutter, база локальных данных — встроенная Isar,
  без процесса СУБД. Постоянные профильные данные/доверие/настройки/история повторов
  хранятся в Isar; секреты защищены средствами ОС и не сохраняются открыто.
  Один владелец базы и операций обслуживает UI и MCP. Isolates/потоки допустимы,
  отдельное постоянно работающее приложение/служба или второй независимый store — нет.
- **FR-204**: Данные MUST принадлежать текущему пользователю ОС, находиться отдельно
  от EXE/runtime-кэша и открываться без сети. Смена пути EXE не создаёт новое пространство.
  Ошибка открытия, несовместимая схема или повреждение базы блокируют операции с данными
  и явно показываются; запрещён тихий reset, затирание или открытие пустой замены.
  Совместимые обновления сохраняют данные; откат к несовместимой версии отказывает
  без изменения базы. Миграции не считаются выполненными по наличию новых файлов.
- **FR-205**: На пользователя Windows MUST работать один экземпляр ServerDeck,
  независимо от пути копии EXE. Обычный повторный запуск активирует прежнее окно и завершает
  только дубликат. Во время shutdown второй запуск сообщает, что приложение завершает
  работу, и не открывает базу параллельно; после окончания пользователь запускает снова.
  Если прежний экземпляр недоступен, нельзя запускать второго владельца до освобождения
  блокировки; показывается ошибка/повтор, данные не переинициализируются.
- **FR-206**: Первый обычный запуск MUST показывать главное окно и создавать трей. Запуск
  автоматически при входе Windows не включается и не входит в scope. Пункт «Открыть»
  и двойной щелчок восстанавливают/активируют существующее окно. Сворачивание обычной
  кнопкой минимизации остаётся стандартным сворачиванием окна; крестик/Alt+F4 скрывают в трей.
- **FR-207**: Скрытие окна MUST сохранять черновики в памяти, состояние UI и работу
  владельцев SSH/MCP/Isar; оно не означает disconnect, cancel, logout или выход.
  При восстановлении видны актуальные данные, включая изменения MCP, без второго bootstrap.
  При конфликте сохранённого черновика с внешним изменением действует проверка версий,
  а не молчаливая перезапись. Подтверждения не принимаются автоматически при скрытии.
- **FR-208**: В трее MUST быть «Открыть» и «Выход». В главном окне, MCP, клавиатурном
  закрытии окна и стороннем remote API нет альтернативной команды нормального выхода.
  Подтверждение пункта «Выход» не требуется: несохранённые черновики отбрасываются;
  сохранённые данные не удаляются. Повторный выход не запускает повторное завершение.
- **FR-209**: Если трей недоступен, MUST сохраняться видимое доступное окно и действие
  «Повторить создание значка». После перезапуска Explorer значок восстанавливается;
  при неуспехе скрытое окно возвращается на экран с ошибкой. Пока доступного трея нет,
  крестик не скрывает последнее окно и не завершает процесс.
- **FR-210**: При выходе MUST атомарно фиксироваться переход к shutdown: UI/MCP больше
  не начинают записи/подключения, попытки отменяются, сеансы закрываются, MCP перестаёт
  принимать запросы, уже начатые локальные записи завершаются целиком или откатываются,
  после чего Isar закрывается и приложение завершается. Поздние callbacks не начинают
  новую запись. Итог записи доступен при следующем запуске, а не считается успехом
  только потому, что отправлен запрос сохранения.
- **FR-211**: При штатных условиях выход MUST завершаться не позднее 10 секунд.
  Если безопасное закрытие не удалось, процесс не завершает себя принудительно:
  возвращает окно с причиной, оставляет трей и возможность повторить «Выход».
  Новые операции остаются заблокированы до завершения; MCP уже выключен, SSH закрываются.
  При следующем выборе выхода продолжается безопасное закрытие, а не повтор записи.
- **FR-212**: Принудительное завершение/сбой/завершение ОС не подменяются нормальным
  пользовательским выходом. При запросе завершения сеанса ОС приложение пытается
  выполнить тот же безопасный shutdown в доступное ОС время и не препятствует
  завершению Windows. При следующем запуске подтверждённые записи сохраняются,
  SSH-соединения не восстанавливаются автоматически. Целостность записи не зависит
  от успешного закрытия окна или наличия отдельной службы.
- **FR-213**: Встроенные возможности SSH/MCP принадлежат [003](../003-ssh-mcp/spec.md).
  Runtime обеспечивает их запуск/остановку и общие данные, не добавляет отдельные
  операции над серверами. MCP по умолчанию выключен; при включении работает в трее,
  после restart настройка включения сохраняется, клиентские разрешения сохраняются
  до отзыва или истечения срока по 003. Ошибка MCP-канала не останавливает UI/SSH; видны причина и явный повтор.
  MCP-запросы не запускают основное приложение автоматически. Тот же EXE
  допускает режим `--mcp-stdio --client <id>`: процесс-мост без окна/трея, открытия
  Isar или собственных SSH-сеансов; только stdio ↔ канал основного экземпляра.
  Это не дубликат основного приложения, не отдельный EXE и не служба. При остановке
  владельца/EOF клиента мост завершает только себя; правило «Выход только в трее»
  относится к основному приложению. Подробности авторизации определяет 003.
- **FR-214**: Главное окно и служебные сообщения MUST использовать готовые C01/C02,
  C10/C11/C12, C14, C17 из [001](../001-design-system/spec.md). Трей использует системное
  меню и брендовые assets 001, без отдельного стиля приложения. Приёмка проверяет
  lifecycle, данные, доступность действий и callbacks; геометрия, golden/screenshots,
  overflow и дизайн-матрицы feature-экранов не входят в тесты и приёмку.

### Key Entities

- **Экземпляр приложения**: текущий пользователь ОС, единственный владелец UI,
  трея, базы и встроенных возможностей; состояния startup/running/shutting-down/ошибка закрытия.
- **Состояние окна**: видно/свёрнуто/скрыто в трее; не равно состоянию процесса.
- **Локальные данные**: Isar, версия схемы и защищённые секреты отдельно от runtime.
- **Комплект runtime**: встроенные в EXE библиотеки/assets версии и управляемая распаковка;
  не новое приложение пользователя и не отдельная служба.

## Success Criteria

### Measurable Outcomes

- **SC-201**: Единственный полученный EXE запускается обычным пользователем без сети
  и дополнительных установок на чистой Windows; открывает сохранённые данные
  после перемещения/совместимой замены EXE (AC-201, AC-203, FR-201–204).
- **SC-202**: Повторный запуск создаёт ноль дополнительных владельцев базы/трея/MCP-сервера;
  пользователь возвращается в прежнее окно (AC-202, FR-205).
- **SC-203**: Крестик и Alt+F4 не завершают экземпляр, не рвут SSH/MCP и не стирают
  черновик; восстановление показывает текущие данные (AC-205–206, FR-206–207).
- **SC-204**: Нет сценария, в котором штатное скрытие окна оставляет пользователя без
  окна и доступного трея; сбой трея объяснён (AC-207, FR-209).
- **SC-205**: «Выход» останавливает все части приложения; нормальный shutdown занимает
  не более 10 секунд, ошибка безопасного закрытия показана без потери подтверждённых
  записей; новый запуск не восстанавливает SSH (AC-208–210, FR-210–212).
- **SC-206**: При отказе базы/распаковки и принудительном завершении сохранённые данные
  не заменяются пустыми; приложение не объявляет недоступные функции работающими
  (AC-204, AC-210, FR-202–204, FR-212–213).

### Граница runtime и MCP-моста

Режим `--mcp-stdio` из 003 — транспортный процесс того же поставляемого EXE,
не обычный повторный запуск. Он не открывает UI/трей/Isar и не требует отдельного
выхода через трей. Его EOF/ошибка не завершает основное приложение и не стирает
профили. Основной экземпляр отсутствует — мост отказывает, а не запускает его.
На этапе 002 runtime обязан различать зарезервированный режим и обычный запуск;
до реализации 003 этот режим явно сообщает «MCP ещё недоступен» и завершается.
Включение/работа MCP не является обязательной приёмкой одного только пакета 002;
проверки контракта 003 также подчиняются общему правилу только юнит-тестов. Runtime 002 проверяет lifecycle встроенных
возможностей на синтетических владельцах без настоящих SSH/MCP.

## Assumptions

- Этот пакет выделяет описание приложения и lifecycle из SSH/MCP-функции 003; является
  её runtime-предпосылкой. Порядок реализации: база приложения 002, затем SSH/MCP 003.
  Порядок пакетов согласован пользователем: 001 → 002 → 003. Старые IDs
  FR/AC/SC-3xx этого runtime перенумерованы в 2xx; прежний снимок сохранён вне проекта.
- Целевая среда — Windows 10/11 x64, обычная интерактивная пользовательская сессия.
  Отдельные профили данных/владельцы на разные ОС-учётные записи допустимы.
  Первичная рабочая папка данных — пользовательская область приложения, не каталог EXE.
- Один EXE означает один доставляемый файл; пользовательские данные и внутренняя
  распаковка библиотек допустимы. Нельзя требовать от пользователя разбирать ZIP,
  копировать DLL или устанавливать внешний runtime. Механизм упаковки определяется Plan,
  а результат проверяется как свойство релиза, не предполагается по обычному Flutter build.
- Flutter/Isar закреплены [конституцией](../../.specify/memory/constitution.md).
  Конкретные версии Isar/native bindings, схема базы, миграции, структура исходников и
  способ упаковки относятся к Plan, а не выбираются из прежнего архивного приложения.
- Пользовательская команда выхода только в трее; сбои, OS shutdown и завершение
  повторного запуска — явные исключения, не дополнительные команды выхода.
- Вне scope: автообновление, установщик, автозапуск Windows, удалённый MCP, серверные
  службы, новый дизайн экранов. Существующий каталог 001 — инструмент разработки,
  не дополнительное приложение релиза.
