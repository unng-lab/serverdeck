# Feature Specification: Установка и обновление ServerDeck

**Feature**: `006-install-update`
**Feature Branch**: текущая рабочая ветка; отдельная ветка не создавалась.
**Created**: 2026-11-04
**Status**: Реализовано, включая подключённую public policy в стандартную поставку (FR-619, T073–076); проверки и независимое ревью завершены. Публикация prepared release assets — отдельное действие издателя.
**Input**: Выделить установку и обновление программы в отдельную спецификацию.
Пользователь выбрал проверку новой версии и установку по своему подтверждению.

## Clarifications

### Session 2026-11-04

- Пользователь скачивает установщик, запускает его и устанавливает ServerDeck.
  Скачанный файл не является приложением для прямого запуска без установки.
- Для этой функции подтверждённая модель поставки заменяет прежний сценарий
  скачивания и прямого запуска `ServerDeck.exe` из пакета 002 и принципа IV
  конституции. Установщик и установленное приложение — разные артефакты;
  установленное приложение остаётся одним самодостаточным `ServerDeck.exe`.
  Установщик не является дополнительным постоянно работающим приложением,
  владельцем данных или службой. Принцип IV конституции и документы поставки 002
  синхронизированы; их исторические формулировки не означают поддержку portable-режима.

### Session 2026-11-06 — версия основного окна

Пользователь попросил вывести текущую версию в UI и пройти Spec Kit с новым релизом.
Версия уже видна в настройках обновлений; доработка делает её доступной в основном
окне. Default: существующий блок состояния оболочки, без нового диалога/действий.
Clarify: вопросов0; scope/data/UX/failure/privacy/dependencies/testability ясны,
продуктовых или архитектурных решений на потом не оставлено.

## User Scenarios & Testing

### User Story 1 — Установить программу для себя (Priority: P1)

Пользователь скачивает один установочный файл `ServerDeckSetup.exe`, запускает
мастер установки и устанавливает программу для своей учётной записи.
Установщик содержит полный выпуск и необходимые runtime-зависимости;
для установки не нужны сеть, администратор или учётная запись в сетевом сервисе.
После завершения пользователь запускает установленный `ServerDeck.exe`.

**Why this priority**: Нужны понятный способ начать работу и постоянное место запуска.
**Independent Test**: Unit-тесты решения об установке и native adapters на временных
файлах; регистрация и ярлыки проверяются через подставные зависимости, без запуска продукта.

**Acceptance Scenarios**:

1. **AC-601 Given** программа ещё не установлена, **When** пользователь выбирает
   «Установить для меня» и подтверждает показанные действия, **Then** создаются
   пользовательская установка, ярлык в меню «Пуск» и запись удаления; доступен запуск.
2. **AC-602 Given** запущен установщик, **When** пользователь отменяет установку
   до её подтверждения, **Then** программа не устанавливается и не запускается,
   ярлыки и регистрация не создаются; portable-запуск не предлагается.
3. **AC-603 Given** программа уже установлена, **When** повторно выбран установочный
   сценарий, **Then** показана существующая установка; равная версия не создаёт дубликат,
   более новая проходит правила обновления, более старая не подменяет установленную.
4. **AC-604 Given** нет прав или места, **When** установка не может завершиться,
   **Then** нет ложного успеха и действующего ярлыка на неполную установку;
   прежние данные и прежняя установка остаются доступны, предложен повтор.

### User Story 2 — Узнать об обновлении и решить, устанавливать ли его (Priority: P1)

Пользователь видит текущую и доступную версии, описание изменений и может
подготовить обновление либо отложить его. Проверка не мешает работе с серверами.

**Why this priority**: Обновление должно быть доступно без принуждения и потери контроля.
**Independent Test**: Fake clock/network/release source проверяют расписание,
сравнение версий, согласие и различимые результаты проверки.

**Acceptance Scenarios**:

1. **AC-605 Given** установленная программа и доступная новая стабильная версия,
   **When** завершена проверка, **Then** показаны обе версии, изменения и действия
   «Скачать обновление» / «Позже»; без согласия EXE не скачивается и не заменяется.
2. **AC-606 Given** нет новой версии, сеть недоступна или источник не прошёл проверку,
   **When** завершена попытка, **Then** различимы «Установлена актуальная версия»,
   «Не удалось проверить» и «Источник обновления не прошёл проверку»;
   SSH/MCP и локальные данные продолжают работать.
3. **AC-607 Given** фоновая проверка выключена, **When** пользователь нажимает
   «Проверить обновления», **Then** выполняется одна явная проверка;
   настройка фоновых проверок не включается автоматически.

### User Story 3 — Безопасно применить обновление (Priority: P1)

Пользователь подтверждает скачивание, видит прогресс и готовность. Для применения
он сохраняет работу и выходит через трей. При следующем обычном запуске
установленной программы применяется подготовленная версия.

**Why this priority**: Нельзя оборвать серверную операцию или потерять рабочую установку.
**Independent Test**: Unit-модель стадий и native file adapters на синтетических EXE
проверяют ошибки, блокировки, восстановление и сохранность независимого data root.

**Acceptance Scenarios**:

1. **AC-608 Given** согласие на конкретный выпуск, **When** он скачан и проверен,
   **Then** показано «Обновление готово» с целевой версией и инструкцией выйти через
   трей; программа сама не завершает основной экземпляр и не разрывает SSH/MCP.
2. **AC-609 Given** подготовленное обновление и отсутствие работающего владельца,
   **When** пользователь снова запускает установленную программу, **Then** до открытия
   базы применяется проверенный полный выпуск; новая версия использует прежние
   профили, настройки и защищённые credentials без автоматического SSH-подключения.
3. **AC-610 Given** обрыв скачивания, неверная подпись/целостность или ошибка замены,
   **When** операция завершается ошибкой, **Then** старая полная версия остаётся
   доступна, смешанный runtime не запускается, доступны причина и безопасный повтор.
4. **AC-611 Given** другая копия приложения работает или уже идёт установка/обновление,
   **When** запрошено применение, **Then** параллельной замены нет; пользователь
   видит причину ожидания, принудительное завершение не выполняется.
5. **AC-612 Given** неподдерживаемый формат базы, **When** запускается новая версия,
   **Then** данные остаются нетронутыми и показана причина отказа; база не сбрасывается,
   ошибка не маскируется пустыми профилями или автоматическим откатом с открытием базы.

### User Story 4 — Удалить программу, сохранив данные (Priority: P2)

Пользователь удаляет установку стандартным пользовательским действием Windows.
Удаление программы не означает согласия удалить серверные профили и секреты.

**Why this priority**: Жизненный цикл установки должен быть обратимым.
**Independent Test**: Unit-проверки плана удаления и file adapters во временных
каталогах; системная регистрация подставная, настоящая установка не затрагивается.

**Acceptance Scenarios**:

1. **AC-613 Given** приложение закрыто, **When** подтверждено удаление,
   **Then** удалены управляемые файлы программы, подготовленные обновления,
   ярлык и регистрация; пользовательские данные и секреты сохранены.
2. **AC-614 Given** приложение работает, **When** запрошено удаление,
   **Then** предложено выйти через трей и повторить; процесс не убивается.
3. **AC-615 Given** данные сохранены после удаления, **When** программа установлена
   повторно тем же пользователем, **Then** используется прежнее пространство данных
   с обычной проверкой совместимости; чужие данные не присоединяются.

### Edge Cases

- Прерванная установка, перезагрузка между стадиями замены, заблокированный антивирусом файл.
- Повторное нажатие, две установки, ручной запуск новой/старой копии одновременно.
- Отозванный выпуск после подготовки, истёкшее описание выпуска, неверные часы компьютера.
- Изменившаяся версия или содержимое источника между проверкой и скачиванием.
- Повреждённая/неполная загрузка, нет места для старого и нового полных комплектов.
- Работа без сети, отмена загрузки, read-only исходный каталог, нелатинский путь пользователя.
- Символическая ссылка/подмена управляемого пути; удаление не должно выйти за его границы.
- Несохранённая форма, активная серверная операция, MCP-мост внешнего клиента.
- Совместимое расширение схемы и действительная несовместимость формата базы.

## Requirements

### Functional Requirements

- **FR-601**: MUST распространяться одним установочным файлом `ServerDeckSetup.exe`
  для Windows 10/11 x64, содержащим полный выпуск. Установщик размещает один
  самодостаточный `ServerDeck.exe` с необходимыми встроенными зависимостями.
  Установка, обновление и удаление доступны обычному пользователю без admin-прав,
  отдельной службы или скачивания runtime. Установка из уже скачанного файла
  и обычный запуск после установки не требуют сети. Установщик не открывает
  рабочее пространство приложения вместо установки; прямой запуск скачанного
  установщика не означает portable-режим.
- **FR-602**: MUST предложить подтверждение пользовательской установки и отмену.
  Установка не выполняется без подтверждения её состава.
  Устанавливаются программа, ярлык «Пуск» и пользовательская запись удаления;
  также создаётся действие «ServerDeck — восстановление» в меню «Пуск» для случая,
  когда незавершённая замена сделала обычный EXE недоступным;
  ярлык рабочего стола, автозапуск Windows и изменение PATH не выполняются.
- **FR-603**: MUST иметь одно постоянное место установки для текущего пользователя,
  отдельное от данных и runtime-кэша. Повторная установка не создаёт новый профиль
  данных или вторую регистрацию. Установка поверх существующей программы
  сохраняет пространство данных пользователя, заданное пакетом 002.
- **FR-604**: MUST проверять доступ, свободное место и полноту выпуска до активации.
  При нехватке места или неполном результате прежняя установка остаётся рабочей.
  Успех означает завершение копирования, регистрации и создания ярлыка; незавершённая
  операция допускает повтор без дубликатов и удаления чужих файлов.
- **FR-605**: MUST предоставлять текущую версию, ручную проверку и настройку фоновых
  проверок. Для установленной программы фоновые проверки по умолчанию включены:
  одна после готовности приложения, затем не чаще раза за 24 часа, только пока оно
  работает. Выключение запрещает новые фоновые обращения.
- **FR-606**: MUST использовать только стабильные выпуски для текущей платформы.
  Предложение содержит идентификатор выпуска, версии, дату, описание изменений,
  размер и сведения о совместимости. Равная/более старая версия не предлагается.
  Откат и переключение каналов в этой версии функции не поддерживаются.
- **FR-607**: MUST скачивать программу только после явного согласия на показанный
  выпуск. Для обновления скачивается установочный файл этого выпуска;
  проверенный встроенный комплект используется для обновления существующей установки
  без повторного выбора пути и создания второй установки.
  «Позже» ничего не скачивает; до следующей фоновой проверки повторное
  уведомление не показывается. Согласие не переносится на другой выпуск. После
  скачивания применяется именно согласованный выпуск при следующем запуске;
  выход через трей и обычный запуск остаются допустимы; для немедленного обновления
  пользователь отдельно подтверждает «Обновить и перезапустить» (FR-622).
- **FR-608**: MUST получать описания и файлы только из предусмотренного продуктом
  доверенного источника по защищённому соединению, проверять подлинность издателя,
  целостность и соответствие выпуска до подготовки и непосредственно перед применением.
  Одного хеша из непроверенного сетевого ответа недостаточно. Пользователь не может
  отключить эти проверки или подставить произвольный источник через UI/MCP.
- **FR-609**: MUST отвергать подменённый, отозванный, просроченный, неподходящий по
  платформе или несовместимый выпуск с различимой причиной. Перед применением
  нужна свежая успешная проверка его допустимости; если сеть недоступна, обновление
  остаётся подготовленным, запускается прежняя версия. Обычная работа не блокируется.
  Просроченные/ошибочные данные источника не выдаются за отсутствие обновлений.
- **FR-610**: MUST показывать стадии проверки, скачивания, проверки файла, готовности,
  применения и ошибки. Прогресс с неизвестным общим размером не показывает выдуманный
  процент. Загрузку можно отменить; неполный файл не становится устанавливаемым.
  Проверка ограничена 30 секундами, загрузка — 60 секундами без поступления данных
  и 30 минутами суммарно; таймаут оставляет текущую программу рабочей. Повтор явный,
  без бесконечных скрытых попыток. Повтор загрузки начинается заново.
- **FR-611**: MUST применять обновление только до открытия runtime/базы и при отсутствии
  владельца приложения текущего пользователя во всех его сессиях. Работающий основной
  экземпляр завершает работу через трей либо по явному действию
  «Обновить и перезапустить» для проверенного подготовленного выпуска (FR-622).
  MCP/updater не завершают работающий экземпляр самостоятельно. Скачивание допустимо при активных SSH/MCP, применение — нет.
  Последующий запуск не возобновляет подключения или серверные команды автоматически.
- **FR-612**: MUST сериализовать установку, применение и удаление на пользователя;
  повторные команды не создают вторую операцию. При прерывании замены следующий
  запуск восстанавливает полный прежний или завершает полный новый комплект до
  открытия базы; смешанное состояние и сообщение успеха без завершения запрещены.
  Если обычный EXE недоступен, пользователь вызывает «ServerDeck — восстановление»
  из меню «Пуск»; эта независимая точка готовится до замены и не меняется во время неё.
  Короткоживущий maintenance-процесс может продолжить замену после завершения
  bootstrap до открытия UI/данных; работающий основной экземпляр он не завершает.
  Сохранённая старая копия служит только восстановлению незавершённой замены;
  после первого открытия данных новой версией автоматического отката нет.
- **FR-613**: MUST сохранять базу, credentials, host-key trust, настройки, серверные
  профили и ещё не истёкшие локальные данные при установке/обновлении. Политика
  естественного истечения журналов/мониторинга не меняется. Применяется действующая
  конституция VI: совместимые расширения без искусственного повышения формата и
  прикладных миграций; неподдерживаемые форматы/повреждение отвергаются без удаления.
  Реальная несовместимость не даёт согласия на конвертацию или сброс данных.
- **FR-614**: MUST удалять только принадлежащие установке файлы и регистрацию текущего
  пользователя, сохраняя данные и OS-защищённые секреты. Полное уничтожение данных
  и credentials — отдельная функция вне scope. При частичном отказе удаления видны
  оставшиеся элементы и возможность повторить; завершённые шаги не повторяют побочные эффекты.
  Временная копия обслуживающего EXE в каталоге временных файлов ОС может остаться
  до его штатной очистки; это не установленная программа и не фоновая служба.
- **FR-615**: MUST сохранять путь установленного EXE между обновлениями, чтобы ярлыки
  и существующая MCP-конфигурация не требовали ручного исправления. Установка не
  переписывает конфигурации внешних MCP-клиентов без отдельного действия пользователя;
  для конфигурации, ссылающейся на прежнее расположение программы, показывает новый
  путь и необходимость обновить настройку.
  После удаления старый путь MCP не работает; данные доверия при этом не стираются.
- **FR-616**: MUST не передавать источнику обновлений профили, адреса серверов,
  credentials, журналы или постоянный идентификатор установки. Допустимы только
  текущая версия, платформа и необходимые технические данные соединения.
  Диагностика стадий/ошибок не содержит секретов, токенов и содержимого базы.
- **FR-617**: MUST переиспользовать [компоненты 001](../001-design-system/component-library.md):
  C02 действия, C04 выбор/настройка, C10 статусы, C11 сообщения, C12 недоступность,
  C14 подтверждение, C18 сведения о выпуске, C23 прогресс, C27 путь, C28 время.
  Состоянием, разрешениями, согласием и повторами владеет функция; общего нового
  дизайна и проверок layout экранов этот пакет не вводит.

- **FR-618**: MUST размещать и получать релизы только через GitHub Releases
  публичного репозитория `unng-lab/serverdeck`: полный установщик, описание,
  changelog и служебные метаданные принадлежат релизу. Отдельный сервер и GitHub-вход
  пользователя не требуются. Согласие и проверка доверия сохраняются.
  **AC-616**: stable latest обнаруживается, setup берётся из его assets; отсутствие
  новых релизов более недели не делает выпуск просроченным. Отказ GitHub, отзыв или
  подмена не заменяют программу и не удаляют готовый установщик.

- **FR-619**: Обычная сборка для распространения и workflow MUST встраивать постоянную
  public policy GitHub Releases и ключ издателя. UPDATE_NOT_CONFIGURED допустим только
  для явно выбранного developer-профиля. Отсутствующая/невалидная policy в release
  сборке блокирует сборку, а не даёт тихо отключённый updater. Private key хранится
  отдельно и не публикуется; update-enabled installer и matching signed catalog
  подготавливаются по окончательным audited bytes. Первая настройка уже установленной
  unconfigured версии доставляется ручным полным установщиком с большей версией.
  **AC-617**: Default/workflow artifact имеет publishable audit и identical embedded
  GitHub policy app/setup; matching key подписывает metadata именно этих bytes,
  developer требует explicit selection, отсутствие policy/mismatch блокирует выпуск.

- **FR-620**: Основное окно MUST показывать текущую версию ServerDeck в постоянном
  блоке состояния приложения без открытия настроек и выбора сервера. Отображается
  полный номер запущенной программы, включая build после «+», из локальных сведений
  программы; новый доступный/подготовленный выпуск его не заменяет. Номер доступен
  при готовности и ошибке открытия данных, когда локальные сведения получены; до
  их получения или при их отсутствии явно показано «Версия ServerDeck — Не определена».
  Отображение не требует сети/открытой базы и не запускает дополнительные операции.
  Повторная привязка окна к другому экземпляру runtime использует его сведения.
  **AC-618**: Основное окно без выбранного сервера и с серверным workspace показывает
  полный текущий номер; ошибка данных его не скрывает, unknown не выдаётся за номер
  релиза, предложение обновления не меняет текущий номер. Проверки функциональные,
  без assertions размеров/положения/дизайна страниц.

### Key Entities

- **Установка пользователя**: владелец ОС, постоянный путь программы, текущий выпуск,
  ярлык и регистрация удаления; не содержит отдельной копии серверных данных.
- **Выпуск**: неизменяемая идентичность, версия, платформа, описание, размер,
  сведения о совместимости и проверяемое подтверждение издателя/допустимости.
- **Операция установки/обновления/удаления**: тип, целевой выпуск, стадия,
  согласие пользователя, результат, причина отказа и сведения для восстановления.
- **Настройка проверки**: разрешение фона, последняя попытка/успех и показанный выпуск;
  ошибка проверки не подменяет время последнего успеха.

## Assumptions

- Установка и обновление объединены в один пакет жизненного цикла поставки;
  это отдельная функция относительно [runtime 002](../002-desktop-runtime/spec.md).
  Исключение установщика/автообновления из scope 002 не запрещает их в пакете 006.
- Предлагаемые для обсуждения defaults: установка только для текущего пользователя,
  полный офлайн-установщик, один стабильный канал, отсутствие silent-установки,
  автоматического применения во время работы, автозапуска ОС и удаления данных.
- Название `ServerDeckSetup.exe` обозначает роль установочного артефакта;
  `ServerDeck.exe` — установленную программу и постоянную точку запуска UI/MCP.
  Поддержка запуска без установки не входит в эту функцию.
- Для установленной программы подтверждение «Скачать обновление» разрешает подготовку
  и применение при следующем запуске; перед подтверждением это явно написано.
- Предполагается доступный продукту доверенный источник выпусков и издатель релиза.
  Источник выпусков — GitHub Releases публичного репозитория `unng-lab/serverdeck`.
  Установщик, описание, changelog и необходимые служебные файлы размещаются в релизах;
  отдельного сервера DXZ или другого сервера обновлений нет. Коммерческий сертификат
  и выполнение публикации/production rollout не входят в текущую задачу.
  Обязательные технические решения следующей стадии: способ проверки доверия/отзыва
  и ротации, версия/срок действия описания выпуска, правила сравнения версий и
  совместимости, сетевые/дисковые пределы, схема атомарной замены/восстановления,
  точные пути и пользовательская регистрация Windows. Это необходимые design-артефакты,
  а не разрешение реализовать механизм обновления с неустановленными контрактами.
- Действующая [конституция](../../.specify/memory/constitution.md) имеет приоритет над
  историческими storage-уточнениями 002: несовместимость не выводится из одного номера
  версии приложения или самого факта изменения схемы.
- Проверка поведения только unit/fake и изолированными native adapters на синтетических
  входах/временных файлах. Допускаются сборка и статические проверки упаковки/manifest.
  Запуск продукта, интеграционные/VM/e2e/smoke/process-kill прогоны и проверки дизайна
  feature-экранов не входят в задачи или приёмку. Юнит-результаты не доказывают
  фактическую установку и интеграцию на чистой Windows.
- Пользователь поручил пройти полный цикл Spec Kit. Проектные решения, контракты,
  задачи и результаты проверок оформляются в этом пакете; готовность объявляется
  только после обязательных проверок и независимого ревью.

## Amendment 2026-11-06: заметные обновления и перезапуск

**Уточнение пользователя:** перезапуск находится в кнопке обновления —
«Обновить и перезапустить», как в Codex; отдельного пункта в трее нет.

### User Story 5 — Обновиться из главного окна (P1)

Пользователь видит текущую установленную версию и кнопку обновлений без перехода
в настройки и без выбора сервера. Открывает сведения о выпуске, подтверждает
скачивание. После проверки установщика может продолжать работу либо обновиться
сейчас. Перед перезапуском видит предупреждение о закрытии SSH/MCP и сохранении данных.

- **FR-621**: Постоянная кнопка «Обновления» MUST заменить обычное сообщение
  «Приложение готово». Текущая локальная версия FR-620 сохраняется. Во время проверки,
  скачивания/проверки файла, при доступном и подготовленном выпуске подпись кнопки
  отражает состояние; ошибки различимы. Кнопка открывает отдельное окно обновлений
  с существующими сведениями и действиями, без выбора сервера и вкладки настроек.
  До готовности runtime действие недоступно, состояния запуска/ошибки данных/выхода
  продолжают отображаться. Отсутствующий update owner не создаёт фиктивную готовность.
- **FR-622**: «Обновить и перезапустить» MUST быть доступно только для сохранённого,
  проверенного подготовленного выпуска без preparedCode/ошибки чтения и без активной
  операции обновления. Ошибка или отмена подготовки другого выпуска (state=failed,
  общий code) не блокирует прежний подготовленный выпуск, если его preparedCode пуст.
  Подтверждение C14 называет точную версию, предупреждает о закрытии SSH/MCP, сохранении
  данных и отсутствии автоматического восстановления подключений. Отмена ничего
  не завершает. Native повторно атомарно проверяет готовность/версию/owner и закрывает
  admission. Успех запускает существующий shutdown, повторное нажатие не дублирует его.
  До успешного shutdown установщик не запускается. Ошибка shutdown оставляет окно
  с явным повтором завершения; таймаут не разрешает принудительное закрытие.
  Завершение сессии Windows отменяет намерение перезапуска; обычный «Выход» в трее
  также отменяет его. Самостоятельного перезапуска в трее/MCP нет.
- **FR-623**: После успешного shutdown MUST использоваться существующий защищённый
  pending handoff и startup-правила FR-608–613: непрерывное владение owner lease,
  ограниченный maintenance lock, проверка pending, пять inherited HANDLE с ready/permit,
  ожидание завершения старого процесса, свежая проверка выпуска и запуск canonical EXE.
  Сбой запуска helper после закрытия UI показывает native retry/cancel: повторяется
  только handoff, без второго Flutter engine; отмена оставляет приложение закрытым,
  данные и pending сохранёнными. При недоступности GitHub helper запускает проверенную
  старую версию с причиной неустановленного обновления. При повреждении установки
  остаётся существующее восстановление. Ни путь, ни URL, ни PID не приходят из UI.

**AC-619**: Без сервера и в workspace видна кнопка с достоверным состоянием;
она открывает обновления напрямую; смена owner/runtime и shutdown закрывают все
вложенные подтверждения. Ошибки и прогресс не маскируются надписью «готово».
**AC-620**: Functional units проверяют отмену, точную версию и повторную проверку
после подтверждения, отказ при busy/stale owner/version/error, один shutdown,
сохранение данных/закрытие capabilities до finishExit, retry после отказа и отмену
перезапуска при tray exit/OS ending. Сохранённый проверенный A остаётся доступен
после ошибки/отмены подготовки B, но блокируется при ошибке проверки самого A
(preparedCode), ошибке чтения или активном worker. Native synthetic units проверяют передачу
непрерывного owner, только готовый pending, failure/retry/cancel и отсутствие
повторного Flutter host; существующие handoff/revalidation unit cases сохраняются.
**SC-607**: Обновление доступно за одно действие из работающего главного окна;
установка и перезапуск требуют отдельного явного согласия после проверки файла.
Проверяется unit/fake данными и действиями, без feature design/e2e tests.
