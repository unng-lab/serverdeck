# ServerDeck: сервис и последовательность его создания

**20 спецификаций, реализация с нуля, hard cutover.** Specify завершён; Implement001.1 начат, scaffold и часть primitives реализованы. Полная служба, пересмотренное хранение, CRUD/UI и приёмка не завершены. Охват защиты уточнён пользователем 2026-10-11.

Начать с [001 — Основа сервиса](001-service-foundation/spec.md). Здесь описан сам продукт: назначение, владельцы данных, компоненты и их обязанности, bootstrap/readiness/Local API, завершение и recovery, первый законченный read-only маршрут. 002–020 расширяют эту основу, а не подразумевают её существование.

[Состав и ответственность расширений](service-overview.md) · [Бизнес-требования](business-requirements.md) · [Трассировка](traceability.md) · [Машиночитаемая очередь](sequence.json)

## Минимальный первый результат

Windows-клиент запускает собственный locald → получает ready защищённого нового пространства → пользователь создаёт профиль → подтверждает host key и сохраняет доступ → подключается → получает реальные сведения/ПО/ресурсы/журнал. Backend, installer helper, готовая библиотека из старого кода и будущие модули для этого не нужны. Уже первое сохранение защищено; plaintext промежуточной фазы нет.

Первый запуск пустой, область данных/credentials/trust отдельная от старого сервиса. Нет импорта старых данных, совместимости с его API или обязательного merge старых MR. Новые обновления сохраняют данные новой реализации. Брендбук сохранён и используется в базовом UI.

## Последовательность

Нумерация — рекомендуемый линейный порядок. Зависимости — принятые результаты предыдущих пакетов; каждый последующий модуль указывает своё место в существующем сервисе. Внутри пакета три существенных этапа идут последовательно. Один этап — отдельный MR либо согласованная меньшая часть; все три этапа и все 20 пакетов одним MR не объединяются.

## Gates

- 001 сам содержит начальную защиту и реальное read-only исполнение. Его bootstrap/storage/jobs contracts проектируются в собственном Plan; зависеть от ещё не созданной реализации 002 нельзя.
- 002 расширяет работающую защищённую основу и обязателен перед production поставкой 005. Windows gate 005.1 не ждёт дополнительных платформ 005.3.
- 006 включает первую настоящую запись только после disposable systemd VM post-check/failure gate; 007 читает и регистрирует существующее ПО без его изменения.
- 012 принимает схему копирования вместе с пробным восстановлением в независимую цель; 015 не является скрытой предпосылкой для этого.
- 020 — первый пакет с backend; production sync включается лишь после третьего интеграционного этапа. Все предыдущие пакеты работают локально без него.

## Следующий шаг

Scaffold и часть primitives уже реализованы; продолжение после clean review пересмотренного пакета начинается с T063, затем открытой очереди001.1. Остальные этапы требуют собственных Plan/Tasks. Реализация/приёмка/MR разделяются по этапам; готовность к запуску/merge ещё не установлена.

После изменений обязательны `lychee "specs/**/*.md"` и независимое ревью по AGENTS.md; исправления повторяют checks и запускают нового reviewer до чистого результата.
