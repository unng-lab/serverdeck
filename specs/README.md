[Распределение 98 ID и shared функций](design-delivery.md) определяет владельцев; [текущая карта 37](003-design-system/screen-map.md) связывает базовые композиции с обработчиками и задачами. Инвентарь/поиск обнаруженного ПО 008 не заменяется каталогом рецептов чистой установки 006. Локальные фильтры, вкладки и сводки и метрик composition 05 по доступным данным входят в базу 003.

Прежние scoped UI результаты 003.1–003.3 сохранены как история; они не подтверждают точного совпадения с каноном и не закрывают новую базовую приёмку. Полный 98-screen результат и готовность будущих пакетов к реализации не установлены: каждому нужны собственные Plan/модели/контракты/Tasks, UI+сервис+состояния+приёмка, без произвольных provider defaults. Пользователь выбрал для 020 внешний OIDC-провайдер, настраиваемый администратором; остальной предложенный набор провайдеров не принят.

## Минимальный первый результат

Windows-клиент запускает собственный locald → получает ready защищённого нового пространства → пользователь создаёт профиль → подтверждает host key и сохраняет доступ → подключается → получает реальные сведения/ПО/ресурсы/журнал. Backend, installer helper, готовая библиотека из старого кода и будущие модули для этого не нужны. Уже первое сохранение защищено; plaintext промежуточной фазы нет.

Первый запуск пустой, область данных/credentials/trust отдельная от старого сервиса. Нет импорта старых данных, совместимости с его API или обязательного merge старых MR. Новые обновления сохраняют данные новой реализации. Брендбук сохранён и используется в базовом UI.

## Gates

- 001 сам содержит начальную защиту и реальное read-only исполнение. Его bootstrap/storage/jobs contracts проектируются в собственном Plan; зависеть от ещё не созданной реализации 002 нельзя.
- 002 расширяет работающую защищённую основу и обязателен перед production поставкой 005. Windows gate 005.1 не ждёт дополнительных платформ 005.3.
- 006 включает первую настоящую запись только после disposable systemd VM post-check/failure gate; 007 читает и регистрирует существующее ПО без его изменения.
- 012 принимает схему копирования вместе с пробным восстановлением в независимую цель; 015 не является скрытой предпосылкой для этого.
- 020 — первый пакет с backend; production sync включается лишь после третьего интеграционного этапа. Все предыдущие пакеты работают локально без него.
