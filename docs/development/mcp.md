# Запуск ServerDeck с MCP

Команды выполняются из корня репозитория в PowerShell 7.4+ на Windows x64.
Это инструкция по имеющимся исходникам. Полная приёмка текущей реализации
ещё не завершена; результаты отмечаются в [журнале](mcp-verification.md) и
[Tasks 021](../../specs/021-mcp-control/tasks.md).

## Сборка приложения и MCP

Подготовьте закреплённый Flutter/Dart и Windows toolchain по
[инструкции среды](foundation.md). Нужен также Python 3.12 для генерации
описателя исполнителя. Сборка использует закреплённые зависимости и выбранную
проверенную native-библиотеку; отсутствие обязательного компонента останавливает
сборку.

```powershell
./tools/run-serverdeck.ps1 -Configuration Debug -BuildOnly -Python python
```

Результат находится в `build/windows/x64/runner/Debug`. Обычный запуск:

```powershell
./tools/run-serverdeck.ps1 -Configuration Debug -Python python
```

Сборка включает Flutter-приложение, `locald.exe`, `mcp.exe`, `libisar.dll`,
`executor-release.json` и `foundation.manifest.json`. Manifest формата 3
связывает хеши пяти артефактов, API 1.1 и схему workspace 3. Сохраняйте весь
каталог сборки: один скопированный `mcp.exe` не является рабочей поставкой.
`tools/build-mcp.ps1 -OutputDirectory <каталог-внутри-репозитория>` собирает
только мост и сам по себе не создаёт совместимый комплект.

## Выдача доступа ИИ

1. Запустите приложение. Раздел «Автоматизация» доступен и в пустом workspace.
2. Создайте доступ ИИ с нужными scopes, сроком и конкретными серверами.
   Для одного авторства профилей серверы не требуются: `serverIds=[]`.
3. Получите конфигурацию выбранного доступа в интерфейсе. Она содержит
   абсолютный `command` и `args`, без паролей и SSH-ключей.
4. Добавьте эту stdio-конфигурацию в MCP-клиент. Каждому независимому клиенту
   выдавайте отдельный доступ, чтобы отзывать их независимо.

Структура записи для клиента, использующего контейнер `mcpServers`:

```json
{
  "mcpServers": {
    "serverdeck": {
      "command": "C:\\ServerDeck\\mcp.exe",
      "args": [
        "--app-root", "C:\\ServerDeck",
        "--grant-id", "11111111-1111-4111-8111-111111111111"
      ]
    }
  }
}
```

Пути и UUID выше — пример структуры. Используйте значения, выданные вашим
приложением; обёртка записи зависит от MCP-клиента. Передавать переменные
окружения с SSH-доступом или секретом grant не требуется. Защищённый grant
доступен только соответствующему пользователю Windows в этом workspace.

Без аргументов мост допускает MCP initialization, но возвращает пустой список
инструментов. Это не режим доступа к серверам. Ошибка настроенного запуска
не переключает его в такой режим. Диагностика запуска идёт в stderr в виде
фиксированного `MCP:<код>`, stdout занят протоколом.

Если клиент ограничивает дочерние процессы Windows Job Object и запрещает
breakaway, сначала запустите приложение обычным способом. MCP подключится
к уже работающему совместимому locald. При отказе безопасного холодного
запуска возвращается `MCP:PREREQUISITE_UNAVAILABLE`; обхода политики процесса
или повторного запуска с наследованием kill-on-close нет.

## Управление серверами и выполнение

Владелец добавляет сервер и credentials в приложении, сверяет и подтверждает
SSH fingerprint. ИИ получает только MCP tools. UI и MCP обращаются к общим
сервисам locald: состояние, метрики, логи, конфигурация, профили и задания
не имеют отдельных обходных путей для ИИ.

ИИ создаёт типизированный JSON-профиль, проверяет и сравнивает его версии,
затем строит неизменяемый план для разрешённого сервера. Произвольные YAML,
shell, пути и Ansible-модули не принимаются. План показывает эффекты и условия;
изменение состояния может сделать его устаревшим. Для исполнения необходима
делегация владельца на точную версию `(profileId, revision, bodyDigest)` либо
подтверждение конкретного плана. Право создавать профиль не даёт права
самостоятельно разрешить его выполнение. Задания имеют статус, события,
отмену и явное согласование неопределённого результата без повторного запуска.

Исполнитель отдельно подготавливается администратором на Ubuntu 24.04
amd64 с systemd и Python 3.12. Его установка не является MCP tool. Сначала
используйте [инструкцию исполнителя](../../executor/README.md); затем владелец
инспектирует и подтверждает его identity в приложении. Генерация локального
`executor-release.json` не устанавливает ничего на сервер.

Установка PostgreSQL/ClickHouse требует подготовленного подписанного APT
каталога с точными версиями и полным набором зависимостей. Процедура описана
в [рецептах](../../executor/recipes/README.md). Пустой каталог означает
недоступность установки. Подготовка метаданных не равна квалификации рецепта;
готовые квалифицированные рецепты текущего checkout пока не подтверждены.

## Проверки

Порядок приёмки и обязательные сценарии описаны в
[Quickstart 021](../../specs/021-mcp-control/quickstart.md).
Наличие скрипта, исходника или старого зелёного результата не доказывает
проверку текущей сборки. Независимые клиенты для сквозного стенда находятся
в [tools/mcp_clients](../../tools/mcp_clients/README.md); Docker используется
как отдельный временный сервер, а не как зависимость обычного MCP-клиента.
